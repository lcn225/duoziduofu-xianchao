| 艺 | key | 消耗 | 产出 | 状态 |

| 制符 | `talisman` | **叶 / 藤**（妖兽材料池里没有，见下） | 一次性 Buff / 攻击符箓 | ✅ B11-a2 |

> ⚠ **材料分类的实际缺口**（2026-10-25 查物品池，2026-11-07 B11-a2 复核）：
> 金属 58 件（一阶 16）/ 宝晶 59 件（一阶 12）够炼器；

> 金属同时是药浴的「金系」燃料 —— 抢料优先级定死：**配方锁 > 药浴**。
>
> **2026-11-04 补**：四艺分**两条产线**（桂冈个人 / 乡间自动），阶位口径、封地产物分流、
> 秘境消耗品见 **§十一**；「法器」只是产出名，物品池分类唯一写作 **灵器**。

## 二、配方与残页

- **解锁（2026-10-26，《模块解锁方针》§五）**：**炼器开局即送**（唯一有完整产物链的艺）；
  炼丹 / 制符 / 炼阵**拿到对应功法或残页才解锁**，在那之前入口灰显占位。
- 开局只有《萧氏炼器基础卷一》（`xiao_forging_1`，放在 `arts.manuals`）。
- 高级配方靠**残页拼图**解锁；残页来源：探索（主）、宝匣 TC、传功阁、门派秘库。
- **残页是独立字段**：现有 `pills.pillFragments`（丹方）与 `cultivationData` 的功法残页
  是**另一套**，不要混用。数量公式参考 `fragmentsNeeded = 5 × 品阶 + 5`。
- 学习配方需要对应百艺的**熟练度**达标。
- **2026-11-04 修正（§11.5）**：**低阶配方不走残页** —— 做一次就永久解锁，之后交乡间自动跑；
  **只有二阶及以上的高阶配方**才用残页拼图，熟练度也只作「学高阶」的门槛。

## 三、时间成本（进度条式）

- 每个配方有基础耗时；**制作占用日常循环的时间**。
- 一轮 45 游戏分钟，按轮推进进度条：**一轮 +N%**，支持跨多天。
- **第一期只做 ≤1 游戏天完成的配方** —— 多月制作需要「长期工序」状态机，等第一批跑通再说。
- 玩家可随时中断（材料是否损耗待定，先按保留）。

## 四、熟练度

四档：**熟练 → 精通 → 大师 → 宗师**。

| 效果 | 口径 |
|---|---|
| 降耗时 | 最多 **−50%** |
| 成功率 | 越级制作会失败，失败退还部分材料 |
| 品质 | 熟练度越高，产出「下 / 中 / 上 / 极」成色的概率越高 |

**2026-11-04 口径（§11.5）**：

- **低阶配方做一次就永久解锁**，之后由乡间建筑自动跑；玩家主要只做**高阶**。
- **熟练度只有桂冈亲手制作才涨；乡间自动不涨熟练度**。
- 熟练度**只作「学高阶配方」的门槛**；四档阈值、降耗时比例仍**待定**（交开发组）。
- 成功率 / 品质**后置**：杂物阶段无品质，先不做。

## 五、入道（补偿「玩物丧志」）

| 机制 | 口径 |
|---|---|
| 制作顿悟（看脸） | 完成瞬间小概率触发，给一笔修为 |
| 百艺入道（保底） | 某项达到**宗师**解锁常驻被动：**只加修炼速度，不进突破门槛** |

> 入道加成**不进门槛**是硬口径：一旦进门槛，就要按宪法第二章重算全部节点。

## 六、与封地、药浴的联动

1. **封地 → 百艺**：灵田产灵植、矿场产矿石；传功阁定期出残页；
   **丹炉 / 工坊 / 符坊 / 阵堂的等级决定能自动产到哪一阶**（由乡侯府卡等级上限，§11.1）。
2. **百艺 → 封地**：**丹炉 / 工坊 / 符坊 / 阵堂 = 百艺自动化**，产低一阶实物进背包（B11-b）；
   **酒坊 = 经营链**，产抽象货物即产即卖。封地 Lv.3 / Lv.4 升级交实物建材**仍不做**
   （会让封地升级倒过来依赖百艺，顺序倒挂）。分流表见 §11.3。
3. **配方锁**：排班配方所需材料自动进入「配方锁」；**药浴池的一键投料自动跳过被锁的品种**。
   这是《炼体药浴》§4 / §9.3 已经预留的口子。

### 11.1 两条产线

| 产线 | 谁在做 | 怎么产 | 产物去向 |
|---|---|---|---|
| **桂冈个人百艺** | 桂冈本人，挂在 `dayLoop` | 百艺页自选配方 → 真实扣料 → 产**高一阶**成品 | 进背包，可自用（秘境耗材）/ 卖钱 |
| **乡间自动百艺** | 封地建筑（丹炉 / 工坊 / 符坊 / 阵堂） | 自动扣料 → 产**低一阶**成品 | 进背包，可自用 / 卖钱（B11-b） |

**共同约束**：**乡侯府等级 → 解锁附属建筑等级上限**。丹炉 / 工坊 / 符坊 / 阵堂能升到几级，由乡侯府卡。
⚠ 现行代码的建筑上限是写死的 `maxLevel:3`（`plugins/estate.js`），这条是**新规则**，在 B11-b 落地。

**时间口径**：个人百艺仍是 `dayLoop` 的一部分，**跟游戏时钟**（练气 1× / 筑基 24× / 金丹 168×）。
筑基后小循环在 UI 上退场、引擎照跑，产出进战报 —— 属**预期行为**，不另加密度上限。

### 11.2 四艺统一与阶位口径

| 艺 | 乡间建筑 | 乡间产 | 桂冈个人产 |
|---|---|---|---|
| 炼器 | 工坊 | 低一阶灵器 | 高一阶灵器 |
| 炼丹 | 丹炉 | 低一阶丹药 | 高一阶丹药 |
| 制符 | **符坊（新增）** | 低一阶符箓 | 高一阶符箓 |
| 炼阵 | **阵堂（新增）** | 低一阶阵法 | 高一阶阵法 |

**阶位基准（2026-11-04 拍板）**：以**配方所在境界段**为基座 —— 乡间自动产**本段阶**、
桂冈亲手产**高一阶**：

| 段 | 乡间自动 | 桂冈个人 |
|---|---|---|
| 练气 | 一阶 | **二阶** |
| 筑基 | 二阶 | 三阶 |
| 金丹 | 三阶 | 四阶 |

> 这样 §五「高难度秘境要二阶耗材」在练气段正好等于「桂冈个人产的」，乡间只供一阶。
> 跨段沿用「掉落阶按境界段」的既有口径（P30），**不按地图阶**。

**法器就是灵器**：物品池分类唯一写作 `'灵器'`（`plugins/items.js` 的 `ITEM_CATEGORIES`），
「法器」只作为产出名 / 口语保留。灵器是**装备**，不是抽象货物 —— 进背包、可穿戴。

### 11.3 封地产物分流（⚠ 覆盖 B14-b 的三链口径）

| 类 | 建筑 | 产物 | 性质 |
|---|---|---|---|
| **经营链** | 酒坊（以及以后的灵食坊 / 灵砖坊） | 灵酒 / 灵食 / 灵砖 | **抽象货物，即产即卖，不进背包** |
| **百艺自动化** | 丹炉 / 工坊 / 符坊 / 阵堂 | 低一阶丹药 / 灵器 / 符箓 / 阵法 | **真实物品，进背包**，可自用 / 卖钱 |

- **目的**：经营链提供模拟经营趣味；百艺自动化解放玩家时间，不手工刷低阶货。
- **落地批次**：**本批不改 B14-b 代码** —— 丹炉 / 工坊继续产抽象成品。
  换实物、加符坊 / 阵堂一起放 **B11-b**（§11.8）。
- **经济后果**（已登《产出登记表》变更记录 2026-11-04，**未生效**）：
  丹炉（灵丹 12 一阶/天）与工坊（法器 12 一阶/天）不再即卖 ⇒
  练气 Lv1 经营链收入 **48 → 24 一阶/天（−50%）**，市集闸门从三链变**一链（酒）**。
  这是**预期行为**，不是 bug。
- **B11-b 动工前必须先定**（否则无法落代码）：
  ① 乡间百艺吃**封地中间产物仓**还是背包；② 成品卖价 / 回收价；
  ③ 丹药 / 符箓 / 阵法的**堆叠键**（量级参考 P62：不合并会重演 12 万条 / 48MB）。

### 11.4 秘境消耗品（与 B10 独立）

> 术语先厘清：**一层 = 一场战斗**（`simulateBattle`，内含多回合 round）；
> 5 层 = 一个**段**（`runSegment` 的循环）。旧写法「一层 = 一回合」作废。

| 项 | 口径 |
|---|---|
| 丹药 | **每 5 层消耗 1 粒**，效果只管这 5 层，没续上就断（脉冲式） |
| 符箓 | **每层消耗 1 张**，本层有效 |
| 阵法 | **持续整趟**，每趟重新部署（消耗品） |
| 触发 | **自动**，不需要玩家中途操作 |
| 作用对象 | **全队**（桂冈 + 子嗣 + 出战灵宠，与 `applyBuffIds` 同口径） |
| 阶位选择 | **默认高阶优先，可自选**（整备页设置消耗优先级） |
| 不够时 | **停止消耗，后续层无 buff**；不降级、不失败 |
| 与现有 buff 门 | **并存**：秘境每 5 层已有 `pendingBuff` 选增益（`buffEveryFloors:5`），消耗品在**同一层边界**另算，**不替换** |
| 段内提前结束 | 丹药**按已跨过的 5 层边界实扣**（撤退 / 阵亡不追扣） |
| 与 B10 | **完全独立**，不依赖战斗系统整理；但**不改排序链**（B11 仍排 B10 后） |

**实装（交开发组）**：在 `runSegment` 的**层循环开头**插「消耗品结算」钩子，
**不重写 `simulateBattle`**。⚠ 备忘录原文「`simulateBattle` 一次算完整段（5 层）」是错的 ——
它是**一层一场**，5 层循环在 `runSegment`（`plugins/secretRealm.js:960-1027`）。

**UI**：现有只有「整备出发」界面，**没有整备页**；带哪些 / 各带多少 / 优先级的配置面是 B11 新增工作。

#### ✅ 2026-11-08 B11-a3 已落地（三条拍板 + 实装口径）

### 11.5 配方解锁与熟练度（2026-11-04 拍板）

| 项 | 口径 |
|---|---|
| 低阶配方 | **做一次就永久解锁**，之后交乡间自动跑；**不走残页** |
| 高阶配方（二阶及以上） | **残页拼图**解锁（`fragmentsNeeded = 5 × 品阶 + 5`），口径同 P47 #2 |
| 熟练度 | 只作**学高阶配方**的门槛；**乡间自动不涨熟练度**，只有桂冈亲手制作涨 |
| 玩家主要动作 | 只做**高阶**（低阶由乡间供应） |
| 数值 | **待定**（四档阈值、降耗时比例，§11.8） |

> 这条解开 §二 / §四 与 P47 #2 的重叠：低阶免残页、不设熟练度门槛；高阶两样都要。
> 玩家仍要把每种低阶配方**亲手做一次**才解锁 —— 这是有意的前两次手感，不是漏授权。

### 11.6 二阶定位与乡间产速

- **二阶定位**：低难度秘境一阶丹药 / 符箓 / 阵法够用；**高难度秘境要二阶（桂冈个人产）**
  才打得过 ⇒ **勾不勾百艺 = 打不打高难度秘境**的决策，不是「能不能打」。
- **乡间产速方针**：类似探索系统 —— **只要投入一定时间，产出就绰绰有余**；
  具体数值交开发组（§11.8）。
- ⚠ **料源才是瓶颈**：符箓吃叶 / 藤（池里叶 10、藤 18），炼阵吃骨材（9 件）。
  产速定得再快，原料不够也会停 —— 定数值时必须连底材供给一起算；
  **不许为此偷偷加掉落**（加掉落要登《产出登记表》）。

### 13.3 料源结论（为什么炼阵从筑基起）

| 底材 | 件数 | 一阶 | 结论 |
|---|---:|---:|---|
| 草 / 花 / 树 / 果 | 34 / 28 / 23 / 9 | 12 / 7 / 5 / 5 | 炼丹料最宽，按 2~3 件/轮写 |
| 叶 / 藤 | 10 / 18 | 3 / **1** | 制符能跑，但藤一阶只有 1 种，靠掉落频次 |
| 灵土 | 38 | 14 | 炼阵够用 |
| 骨材 | 9 | **0**（最低二阶） | **练气段按「料阶 ≤ 配方阶」配不出料** ⇒ 炼阵整表从筑基起 |
| 妖兽材料 | **0** | — | 池里没有这个 type ⇒ 制符只用叶 / 藤 |

- **炼阵在练气期的表现**：页签可见（残页能掉、能解锁），但没有可排配方，
  显示「炼阵配方从筑基段起」。二阶骨材在练气期就会掉（`pickBaseItemForEvent` 规则 4
  「T1 宁可给二阶骨材」），属于**先囤料**，不是给了没用的东西。
- **百艺吃的是探索掉的实物**：封地药圃产的「灵植 3/天」是**中间产物仓**，
  不进背包、不能当百艺底材（§11.3 / B14-a 口径）。所以配方一律按 2~3 件/轮写，
  别按「满勾 10 轮/天」估产量。

### 13.4 解锁与残页的最终口径

| 项 | 口径 |
|---|---|
| 开局 | **只送炼器**（`STARTER_ARTS = ['forge']`） |
| 解锁炼丹 / 制符 / 炼阵 | **拿到该艺任意一张残页** —— 残页都挂在二阶及以上配方上，所以第一张残页必然来自该艺 |
| 解锁时 | 该艺**一阶配方全部免费到手**（「低阶不设门槛」§11.5）；炼阵没有一阶配方，只解锁艺 |
| 二阶配方 | 集齐 **10 张同配方残页**自动学会（不是同艺通用） |
| 残页来源 | 探索事件（原「丹方残页」掉点）· 秘境结算 · 宝匣残页节点 |
| 旧丹方残页 | 老档 `pillFragments` **1:1 折算成炼丹残页**（轮转填未学二阶丹方，填满后的剩余丢弃） |

> **为什么不给二阶配方加熟练度门槛**：炼阵没有一阶配方，`skill` 只能靠亲手制作涨，
> 设 `skill ≥ 1` 会死锁。炼丹 / 制符若单独设门槛，又会让「三艺同构」失效。
> 统一留到三阶（熟练度四档仍照 §四 的 0 / 30 / 100 / 300）。
