# 模块二：多子多福系统 完整设计方案

## 一、模块定位

多子多福系统是全书的**招牌系统**，也是放置游戏的核心爽点。

**核心循环**：

```
晚间互动 → 当场确认怀孕 → 孕育 → 诞生抽卡 → 有灵根子嗣提供修炼加成

↓

无灵根子嗣 → 家族工作 / 联姻 / 繁育

↓

位阶提升 → 怀孕概率↓，灵根概率↑

↓

女修加入 → 高质量子嗣
```

**与修炼系统的绑定**：

- 子嗣**只影响修炼速度**，不影响契合度

- 门槛靠配置，子嗣是加速器

- 散功重修时子嗣加成不受影响，是保底

### 2.2 关键规则

| 规则 | 说明 |

|---|---|

| **位阶不影响互动选择** | 所有侍妾都可互动，只是怀孕概率不同 |

| **位阶影响怀孕概率** | 凡女 1.0，女修随修为降低（0.5→0.2） |

| **位阶影响灵根概率** | 凡女 0.5-1.0，女修 **2.0（封顶）**。2026-10-17 起 P9 以上不再继续 ×2.5/3.0/3.5/4.0 |

| **子嗣灵根加成只在该侍妾怀孕时生效** | 不影响怀孕概率 |

| **P8 是荣誉位阶** | 产下多位仙师，只存在理论可能 |

| **P9 是女修起点** | 女修入门即 P9 |

### 2.3 设计意图

**"女修怀孕概率低，但仙师产率高"通过位阶统一实现**：

- 凡女：怀孕容易，但子嗣有灵根的概率低

- 女修：怀孕困难，但子嗣有灵根的概率高

- 位阶越高，怀孕越难，但子嗣质量越高

**策略选择**：

- 早期靠凡女堆数量

- 后期靠女修提质量

### 3.3 状态判定规则

**例假**：每月固定 5 天，时间随机。可通过【调经丹】调整或缩短。

**回娘家**：随机事件，与家族、好感度有关。可通过派人接回、送礼缩短。

**闭关/修行**：女修专属，可主动安排。闭关期间不可互动，但修为提升。

## 四、体力与精力（2026-10-17 重写）

> 本节原为「精力系统」（互动消耗精力）。2026-10-17 决议**职责互换**：
> **体力** = 身体，管所有白天活动与晚间互动；**精力** = 脑力，只管【镇守】里的百艺。
> 数值真源在 [《日常循环》](../20-系统设计/日常循环.md) §一/§二/§4.3，本节只保留模块二的引用口径。

```
体力上限 = 145 + 外功加成
```

| 外功段 | 每级加成 | 该段末尾上限 |
|---|---|---|
| 炼体 一~十层 | +3 | 172 |
| 锻骨 初/中/后/圆满 | +6 | 196 |
| 洗髓 初/中/后/圆满 | +9 | 232 |
| 超级炼体（19 级起） | +25 | 357~382 |

### 4.2 消耗

| 行为 | 消耗 |
|---|---|
| 与侍妾互动 | **体力 20/人**（1 游戏小时；2026-10-17 决议） |
| 白天所有活动 | 见《桂冈的一天》§二（巡视 −10/h、练功 −3/h、炼体 −15/h） |

### 4.3 恢复

| 资源 | 恢复方式 |
|---|---|
| 体力 | 睡觉：`min(睡觉时长 × 体力上限/4, 体力上限)` —— 4 小时回满（《日常循环》§4.3） |

⚠ 旧表里的「回气丹 +30 / 灵茶 +10-20 / 侍妾照料 +5-15 / 灵地打坐 +20」**尚未重新归属**
（哪些补体力、哪些补精力未定），等丹药/百艺系统上线时再定，别照旧实现。

### 4.4 耗尽处理

- **精力耗尽**：打坐一轮（1 小时，+10 精力）后放弃当天剩余安排、提前下班（不是回满）。
- **体力耗尽**：自动睡觉。

详见《桂冈的一天》§3.3。

## 六、子嗣抽卡

### 6.0 子孙判定（Y 染，2026-10-18 补齐）

原著系统对「子孙」的定义**不是「所有孩子」**：

> 子孙定义遵循 Y 染判定，即包括所有继承宿主 Y 染的男性和携带宿主 Y 染男性的
> 下一代女性，该女性的再下一代不包括在内。

展开成表：

| 关系 | 算不算子孙 | 理由 |
|---|---|---|
| 桂冈本人 | — | 宿主，不是自己的子孙 |
| 儿子 | ✅ | 继承宿主 Y 染 |
| 女儿 | ✅ | 是「携带宿主 Y 染的男性（桂冈/儿子）」的下一代女性 |
| 儿子的儿子 / 女儿 | ✅ | 男性支线继续传 Y；其女儿仍属「下一代女性」 |
| 女儿的儿子 / 女儿 | ❌ | 不带宿主 Y 染；规则明确排除该女性的再下一代 |
| 更远的母系后代 | ❌ | 同上 |

**这条规则把 `gender` 变成了子嗣的第一等字段**，不是取名用的装饰：
它决定一名子嗣能否把「子孙」身份传给下一代。

- 第一代（桂冈亲生）男女都算子孙，所以**当前修行加成不受性别影响**；
- 子嗣繁育（模块五/家族工作）上线后，女儿的子女必须被排除在
  `offspringCultivationBonus`、抽奖次数、修行返还、词条抢夺、雷达/地图之外。

**落地（2026-10-18，P12.6）**：`newOffspring.gender`（`'male' | 'female'`），
出生时 **50/50**；老档没有该字段的，读档时按 `id + name` 稳定哈希补齐
（同一名子嗣刷新后性别不变）。

| P1-P2 | 10% × 0.5 × 2.0 = **10%** |

| P3 | 10% × 0.7 × 2.0 = **14%** |

| P4 | 10% × 0.8 × 2.0 = **16%** |

| P5 | 10% × 0.9 × 2.0 = **18%** |

| P6 | 10% × 1.0 × 2.0 = **20%** |

| P7 | 10% × 1.2 × 2.0 = **24%** |

| P8 | 10% × 1.5 × 2.0 = **30%** |

| P9-P13 | 10% × 2.0 × 2.0 = **40%**（母方系数封顶后全部同值） |

**灵根概率的实际上限是 80%**——母方封顶 ×2.0、父方封顶 ×4.0，`10% × 2.0 × 4.0 = 80%`。
没有 100% 的情况，**也不需要额外写死钳制**。（本批只做 P1-P6，实得区间是 10%~20%。）

**首充礼包**：第一个子嗣必定拥有灵根。

**注**：灵根概率**只取决于父母身份**，不受人口基数影响。

### 6.2 有灵根子嗣品质

> **✅ 2026-10-18 口径变更（已落地，P15.5(c)）**：
> **灵根没有独立的品质，品质只是「几灵根」的派生叫法。**
> 抽取顺序已改为「先掷灵根数量 → 派生品质」，数量分布沿用下表的概率
> （5 灵根 60% / 4 或 3 灵根 25% / 2 灵根 12% / 1 灵根 3%）。
> `quality` 字段保留（存档、UI、本命池、战力仍按它取），但它不再是一个独立随机量。
> 洗命、血脉提纯、配偶生成都只操作「灵根数量」这一个真源。

**抽卡分两步**（见 §6.2；原《跨文档冲突审阅》§8 已归档）：

**第一步：判有无灵根** —— 用 §6.1 的 `基础 10% × 母方位阶系数 × 父方身份系数`，上限 100%。这一步已经决定了「有灵根」的概率，**不存在固定的「无灵根 90%」**。

**第二步：有灵根后，在品质分布里抽**

| 品质 | 概率 | 灵根 | 本命 | 词条 |

|---|---|---|---|---|

| 下品 | 60% | 五灵根 | 凡兽 | 1 个普通词条 |

| 中品 | 25% | 四灵根/三灵根 | 灵兽 | 1 个稀有词条 |

| 上品 | 12% | 双灵根 | 王级变异兽 | 2 个稀有词条 |

| 极品 | 3% | 单灵根 | 神兽/仙器 | 3 个词条+1 个传说词条 |

品质分布是**「已确定有灵根」前提下的条件概率**，四档合计 100%。

> 旧版那张含「无灵根 90%」的综合概率表（下品 6% / 中品 2.5% / 上品 1.2% / 极品 0.3%）**已作废**——那是把两步揉成一步的平均值，与本文件 §6.1「灵根概率随父母身份从 10% 变到 80%」直接冲突。

### 6.3 本命抽取（并入全局物品池）

**独立的本命池已删除（2026-10-17）。** 子嗣诞生时抽取本命，直接调用全局《物品池》四大类：

| 灵草 | ✅ | 炼丹 / 同参 / 子嗣本命 |
| 灵器 | ✅ | 装备 / 同参 / 子嗣本命 |

> 旧表（凡兽 / 灵兽 / 王级变异兽 / 神兽仙器 / 器 / 草·木 / 杂物）**作废** ——
> 那是另一套平行分类，与物品池四大类对不上，正是「同一批小说物件被两套系统各记一半」的来源。

**子嗣本命与玩家本命的关系**影响修炼加成系数：

> 永远为 false，这一档在现有数据下是**死代码**。删掉后只剩三档，语义反而干净。
> 连带 `wuxing.js` 的 `isSameElementGroup` 失去调用方（那条注释已同步作废）。

## 七、子嗣成长与派遣

### 7.1 成长阶段（2026-10-18 重定：仙凡双轨 + 压缩到游戏天）

**为什么改**：世界钟固定为「1 游戏天 = 96 现实秒」，1 游戏年 ≈ 9.7 现实小时。
按旧的 18 岁成年，子嗣要 **7.3 现实天**才能用，第一代孙辈要一周以上 ——
多子多福的世代循环根本转不起来。世界钟不能动（日常循环/动画/孕育/离线都绑在它上面），
所以把子嗣成长**单独压缩到游戏天**，并分仙凡两轨。

**时间刻度**：仙龄 1 岁 = 凡人 15 游戏天 / 仙师 23.33 游戏天；成年统一定在 **18 仙龄岁**。

| 阶段 | 仙龄 | 凡人（无灵根）游戏天 | 仙师（有灵根）游戏天 | 现实时长（凡 / 仙） |
|---|---:|---:|---:|---:|
| 幼年 | 0–3 岁 | 0–45 | 0–70 | 1.2 / 1.9 小时 |
| 启蒙 | 3–6 岁 | 45–90 | 70–140 | 1.2–2.4 / 1.9–3.7 小时 |
| 少年 | 6–12 岁 | 90–180 | 140–280 | 2.4–4.8 / 3.7–7.5 小时 |
| 青年 | 12–18 岁 | 180–270 | 280–420 | 4.8–7.2 / 7.5–11.2 小时 |
| 成年 | 18–30 岁 | 270–450 | 420–700 | 7.2–12 / 11.2–18.7 小时 |
| 中年 | 30 岁+ | 450+ | 700+ | 12 小时+ / 18.7 小时+ |

**收益启动**（不是等都成年才生效）：

| 阶段 | 凡人（无灵根） | 仙师（有灵根） |
|---|---|---|
| 幼年 | 无收益 | **修炼加成出生即生效** |
| 启蒙 | 可做简单家族工作 | 开始修炼（自动积累修为） |
| 少年 | 可做正式工作 | 可派遣 / 可出战 |
| 青年 | 可婚配 / 可繁育 | 可婚配 / 可繁育 |
| 成年 | 可担任管理岗位 | 可担任门派职务 |
| 中年 | 可担任家族长老 | 可带兵 / 镇守 / 出使 |

**第一代孙辈**：凡人约 **7.5 现实小时**（4.8h 婚配 + 约 16 分钟受孕 + 2.4h 孕育），
仙师约 **10 现实小时**。挂 10 分钟只推进幼年，挂一夜才看到第一代成年/第一个孙辈 ——
这是刻意的挂机节奏，不是数值没调。

> **与旧设计的差异**：旧表按「现实岁数」写 0-3/4-6/7-12/13-18；
> 新表把阶段连续化为 0-3/3-6/6-12/12-18，并用仙龄换算，边界天数见上表。
> 年龄显示口径：**阶段 + 仙龄 + 进度**（例：少年 · 9 岁 · 135/180 天）。

> **落地（2026-10-18，P14）**：纯函数 `offspringGrowthOf` / `formatOffspringGrowth` /
> `canWorkOf` / `canFightOf` / `canMarryOf`，数值在 `innerCourt.TUNING.growth`。
> 秘境出战门槛已改读 `canFightOf`（**有灵根 + 少年**），旧的 `minAgeYears: 1` 已删除；
> 子嗣战力等级改按**仙龄**算（成年 18 仙龄岁 ≈ 10 级）。

> **寿命/死亡暂不做**：本批只做成长与收益门槛。凡人与修士的寿元、老死、
> 陨落返还（§6.0.1）留到模块五/八；在 626 人口上限内，先用「每对 6 胎」节流。

### 7.4 子嗣繁育（2026-10-18 设计，P14 已实现）

**目标**：让世代循环在挂机节奏内转起来 —— 第一孙辈约 7.5/10 现实小时，
626 人仙朝规模约 2–4 现实天，而不是几周。

**配偶**
- 儿子到**青年**（凡 180 天 / 仙 280 天）自动婚配，配偶**不入侍妾池**、不占 36 人上限。
- 配偶来源按儿子的灵根分轨：
  - 无灵根儿子 → 凡女（P1–P3），怀孕系数 1.0；
  - 有灵根儿子 → 女修（练气 P7–P9 / 筑基 P10–P12），怀孕系数 0.5–0.9。
- **女儿不外娶**：到青年外嫁，她的子女**不计入子孙**（Y 染规则，§6.0）；
  外嫁的联姻收益留给模块四/六。

**受孕**
- 每个已婚儿子按**游戏天**结算一次，受孕率直接复用《§5.2》的公式：
  `10% × 配偶位阶怀孕系数`。
  自动模式 −5% 与配偶好感 +5% 抵消；不计算宿主疲劳，也**不设怀孕保底**（设计已废除）。
- 凡女约 10%/天，女修约 5–9%/天；平均约 10–20 游戏天受孕。
- 孕育沿用 **90 游戏天 + 产后 10 天**（与宿主侍妾同一套状态机）。
- 子嗣灵根概率的**父方身份系数**用儿子自己的境界（`realm.tier`），不是桂冈的境界。

**节流**
- 每对夫妻最多 **6 胎**；全族子孙上限 **626**。
- 到 626 后停止新的婚配与受孕（已怀的照常出生）；后续用「分家/外放/陨落」腾位置（未实现）。
- 宿主自己的侍妾也计入这 626；到上限后晚间互动不再产生新子嗣。

**数据**
- `offspring` 新增：`generation`（桂冈亲生 = 1）、`lineage: 'y'`、
  `spouse: { name, kind, rank, affinity, pregCoef, rootCoef } | null`、
  `spouseStatus / spouseStatusEndTime / spousePregnancyStartTime`、`childrenIds`。
- `sumChildrenBonus` / 抽奖次数 / 修行返还 / 雷达只统计 `lineage === 'y'` 的子孙。

> **第一版只做儿子线**：女儿外嫁、她的子女不建模（直接不计入子孙集合），
> 避免把「非 Y 染」分支也塞进家族树。等联姻系统上线再补女儿的收益。

**落地口径（2026-10-18，P14）**

- 代码入口：`innerCourt.TUNING.breeding` + `stores/modules/innerCourt.js` 的
  `advanceOffspringBreeding`（挂在每日 `advanceInnerCourtDay` 上）。
- **孙辈不弹诞生窗**：只有桂冈亲生的第一代会进 `pendingBirthIds`；孙辈只写内宅流水
  （「本日添孙 N 人」）。弹窗会冻结时钟，626 人规模下会反复打断挂机。
- **儿子的境界没有建模**：父方身份系数按「有灵根 = 练气 / 无灵根 = 凡人」占位；
  配偶位阶也一律按练气段 P7-P9。等子嗣修炼系统上线再把筑基段 P10-P12 接进来。
- **626 只拦新的婚配 / 受孕**，不拦已经怀上的（§7.4 原文）。因此实际人口可能短暂超过 626。
- 陨落子嗣腾出名额（只数 `status !== 'fallen'`）。

> **✅ 已落地（P15.5(b)）**：血脉遗传 / 灵根提纯 —— 子嗣繁育时按**母亲（儿子的配偶）的
> 灵根数量**修正子嗣的灵根数量（5→4 概率 10%、4/3→3/2 15%、2→1 20%，最少 1）；
> 配偶随机获得，且**灵根档不优于该子孙**。只作用于子嗣繁育，宿主侍妾不参与。
> 数值在 `innerCourt.TUNING.heritage.purifyChance`。

| 无灵根、未成年 | 50 大子 | 6 金页子 | 零花，可忽略 |
| 无灵根、成年 | 1 金页子 | 12 金页子 | 家族雇员，够日常 |
| 有灵根、练气期 | 5 一阶灵石 | 60 一阶 | 够买基础丹药 |
| 有灵根、筑基期 | 5 二阶灵石 | 60 二阶 | 够买中阶丹药 |
| 有灵根、结丹期 | 20 二阶灵石 | 240 二阶 | 够买高阶丹药 |
| 有灵根、元婴期 | 100 二阶灵石 | 1,200 二阶 | 够买顶阶丹药 |

**设计逻辑**：月钱 = 该境界子嗣每年能买 1-2 瓶正路子丹药的水平。
仙朝阶段月钱约占收入 3.34%（110,000 二阶口径）；与侍妾月饷合计约 9.2%，在 10% 财政线以内。
⚠ 换成 80,000 口径则是 12.7%，会越线 —— 配平时必须明确用哪一档。

### 8.5 子嗣小金库

| 项目 | 说明 |
|---|---|
| 来源 | 月钱花不完的部分 |
| 用途 | 自身修行、培养后代、联络势力 |
| 是否回流 | 不回流，纯运营损耗 |
| 是否影响好感 | 小金库越多，子嗣越独立，好感增长越慢 |

好感 80+ 的子嗣有概率自愿上缴部分小金库（随机事件，属模块八）。

### 8.6 扩张：开拓新地盘

| 方向 | 目标 | 难度 | 收益 | 前置条件 |
|---|---|---|---|---|
| 北 | 长岭关外 | 极高 | 妖兽材料、灵地 | 战斗力系统 |
| 东 | 七连寨 | 高 | 人口、灵矿 | 战斗力系统 |
| 西 | 连山派边缘 | 极高 | 商路、功法 | 战斗力系统 |
| 南 | 郑家飞地 | 中 | 坊市分成 | 外交系统 |

开拓流程：派子嗣+队伍 → 建据点（灵石+时间）→ 占领/谈判/征服 → 设封地（归家族）→ 派管理者 → 产出。

| 封地数量 | 开拓成本 | 管理需求 | 总税收 |
|---|---:|---|---:|
| 1（长岭乡） | 初始 | 1 乡侯 | 5,703 金页子/年 |
| 2 | 5,000 二阶 | 2 乡侯 | +8,000 金页子/年 |
| 3 | 10,000 二阶 | 3 乡侯 | +12,000 金页子/年 |
| 5 | 30,000 二阶 | 5 乡侯 | +20,000 金页子/年 |
| 10 | 100,000 二阶 | 10 乡侯 | +40,000 金页子/年 |

**瓶颈不是钱，是管理能力**：每块封地要有人管；子嗣不够只能派门人，门人忠诚度低、效率差。

### 8.7 家族经济循环

收入 = 俸禄 + 封地税收 + 商队 + 投资 + 子嗣派遣；
支出 = 侍妾月饷 + 子嗣月钱 + 建设 + 修行 + 联姻。

子嗣经济：收入 = 家族月钱；支出 = 自身修行 / 培养后代 / 联络势力；结余 = 小金库（不回流）。

扩张：子嗣派遣 → 开拓新地盘 → 家族直辖 → 新封地。
管理约束：岗位总数 = 10 + 有灵根子嗣×2 + 无灵根子嗣×0.5 + 门人×0.3；
产出效率 = 基础 × 管理者能力系数。

## 九、子嗣修炼加成

### 9.1 公式

```
子嗣修炼加成 = Σ(每个有灵根子嗣的加成)

单个子嗣加成 = 灵根系数 × 本命契合系数 × 词条系数
```

| 灵根 | 灵根系数 |

|---|---|

| 五灵根 | 0.02 |

| 四灵根 | 0.05 |

| 三灵根 | 0.10 |

| 双灵根 | 0.20 |

| 单灵根 | 0.40 |

| 子嗣本命与玩家本命关系 | 本命契合系数 |

|---|---|

| 完全相同 | 1.5 |

| 同类型 | 1.2 |

| 无关 | 0.5 |

（「同五行 1.0」已删除，理由见 §6.3。）

| 词条 | 词条系数 |

|---|---|

| 普通词条 | +0.05 |

| 稀有词条 | +0.10 |

| 传说词条 | +0.20 |

**软上限：每个大境界解锁一档（2026-10-18 改）**

> 2026-10-17 曾定「取消 +200% 封顶、无脑叠加」。2026-10-18 子嗣成长加速
> （§7.1）与 626 人口上限落地后，线性无上限会让 626 人直接把修炼速度拉到几十倍，
> 所以改为**按大境界解锁的软上限**：硬上限仍然是取消的，但总和渐近于一档上限。

```
总加成 = cap × (1 − e^(−原始加成 / cap))
```

| 宿主大境界 | `realm.tier` | cap | 渐近上限 |
|---|---|---:|---:|
| 练气 | `qi` | 2.0 | +200% |
| 筑基 | `foundation` | 4.0 | +400% |
| 结丹 | `core` | 7.0 | +700% |
| 元婴 | `nascent` | 10.0 | +1000% |

- `原始 = cap` 时到 63.2%，`2×cap` 时到 86.5%，`3×cap` 时到 95%。
  即练气期 6 点原始加成 ≈ +190%，元婴期 30 点 ≈ +950%。
- **cap 随宿主大境界切换**，突破后立即重算；不是子嗣各自的封顶。
- 元婴以上（化神等）未定，暂沿用 10.0，等 22 级境界落地再补。

**配平口径**：软上限是防爆安全网，真正的配平仍以《[产出登记表](../00-总览与状态/产出登记表.md)》
全部已登记产出为输入，按宪法第二章的绝对时间倒推；子嗣加成（R07）只是其中一项。

✅ **代码现状（2026-10-18，P14 已落地）**：`TUNING.bonus.softCap = { qi: 2.0, foundation: 4.0,
core: 7.0, nascent: 10.0 }`；`offspringCultivationBonus` 按 `getRealmName(level).tier` 取 cap，
走 `sumChildrenBonus(children, profile, cap)` → `applyBonusSoftCap`。旧字段 `bonus.cap` 已删除。
UI 同时显示「原始 +X%」与「实得 +Y%」，让玩家看得见软上限。

### 9.2 示例

假设玩家有 10 名有灵根子嗣：

| 子嗣 | 灵根 | 本命关系 | 词条 | 单个加成 |

|---|---|---|---|---|

| 桂大 | 单火 | 同类型 | 剑心通明 | 0.40×1.2×1.10 = 0.528 |

| 桂二 | 双水木 | 同类型 | 丹心妙手 | 0.20×1.2×1.10 = 0.264 |

| 桂四 | 三灵根 | 同类型 | 经商奇才 | 0.10×1.2×1.10 = 0.132 |

| 桂六 | 四灵根 | 无关 | 无 | 0.05×0.5×1.0 = 0.025 |

| ... | | | | |

| **10 人合计** | | | | **约 +1.5** |

**修炼速度倍率**：

- 无子嗣：0.5 + 1.0 × 1.5 = 2.0×（满契合度）

- 10 子嗣：2.0 × (1 + 1.5) = 5.0×

- 20 子嗣：按实际 Σ 继续累加，**不再有 6.0× 这个封顶点**；具体值取决于子嗣质量，
  由提高后的修为上限门槛反推配平（不要拿倍率直接外推突破时间）
