## 一、模块定位

多子多福系统是全书的**招牌系统**，也是放置游戏的核心爽点。

**核心循环**：

```
晚间互动 → 当场确认怀孕 → 孕育 → 诞生抽卡 → 有灵根子嗣提供修炼加成

↓

无灵根子嗣 → 家族工作 / 联姻 / 繁育

↓

位阶提升 → 怀孕概率↓，灵根概率↑

↓

女修加入 → 高质量子嗣
```

**与修炼系统的绑定**：

- 子嗣**只影响修炼速度**，不影响契合度

- 门槛靠配置，子嗣是加速器

- 散功重修时子嗣加成不受影响，是保底

### 2.2 关键规则

| 规则 | 说明 |

|---|---|

| **位阶不影响互动选择** | 所有侍妾都可互动，只是怀孕概率不同 |

| **位阶影响怀孕概率** | 凡女 1.0，女修随修为降低（0.5→0.2） |

| **位阶影响灵根概率** | 凡女 0.5-1.0，女修 **2.0（封顶）**。2026-10-17 起 P9 以上不再继续 ×2.5/3.0/3.5/4.0 |

| **子嗣灵根加成只在该侍妾怀孕时生效** | 不影响怀孕概率 |

| **P7 是凡人天花板** | 产下小仙师的凡人女性 |

| **P8 是荣誉位阶** | 产下多位仙师，只存在理论可能 |

| **P9 是女修起点** | 女修入门即 P9 |

### 2.3 设计意图

**"女修怀孕概率低，但仙师产率高"通过位阶统一实现**：

- 凡女：怀孕容易，但子嗣有灵根的概率低

- 女修：怀孕困难，但子嗣有灵根的概率高

- 位阶越高，怀孕越难，但子嗣质量越高

**策略选择**：

- 早期靠凡女堆数量

- 后期靠女修提质量

### 3.3 状态判定规则

**例假**：每月固定 5 天，时间随机。可通过【调经丹】调整或缩短。

**已孕**：互动后当场确认，**90 游戏天**后生产（旧设计 270 天；2026-10-16 时钟放慢 4 倍后同比例压缩）。期间不可互动，但提供子嗣灵根加成。

**产后恢复**：30 天，可通过【产后复原丹】缩短至 7 天。

**生病**：随机事件，与体质、内宅环境有关。可通过丹药、灵医治疗。

> **2026-10-25 砍掉**：「生气」「回娘家」两条状态，以及《模块八》的「侍妾下毒」。
> 侍妾**好感保留**，但冻结为「出身自带的静态值」（`innerCourt.js` 现有实现即如此，
> 只影响怀孕率 +0~10%）。涨跌机制以后单独讨论 —— **明确不做 galgame**。

**闭关/修行**：女修专属，可主动安排。闭关期间不可互动，但修为提升。

## 四、体力与精力（2026-10-17 重写）

> 本节原为「精力系统」（互动消耗精力）。2026-10-17 决议**职责互换**：
> **体力** = 身体，管所有白天活动与晚间互动；**精力** = 脑力，只管【镇守】里的百艺。
> 数值真源在 [《日常循环》](../20-系统设计/日常循环.md) §一/§二/§4.3，本节只保留模块二的引用口径。

### 4.1 体力上限

```
体力上限 = 145 + 外功加成
```

| 外功段 | 每级加成 | 该段末尾上限 |
|---|---|---|
| 炼体 一~十层 | +3 | 172 |
| 锻骨 初/中/后/圆满 | +6 | 196 |
| 洗髓 初/中/后/圆满 | +9 | 232 |
| 超级炼体（19 级起） | +25 | 357~382 |

### 4.2 消耗

| 行为 | 消耗 |
|---|---|
| 与侍妾互动 | **体力 20/人**（1 游戏小时；2026-10-17 决议） |
| 白天所有活动 | 见《桂冈的一天》§二（巡视 −10/h、练功 −3/h、炼体 −15/h） |
| 百艺（炼丹/炼符/炼阵/炼器） | **精力** −30~35/天 |

### 4.3 恢复

| 资源 | 恢复方式 |
|---|---|
| 体力 | 睡觉：`min(睡觉时长 × 体力上限/4, 体力上限)` —— 4 小时回满（《日常循环》§4.3） |
| 精力 | 打坐 +10/h、睡觉 +5/h；上限恒 100，不随炼体涨 |

⚠ 旧表里的「回气丹 +30 / 灵茶 +10-20 / 侍妾照料 +5-15 / 灵地打坐 +20」**尚未重新归属**
（哪些补体力、哪些补精力未定），等丹药/百艺系统上线时再定，别照旧实现。

### 4.4 耗尽处理

- **精力耗尽**：打坐一轮（1 小时，+10 精力）后放弃当天剩余安排、提前下班（不是回满）。
- **体力耗尽**：自动睡觉。

详见《桂冈的一天》§3.3。

## 五、晚间互动

### 5.1 互动流程

1. **18:00 下班后**进入晚间（原「游戏时间 20:00」已作废，见 2026-10-17 决议 §2）

2. 显示**体力**值（不是精力）

3. 选择模式：手动 / 自动

4. 选择侍妾（状态为"待孕"）

5. 消耗**体力 20/人**（每次 1 游戏小时；2026-10-17 决议）

6. **当场判定怀孕**

7. 更新状态

8. 体力耗尽 / 主动结束 / 天亮

### 5.2 自动模式规则

| 规则 | 说明 |

|---|---|

| 优先高好感 | 优先选择好感度最高的侍妾 |

| 优先高位阶 | 优先选择 P4 以上侍妾 |

| 优先未孕 | 优先选择未怀孕的侍妾 |

| 平均分配 | 轮流选择，每人一次 |

| 自定义顺序 | 玩家手动排序，按顺序互动 |

**自动模式怀孕概率 -5%。**

> **实现说明（2026-10-15）**：本批实现了「优先高好感 / 优先高位阶 / 平均分配」三条规则
> （「自定义顺序」留后；「优先未孕」是隐式的 —— 候选人本来就全是待孕）。
> **内宅页面不暂停时间**，自动模式在**每日第 20 游戏小时**触发一次，手动模式随时可点。
> 两条补充约定：
> - 自动挑人会**留出 30 点体力不用**（代码里是 `innerCourt.energy`，语义就是体力）。
>   ~~按 §5.3 的口径，一夜把体力铺满会让所有人的怀孕率掉 10%。~~
>   **2026-10-18 起疲劳 −10% 已废除**，这 30 点只是节奏阀，不再有「避免掉率」的含义；
>   等互动 20/次、1h/次 那批返工时再决定是否删除（现在删会让每晚互动从 4 涨到 6）。
> - 自动/手动**默认自动**，因为内宅的主要体验就是「留在页面里看它自己跑」。
>
> ⚠ **设计-代码差距（2026-10-17）**：新设计把互动起点定为 **18:00 下班后**，而代码仍按
> **每日第 20 游戏小时**触发。这不是 bug，是待落地的差异；改的时候要同时改
> `innerCourt.js` 的触发小时与 `dayLoop.js` 的下班衔接，不要只改一边。

### 6.0 子孙判定（Y 染，2026-10-18 补齐）

原著系统对「子孙」的定义**不是「所有孩子」**：

> 子孙定义遵循 Y 染判定，即包括所有继承宿主 Y 染的男性和携带宿主 Y 染男性的
> 下一代女性，该女性的再下一代不包括在内。

展开成表：

| 关系 | 算不算子孙 | 理由 |
|---|---|---|
| 桂冈本人 | — | 宿主，不是自己的子孙 |
| 儿子 | ✅ | 继承宿主 Y 染 |
| 女儿 | ✅ | 是「携带宿主 Y 染的男性（桂冈/儿子）」的下一代女性 |
| 儿子的儿子 / 女儿 | ✅ | 男性支线继续传 Y；其女儿仍属「下一代女性」 |
| 女儿的儿子 / 女儿 | ❌ | 不带宿主 Y 染；规则明确排除该女性的再下一代 |
| 更远的母系后代 | ❌ | 同上 |

**这条规则把 `gender` 变成了子嗣的第一等字段**，不是取名用的装饰：
它决定一名子嗣能否把「子孙」身份传给下一代。

- 第一代（桂冈亲生）男女都算子孙，所以**当前修行加成不受性别影响**；
- 子嗣繁育（模块五/家族工作）上线后，女儿的子女必须被排除在
  `offspringCultivationBonus`、抽奖次数、修行返还、词条抢夺、雷达/地图之外。

**落地（2026-10-18，P12.6）**：`newOffspring.gender`（`'male' | 'female'`），
出生时 **50/50**；老档没有该字段的，读档时按 `id + name` 稳定哈希补齐
（同一名子嗣刷新后性别不变）。

### 6.2 有灵根子嗣：灵根数量分布

> **✅ 2026-10-18 最终口径**：**灵根只有数量多少的区别**（1~5 系），
> 没有独立的「下品 / 中品 / 上品 / 极品」属性。

> 内部 `quality` 字段仍由数量派生（`qualityOfRootCount`），但只作为
> 本命池 / 词条表 / 战力系数的**内部索引**，不是独立随机量，也不进 UI。
> 洗命、血脉提纯、配偶生成都只操作「灵根数量」这一个真源。

**抽卡分两步**（见 §6.2；原《跨文档冲突审阅》§8 已归档）：

**第一步：判有无灵根** —— 用 §6.1 的 `基础 10% × 母方位阶系数 × 父方身份系数`，上限 100%。这一步已经决定了「有灵根」的概率，**不存在固定的「无灵根 90%」**。

**第二步：先定本命，再查表判断灵根**（2026-10-19 修正）

**本命数量分布**（1~5 件）：

|---|---:|
| 1 件 | 3% |

| 3 件 | 10% |

| 5 件 | 60% |

### 7.1 成长阶段（2026-10-18 重定；**2026-10-29 P55-a 刻度重修：两轨合并 365 天/岁**）

按「现实岁数」长到 18 岁，子嗣要 **7.3 现实天**才能用，世代循环转不起来。

**现口径（2026-10-29 P55-a）**：**仙龄 1 岁 = 365 游戏天**，**两轨相同**。

### 7.4 子嗣繁育（2026-10-18 设计，P14 已实现）

**目标**：让世代循环在挂机节奏内转起来 —— 第一孙辈练气期约 **5.8 现实天**、筑基后约 **5.8 现实小时**。

**配偶**
- 儿子到**青年**（**14 岁 = 5,110 游戏天**，两轨同；P55-a 之前是凡 180 / 仙 280 天）自动婚配，
  配偶**不入侍妾池**、不占 36 人上限。
- 配偶来源按儿子的灵根分轨：
  - 无灵根儿子 → 凡女（P1–P3），怀孕系数 1.0；
  - 有灵根儿子 → 女修（练气 P7–P9 / 筑基 P10–P12），怀孕系数 0.5–0.9。
- **女儿不外娶**：到青年外嫁，她的子女**不计入子孙**（Y 染规则，§6.0）；
  外嫁的联姻收益留给模块四/六。

**受孕**
- 每个已婚儿子按**游戏天**结算一次，受孕率直接复用《§5.2》的公式：
  `10% × 配偶位阶怀孕系数`。
  自动模式 −5% 与配偶好感 +5% 抵消；不计算宿主疲劳，也**不设怀孕保底**（设计已废除）。
- 凡女约 10%/天，女修约 5–9%/天；平均约 10–20 游戏天受孕。
- 孕育沿用 **90 游戏天 + 产后 10 天**（与宿主侍妾同一套状态机）。
  ⚠ 孕期**刻意不动**（用户 2026-10-29 拍板），所以 1:1 下「受孕窗口 5,475 天 + 孕产 100 天」
  让每位妻妾的理论胎数上限再上一个台阶（《产出登记表》R35，**靠 `pregCoef` 收敛，不是改孕期**）。
- 子嗣灵根概率的**父方身份系数**用儿子自己的境界（`realm.tier`），不是桂冈的境界。

**节流**
- 每对夫妻最多 **6 胎**；全族子孙上限 **626**。
- 到 626 后停止新的婚配与受孕（已怀的照常出生）；后续用「分家/外放/陨落」腾位置（未实现）。
- 宿主自己的侍妾也计入这 626；到上限后晚间互动不再产生新子嗣。

**数据**
- `offspring` 新增：`generation`（桂冈亲生 = 1）、`lineage: 'y'`、
  `spouse: { name, kind, rank, affinity, pregCoef, rootCoef } | null`、
  `spouseStatus / spouseStatusEndTime / spousePregnancyStartTime`、`childrenIds`。
- `sumChildrenBonus` / 抽奖次数 / 修行返还 / 雷达只统计 `lineage === 'y'` 的子孙。

> **第一版只做儿子线**：女儿外嫁、她的子女不建模（直接不计入子孙集合），
> 避免把「非 Y 染」分支也塞进家族树。等联姻系统上线再补女儿的收益。

**落地口径（2026-10-18，P14）**

- 代码入口：`innerCourt.TUNING.breeding` + `stores/modules/innerCourt.js` 的
  `advanceOffspringBreeding`（挂在每日 `advanceInnerCourtDay` 上）。
- **孙辈不弹诞生窗**：只有桂冈亲生的第一代会进 `pendingBirthIds`；孙辈只写内宅流水
  （「本日添孙 N 人」）。弹窗会冻结时钟，626 人规模下会反复打断挂机。
- **儿子的境界没有建模**：父方身份系数按「有灵根 = 练气 / 无灵根 = 凡人」占位；
  配偶位阶也一律按练气段 P7-P9。等子嗣修炼系统上线再把筑基段 P10-P12 接进来。
- **626 只拦新的婚配 / 受孕**，不拦已经怀上的（§7.4 原文）。因此实际人口可能短暂超过 626。
- 陨落子嗣腾出名额（只数 `status !== 'fallen'`）。

> **✅ 已落地（P15.5(b)）**：血脉遗传 / 灵根提纯 —— 子嗣繁育时按**母亲（儿子的配偶）的

子嗣修炼加成 = Σ(每个有灵根子嗣的加成)

| 单灵根 | 0.24 |

| 子嗣本命与玩家本命关系 | 本命契合系数 |

|---|---|

| 完全相同 | 1.5 |

| 同类型 | 1.2 |

> 任意一件与玩家本命 id 相同 → 1.5；否则任意一件 kind 相同 → 1.2；否则 0.5。

|---|---|

| 普通词条 | +0.05 |

| 稀有词条 | +0.10 |

> 大类专精（近战/防御/远程/法宝）只让 ×1.1，**不再给修炼加成**。
> 「剑心通明」已改造为「剑专精」，所以它不再出现在上表的稀有词条里。
> 真源见《[装备词条表](../30-数据与决议/装备词条表.md)》§11。

**凡人词条池（2026-10-27 拍板，代码待做）**：无灵根子嗣也 roll 词条，**只抽普通档 5 条** ——
体健 / 机敏 / 勤勉 / 敦厚 / 手巧，**不出稀有、传说**（修仙向词条对凡人无效）。

- **效果**：对应家族工作岗位产出 **+10%**；不进修炼加成表。
- **岗位映射（拟）**：勤勉 → 灵田佃农 / 庄头 · 手巧 → 工坊匠人 · 体健 → 矿场监工 ·
  机敏 → 商队管事 · 敦厚 → 账房。
- **自动排班**：先按「词条匹配岗位」排，再按各岗人数均摊；**不得忽略词条**。
- 现状：`rollOffspring` 对无灵根直接 `traits: []`，`autoAssignFamilyJobs` 只按人最少的岗贪心 ——
  **两处都要改**（P53 #9）。改后凡人才算真正接入词条系统。

**软上限：每个大境界解锁一档（2026-10-18 改）**

> 2026-10-17 曾定「取消 +200% 封顶、无脑叠加」。2026-10-18 子嗣成长加速
> （§7.1）与 626 人口上限落地后，线性无上限会让 626 人直接把修炼速度拉到几十倍，
> 所以改为**按大境界解锁的软上限**：硬上限仍然是取消的，但总和渐近于一档上限。

```
总加成 = cap × (1 − e^(−原始加成 / cap))
```

| 宿主大境界 | `realm.tier` | cap | 渐近上限 |
|---|---|---:|---:|
| 练气 | `qi` | 2.0 | +200% |
| 筑基 | `foundation` | 4.0 | +400% |
| 结丹 | `core` | 7.0 | +700% |
| 元婴 | `nascent` | 10.0 | +1000% |

- `原始 = cap` 时到 63.2%，`2×cap` 时到 86.5%，`3×cap` 时到 95%。
  即练气期 6 点原始加成 ≈ +190%，元婴期 30 点 ≈ +950%。
- **cap 随宿主大境界切换**，突破后立即重算；不是子嗣各自的封顶。
- 元婴以上（化神等）未定，暂沿用 10.0，等 22 级境界落地再补。

**配平口径**：软上限是防爆安全网，真正的配平仍以《[产出登记表](../00-总览与状态/产出登记表.md)》
全部已登记产出为输入，按宪法第二章的绝对时间倒推；子嗣加成（R07）只是其中一项。

    只撞中「猪 + 灵兽」那类部分标签（0.394）→ **2.79/天**，约 **25 天**；
    家里一件都对不上（0）→ **2/天**，约 **35 天**。
    ⚠ 旧校验「同参 0.6 → 3.2/天、一层 22 天」是固定值时代的口径，现在随家的收藏波动。
    每级耗时仍随层数增长：六层约 163 天、八层约 262 天（0.394 那档约 ×1.3）。
  - **2026-10-27 为什么改**：旧曲线「日增 ×1.5、升级所需 ×1.5」⇒ 每级耗时**恒定 31 天**，
    而桂冈打坐受灵力限制（每次消耗 `1.5^层`，灵力产出只按 `1.2^层` 涨），
    每级耗时随层数明显变长。结果子嗣从练气六层左右开始反超桂冈，
    与「多子多福」的设计预期相反。现在子嗣与桂冈**共用同一条修为曲线**、日增按 ×1.2 涨。
  - ⚠ **灵根系数（P55-a 重标）**：单 **1.0** / 双 **0.68** / 三 **0.40** / 四 **0.13** / 五 **0.04**、
    跨度 **25 倍**。旧 `{1.0, 0.8, 0.7, 0.6, 0.6}`（单/五只差 1.67 倍）作废。
    按配给同参 0.6、修行效率 90% 校准：**单灵根 5.7 岁筑基 / 81.6 岁结丹 / 221 岁圆满**；
    双 8.4 / 120 / 325；三 14.2 / 204（金丹无望）；四 43.8 / —；**五 142.2 岁筑基 ⇒ 超了寿元 120，死也筑基不了**。
    ⚠ 已知残余：同参 1.0 + 纯打坐这一极限下五灵根仍能 102 岁筑基（拍板时已知、不追）。
  - ⚠ **筑基段平税**：L ≥ 11 升级所需 **×4.8**（`costBump`）。几何加税 `1.35^(L−11)` 实测两头都对不上
    （结丹初期太快、圆满太慢），已改平税。
  - ⚠ 旧校验「成年 420 天约练气九层」「成年 = 1260 天约练气六层」全部作废：
    **1:1 之后成年 = 6,570 游戏天 = 18 岁**，此时单灵根已筑基。
- 武器、防具、灵兽**不影响修炼速度**，只影响战斗面板。
- **出战门槛：修为达到练气二层**；废除「18 岁成年」。
- 无灵根子嗣**满 10 岁**（**3,650 游戏天**，365 天/岁）后才能安排家族工作。
  2026-10-20 拍板「太小的孩子当差像吃空饷」；2026-10-29 P55-a 从 13 岁下调到 10 岁
  （与 `growth.workStage = 'youth'` 对齐）。
  ⚠ **女儿 10~13 岁可以上工**（婚配 14 岁才外嫁）—— 旧口径「女儿整条线不做工」作废。

### 15.3 子嗣装备与战斗（极简）

- **4 个装备槽**（主角是 13 件套，子嗣简化）：
  1. 1 攻（武器）：提供战力。
  2. 1 防（防具）：提供气血。
  3. 1 同参：只提供契合度，加速修炼。
  4. 1 灵兽：提供战力/气血。
- 战斗属性只有 **【气血】** 与 **【战力】**；灵根只影响修炼，不影响战斗伤害。
- 子嗣在回合制战斗中作为独立单位，按战力输出、按气血承伤。
- 气血归零 → **养伤或陨落**：探索只养伤；秘境可陨落（`status: 'fallen'`，不删列表条目）。
- 具体战斗公式在《模块五-任务战斗》细化。
- **凡人子嗣穿不了灵器，只认不入品的凡俗物品**（P51 #5，2026-10-27 B5 落地）。
  - **不入品 = 凡俗物品**（`tierKey: 'none'` / `tier: 0`）；**只成色为 `none` 不算**
    （`quality:'none'` 但 `tier:3` 仍是三阶灵器）。
  - 闸门看 **`hasRoot`**，不看启蒙：有灵根的子嗣哪怕还没启灵也能穿。
  - ⚠ **物品池现在一件不入品都没有**（炼器 / 宝匣 / 探索全产有品阶灵器）⇒
    凡人子嗣实际**什么都穿不上**，属预期行为；等凡俗物品有产出源（坊市 / 探索）再放开。
  - 不影响战力：出战门槛本来就是「有灵根 + 练气二层」，凡人子嗣从不参战。

### 15.4 冗余物品：一键操作

- **一键装备**：自动给桂冈和所有出战子嗣穿满装备。
  - 同参：遍历背包，自动计算对当前角色契合度最高的同参（优先契合度、其次品阶）。
  - 攻/防/灵兽：优先穿戴品阶最高、成色最好（下/中/上/极）的物品；淘汰的进背包。
  - 限制：子嗣境界不够，穿不上高阶装备。
- **一键售卖**：背包中未装备且未锁定的物品全部卖掉。
  - 可勾选「只卖凡品/下品」「只卖一阶/二阶」。
  - 产出直接转化为灵石（未来凡俗产物可转金页子）。

### 15.5 寿命与死亡

> **设计定稿；代码未落地**（排在《下一步》排序链的「子嗣寿命」批）。
> 刻度真源 = §7.1：**1 仙龄岁 = 365 游戏天**（2026-10-29 P55-a 起两轨相同）。

- 寿元（**仙龄岁**）：凡人 **80** / 练气 **120** / 筑基 **200** / 结丹 **500**。
  换成游戏天是 **29,200 / 43,800 / 73,000 / 182,500 天**。
- **寿元按当前境界实时同步**（不是出生时锁定）：升级即延长，与「侍妾寿元跟境界走」同一条规则。
- **判定时机**：日结（`advanceInnerCourtDay`）**先修炼突破、再判寿终** ——
  否则「今年升级延长寿命」那一年会被提前判死。
- 每年判定一次；年龄 ≥ 寿元且存活 → `status: 'passed_away'`（寿终正寝）。
- **老档**在 `normalizeInnerCourtOnLoad` 之后按 `realm` 补 `lifespanYears`，不升存档版本号；
  已超龄的读档即判；怀孕/产后中**顺延**到恢复结束再判。
  > ⚠ **存量会成批寿终**（2026-10-29 重排理由）：落地前存档里已经堆了**大量越过寿元的子嗣**
  > （代码此前没有判定），第一次读档判定会一次性把整批标成 `passed_away`。
  > 这是**预期行为**，不是 bug；讣告按「子嗣 N 人」聚合一行，不逐个弹窗。
- **在岗 / 出战 / 历练中的寿终**：判定前先把该子嗣从家族工作岗、秘境编成、历练名单里摘出，
  再标 `passed_away`（否则岗位与出战名额会挂在死人身上）。
- 寿终的数组条目**不删**（家族树要读），只从「存活」统计与各类名单里过滤掉 ——
  家族树节点变灰，主表不再显示。
- 战斗陨落 → `status: 'fallen'`，不删列表条目，进英烈祠/家族树折叠层。
- **老死不算英烈**，不提供家族底蕴加成；讣告按「妻妾 / 子嗣」计数聚合，离线同款一行。
- **离线不进暂停点**：一次离线最多 180 游戏天 = **0.49 仙龄岁**，撞上的概率低且可预期。
  ⚠ 这条依赖 `OFFLINE_TUNING.maxGameDays = { qi: 180, ascended: 180 }`；**筑基段配额一旦放开到
  3,650 天（R33 的待办）就变成一次 10 仙龄岁**，届时必须重新评估是否仍不进暂停点。

> ⚠ **24× 的后果（2026-10-29 P55-b）**：筑基后 1 仙龄岁 = 24.3 现实分钟 ⇒
> 凡人 80 岁 = **32.4 现实小时**、练气 120 岁 = 48.7h、筑基 200 岁 = 81.1h。
> 也就是说**切到 24× 之后，妻妾与凡人子嗣会在几天内成批寿终** —— 这是「仙凡永别」的设计意图，
> 首次进筑基有居中弹窗预告（§7.1 同批），**不是 bug**。
>
> ⚠ **桂冈自己的寿元不建模**（B1 拍板）：不加 `lifespan` 字段、不进讣告。
> 2026-10-29 暴露过「结丹圆满 506 游戏岁 > 结丹寿元 500」，**已按用户拍板收窄宪法结丹段
> 现实锚点解决**（结丹圆满 → 445.6 岁，余量 54 岁）。寿元表本身没动。

### 15.6 家族树（分形折叠）

#### 15.6.1 树形态（✅ 2026-10-22 Q6 定稿，取代「按代折叠列表」）

- **A · 纵向缩进树**：每代缩进一层，节点可折叠。
- **默认只展开桂冈 + 第一代**；626 人规模下默认折叠是必须的，否则节点爆炸。
- **节点显示**：

| 类型 | 显示 |
|---|---|
| 桂冈 | 姓名 + 境界 |
| 侍妾 | 姓名 + 位阶；寿终后节点保留并变灰（寿元跟境界走，不是固定 80） |
| 有灵根子嗣 | **姓名（境界）** + 状态符号 + `[母：xxx]` |
| 无灵根子嗣 | **只有姓名** + `[母：xxx]`（凡人无境界） |
| 已外嫁女儿 | 姓名 + 💍，**叶子节点，不展开后代** |
| 陨落 | 姓名 + ✝，变灰，不展开 |

- **状态符号**：🟢 存活 / ✝ 陨落 / 💍 已外嫁 / 🏠 已分家（未来）。
- **挂载规则**：
  - 树本质是**父系树**（Y 染判定，只看男系）。第一代按**生母**（侍妾）分组挂桂冈下；
    **第二代+ 按生父 `fatherId` 挂载**，生母只用来反查生父。
  - **儿媳不上树**，不为配偶生成全局 id。孙辈只在行旁注 `[母：张氏]`（读 `motherName`）。
    理由：`spouse` 是子嗣对象里的内嵌对象，无 id、不入侍妾池（§7.4），上树会逼出一套假 id。
- **`motherId` 现状（✅ 2026-10-23 已核对代码，旧挂起项销掉）**：

| 场景 | `fatherId` | `motherId` | `motherName` |
|---|---|---|---|
| 第一代（桂冈亲生） | `null` | 侍妾 `id` | 侍妾姓名 |
| 孙辈及以下 | 生父 `id` | `''` | 儿媳姓名 |

  代码位置：`stores/modules/innerCourt.js` 新档写入处。**新档不需要任何迁移**。
- **老档兜底**：早于 P14 的子嗣若 `motherId` 与 `fatherId` 都为空，统一挂在一个
  「旁系 / 失传」虚拟节点下，不丢人、不猜母。正常新档走不到这条分支。
- **性能**：树先 `flatten` 成行数组再渲染（为将来接虚拟滚动留路）。
  v1 **不接虚拟滚动** —— 默认只展开桂冈 + 第一代，实际节点 = 1 + 侍妾数 + 第一代人数（几十个），
  真卡了再接 `n-virtual-list`（项目此前没用过，先别提前上）。
- **代码落点**：`plugins/familyTree.js`（`buildFamilyTree` 纯函数 + 导出组装）·
  `components/FamilyTree.vue`（新增，缩进树 + 折叠）· `views/InnerCourt.vue`（替换家族树页签）。

### 15.7 分家、支脉与分封

- **分家条件**：单/双灵根 + 修为 ≥ 筑基 + 主家持有【未分配领地】。
- **分家效果**：该子嗣升格为支脉老祖，`branchId` 改为新支脉，代数重置为第 1 代；
  直系后代（生母、同母弟妹等）从主家谱剥离。
- **支脉运作**：
  - **岁贡**：每年上缴领地总税收的 **30%**（比例待模块四最终确认）。
  - **独立修炼**：支脉自带一块中等灵地，支脉子嗣修炼速度中等提升，不抢主家资源。
  - **战力支援**：主家打高难秘境可无条件一键征召支脉子弟；战死会减少该支脉人口与未来岁贡。
  - **忠诚与叛乱**：主家势弱（桂冈境界停滞且低于支脉老祖）或强征暴敛 → 拒缴岁贡甚至叛乱；主家可派兵平叛收回领地。
- **开疆拓土**：桂冈在封地页发起，消耗大量资源与游戏时间（期间无法镇守日常）；
  成功获得 `unassigned_territory`，失败重伤养伤、资源打水漂。
- **分封双入口**：封地页「赐予子嗣」；子嗣详情页「请求分封」。
- **无地可分**：高资质子嗣只能留在主家，逼迫玩家外出开辟/争夺。

### 15.8 家族羁绊

- **打虎亲兄弟**：同母兄弟姐妹同时编入同一队伍（秘境/战斗），全队总战力 **+10%**。
- **母凭子贵**：有灵根子嗣突破练气二层或更高时，生母自动晋升一级位阶（最高 P13），并大幅增加好感。

### 15.10 落地顺序

1. **子嗣修炼**（后台打坐 + 日增修为）——必须先做，否则「练气二层出战」不可达。
2. 把 `canFightOf` 从「有灵根 + 少年」换成「有灵根 + **练气二层**」。
3. 寿命/老死 + `passed_away` + 家族树折叠。
4. 4 装备槽 + 一键装备/售卖。
5. 分家/支脉/岁贡（依赖模块四的未分配领地）。
6. 家族羁绊（同母 +10%、母凭子贵）。

> ⚠ 在子嗣修炼上线前，**不要单独改 `canFightOf`**；否则所有子嗣都卡在练气一层，秘境无人可派。
