# 模块九：离线结算（v2.0）

**状态：结构定稿，代码未动。** 真源 = 本文；落地清单见《下一步》**P46**。

> **2026-10-25 重写**：取代 v1.0「方案 B」（3 天上限 / 效率 100→70% 递减 / 三档托管）。
> 旧口径的「3 天」= **2,700 游戏天**，新口径 12 现实小时 = **450 游戏天**，差 **6 倍** ——
> 不要把两套混用。

---

## 一、基础规则

| # | 项 | 口径 |
|---:|---|---|
| 1 | 离线上限 | **12 现实小时**（= 450 游戏天），超出部分不结算 |
| 2 | 结算效率 | **100% 平**，不递减 |
| 3 | 配置来源 | **沿袭下线瞬间**的配置（桂冈日常队列 / 百艺排班 / 封地建设 / 子嗣历练策略），不需要额外的托管设置 |
| 4 | 时间换算 | **唯一锚点 = 96 现实秒 = 1 游戏天**（`SECONDS_PER_GAME_HOUR = 0.25`）⇒ 1 现实秒 = 0.25 游戏小时、1 现实小时 = 37.5 游戏天 |
| 5 | 月长度 | 1 游戏月 = 30 天 = **48 现实分钟是名义值（完全不睡）**；实际因睡觉加速约 **34~42 分钟**（见《时间系统》§2.1） |

> **为什么上限是 12 小时而不是 3 天**：3 天现实时间 = 2,700 游戏天 ≈ 7.4 游戏年，
> 一次上线就能吃满四阶段收支表的一半，数值直接失控。12 小时已经能覆盖「睡觉 + 上班」，
> 再长对玩家没有额外意义。
>
> **为什么不做效率递减**：旧方案（8h 内 100% / 24h 内 90% / 2 天 80% / 3 天 70%）
> 是在「上限 3 天」的前提下设计的；上限压到 12 小时后，递减只会变成惩罚。
> **收益减少要登记**——本版不做递减，所以不涉及。

## 二、特殊事件（防呆与防死锁）

| 事件 | 离线处理 | 理由 |
|---|---|---|
| **封地告急**（妖兽入侵等） | **冻结封地**：不产出、不消耗、不推进时间。报告高亮提示，上线处理后才恢复 | 封地是全局资源源，继续跑会放大错误。⚠ **MVP 无对象**：告急在 P38 MVP 已关停（《模块四》§6.2），封地上线后本行才有东西可冻结 |
| **子嗣陨落** | **停住，上线弹窗** | 不可逆 + 有【修行返还】，不能替玩家决定。**这是唯一的暂停点** |
| **子嗣诞生** | 自动取名、**不使用洗命符** | 洗命符是手动道具，离线不消费 |
| **探索叙事** | 按 20 秒超时的**自动善意**分支处理并入账 | 与 P31 已实现的在线逻辑共用同一套 |
| **妻妾 / 子嗣寿终** | 不停顿，统一进报告【内宅讣告】 | 寿终是预期事件，不需要人工决策 |

> **侍妾下毒 / 生气 / 回娘家**：**2026-10-25 砍掉**（只存在于《模块八》事件卡，代码未实现）。
> 模块八对应三处要同步删除。侍妾好感本身保留为「出身值」，涨跌机制以后再议 ——
> **不做 galgame**。

## 三、结算算法（防卡顿）

**绝对不能按秒 / 按小时循环** —— 离线 12 小时 = 43,200 游戏小时，前端会卡死。
必须按**游戏天切片**：

```
1. offlineRealSeconds = now − lastSaveRealTime
2. 折算游戏天数 days = min(offlineRealSeconds × 37.5, 450)
3. runOfflineSimulation(days) 纯函数，以「游戏天」为步长循环
   —— 每一步**调各模块自己的日推进函数**，不另写一套结算：
   · 桂冈日常（按§三.1 的三选一）
   · 封地税收 / 灵田产出 / 药浴池转换
   · 侍妾怀孕 / 子嗣出生
   · 灵力 → 修为（按当天有效练功时长）
   · 百艺成品
   · 子嗣修炼 / 子嗣历练 / 家族工作（全量）
4. 中断：某天触发「子嗣陨落」→ 立即停止后续天数，标记待处理
   （「封地告急」本轮**无对象**，见 §二 与 §七）
5. 汇总：灵石、材料、宝匣、子嗣出生、讣告、修为与突破、重大事件
```

- 纯函数，不碰 store；返回值交给 store 一次性入账。
- 掉帧跨多个月由 `checkBoundary` 补触发的老问题不在这里 —— 离线是**独立读档入口**。

### 3.1 三大挂机：**严格三选一**（2026-10-26 B1 定）

桂冈离线时不可能同时镇守、探索、秘境。读**下线瞬间的状态**：

| 下线时在 | 离线跑什么 |
|---|---|
| **镇守** | 日常循环（练功 / 炼体 / 百艺 / 互动） |
| **探索** | 探索事件结算（含叙事 20 秒自动善意） |
| **秘境** | 按天切片跑秘境挑战（一趟 `ceil(层数/10)` 天） |

**子嗣独立**：子嗣的**历练与家族工作全量参与**，不受桂冈三选一影响 ——
它们本来就是日结的。家族工作里的经济产出照常入库。

### 3.2 突破：满足即突破（2026-10-26 B1 定）

- 修为到当前境界上限、且**契合度 × 灵地都达标** → **自动突破**，与在线同一函数
  （`core.tryBreakthrough`）。突破结果进报告汇总。
- **不达标就锁死**：修为卡在 **100% 不溢出**，报告高亮「修为已满，请上线更换功法 / 同参 / 灵地」。
- **不做「替玩家换配置」**：换功法 / 同参是玩家的决定，离线只执行已有配置。

### 3.3 资源落账：与在线完全一致

| 类 | 离线处理 |
|---|---|
| **宝匣** | **不自动开**，进 `inventory.chests`（开箱是玩家操作） |
| 灵石 / 材料 / 残页 | 直接进背包，沿用在线获取逻辑 |
| 子嗣诞生 | 自动取名、**不用洗命符**（洗命符是手动道具） |
| 侍妾 / 子嗣寿终 | 聚合进报告【内宅讣告】，见 §四 |

### 3.4 讣告必须聚合

12 现实小时 = 450 游戏天 ≈ 凡人一生。寿终会有**几十条**，报告**不能逐条列**：

> 内宅讣告：妻妾 **X** 人、子嗣 **Y** 人已寿终正寝（已移入家族树）。[查看名单]

名单点开再看逐条（按辈分 / 生母分组），不进主报告。

## 四、UI · 离线汇总报告

只展示大类汇总，不刷流水账。

```
【闭关归来】

你离开了现世 8 小时（游戏内经过 300 天）。

--- 收益汇总 ---
修为：+15,200（练气七层 → 练气八层）
灵石：+8,400
灵材 / 灵植：获得 245 件（已存入背包）
宝匣：获得 6 个（未开启，已入背包）
子嗣：新添 4 名（其中 1 名有灵根）
子嗣历练：完成 8 趟，带回灵石 3,200 / 灵材 41 件

--- 内宅讣告 ---
妻妾 3 人、子嗣 17 人已寿终正寝（已移入家族树）。[查看名单]

--- 重大事件记录 ---
[奇遇] 探索中遭遇古修洞府，获得 2 阶宝匣 ×1。
[提示] 修为已满，请上线更换功法 / 同参 / 灵地。
```

> ⚠ **没有「封地状态」区块**：MVP 没有告急，封地只会正常运转；等告急上线再加回来。

> 封地产出口（粮草 / 灵谷）在模块四 MVP 已废 —— 报告只列**一阶灵石、灵材/灵植、宝匣**。

## 六、与 v1.0 的差异

| 项 | v1.0（作废） | v2.0 |
|---|---|---|
| 上限 | 3 天 | **12 现实小时（450 游戏天）** |
| 效率 | 100/90/80/70% 递减 | **100% 平** |
| 托管 | 全托管 / 半托管 / 不托管，默认半托管 | **无托管模式**；唯一暂停点 = 子嗣陨落 |
| 时间暂停 | 停在第一个未托管事件 | 只在封地告急 / 子嗣陨落停 |
| 报告口径 | 粮草、灵谷、侍妾下毒 | 一阶灵石、灵材、宝匣；下毒已砍 |
