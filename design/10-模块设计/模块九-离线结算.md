# 模块九：离线结算（v2.2）

**状态：已落地（B2 2026-10-26；P55-c 2026-10-29 加「按境界两套」）。** 真源 = 本文；落地清单见《下一步》**P46 / P55-c**。

> **2026-10-29（P55-c）双层时间**：离线不再只有一套换算。练气期 1 游戏天 = 96 现实秒、
> 上限 180 天；**筑基后 1 游戏天 = 4 现实秒（24×）**，上限按**分段配额**另算。
> 跨境界的离线（下线时练气、离线期间筑基）**分两段记**：练气段烧掉多少现实秒，
> 剩下的预算再按新速率换算 —— 不按「下线那一刻的境界」一刀切。
>
> ⚠ **筑基段的配额暂按 180 天**（设计表写的是 3,650 天 ≈ 4.06 现实小时）：
> 实测真实档（666 子嗣 / 12,189 物品）逐日重放 3650 天要 **136 秒**、180 天要 **7.9 秒**，
> 瓶颈 96% 在内宅日结。2026-10-29 拍板「先落框架、上限暂用 180」，3650 等
> **跨期聚合结算**引擎落地再改一行常量（`OFFLINE_TUNING.maxGameDays.ascended`）。
> 这是**收益减少**，登记见《产出登记表》R33。

> **2026-10-26 上限下调**：12 现实小时（450 游戏天）→ **180 游戏天（≈4.8 现实小时）**。
> 依据：用现有纯函数实测 450 天 ≈ 探索 110,088 一阶灵石 / 3,387 件材料 / 48 个宝匣，
> 一次过夜就能顶掉玩家整档（当时最久存档才到游戏第二年）。**这是收益减少，
> 已在《产出登记表》登记**，旧 12 小时口径作废。
>
> **2026-10-25 重写**：取代 v1.0「方案 B」（3 天上限 / 效率 100→70% 递减 / 三档托管）。
> 旧口径的「3 天」= **2,700 游戏天**，不要把两套混用。

## 一、基础规则

| # | 项 | 口径 |
|---:|---|---|
| 1 | 离线上限 | **按相位两套**：练气期 **180 游戏天**（≈ 4.8 现实小时）/ 筑基后**同样 180 天**（设计值 3,650，R33 暂缓）。超出部分不结算；**世界日历也只推进结算的天数** |
| 2 | 结算效率 | **100% 平**，不递减 |
| 3 | 配置来源 | **沿袭下线瞬间**的配置（桂冈日常队列 / 百艺排班 / 封地建设 / 子嗣历练策略），不需要额外的托管设置 |
| 4 | 时间换算 | 练气期：**96 现实秒 = 1 游戏天**（`SECONDS_PER_GAME_HOUR = 0.25`）⇒ 1 现实小时 = 37.5 游戏天。**筑基后 24×**：**4 现实秒 = 1 游戏天** ⇒ 1 现实小时 = 900 游戏天 |
| 5 | 月长度 | 1 游戏月 = 30 天 = **48 现实分钟是名义值（完全不睡）**；实际因睡觉加速约 **34~42 分钟**（见《时间系统》§2.1） |

> **为什么上限是 180 游戏天**：1 游戏年 ≈ 7~10 现实小时（月长 34~42 分钟 × 12），
> 450 天 = 1.25 游戏年 ⇒ 「睡一觉、醒一年半」。实测一次过夜能把玩家整档积累顶掉一遍。
> 180 天 ≈ 半年，量级落在「一个白天/一个晚上」的合理区间。
>
> **为什么用「游戏天」而不是「现实小时」**：上限一旦按现实小时给，超过之后游戏日历
> 就会停在结算终点（世界变慢），而按游戏天封顶天然对齐——日历只走结算过的天数，
> 不会出现「过了时间但没判定」的错位。
>
> **为什么不做效率递减**：旧方案（8h 内 100% / 24h 内 90% / 2 天 80% / 3 天 70%）
> 是在「上限 3 天」的前提下设计的；上限压到 12 小时后，递减只会变成惩罚。
> **收益减少要登记**——本版不做递减，所以不涉及。

## 二、特殊事件（防呆与防死锁）

| 事件 | 离线处理 | 理由 |
|---|---|---|
| **封地告急**（妖兽入侵等） | **冻结封地**：不产出、不消耗、不推进时间。报告高亮提示，上线处理后才恢复 | 封地是全局资源源，继续跑会放大错误。⚠ **MVP 无对象**：告急在 P38 MVP 已关停（《模块四》§6.2），封地上线后本行才有东西可冻结 |
| **子嗣陨落** | **停住，上线弹窗** | 不可逆 + 有【修行返还】，不能替玩家决定。**这是唯一的暂停点** |
| **子嗣诞生** | 自动取名、**不使用洗命符** | 洗命符是手动道具，离线不消费 |
| **探索叙事** | 按 20 秒超时的**自动善意**分支处理并入账 | 与 P31 已实现的在线逻辑共用同一套 |
| **妻妾 / 子嗣寿终** | 不停顿，统一进报告【内宅讣告】 | 寿终是预期事件，不需要人工决策 |

> **侍妾下毒 / 生气 / 回娘家**：**2026-10-25 砍掉**（只存在于《模块八》事件卡，代码未实现）。
> 模块八对应三处要同步删除。侍妾好感本身保留为「出身值」，涨跌机制以后再议 ——
> **不做 galgame**。

## 三、结算算法（防卡顿）

**绝对不能按秒 / 按小时循环** —— 离线 12 小时 = 43,200 游戏小时，前端会卡死。
必须按**游戏天切片**：

```
1. offlineRealSeconds = now − lastSaveRealTime
2. 预算 = offlineRealSeconds 的现实秒；按相位分段（P55-c）：
   · 当前境界 → 相位（练气 / 筑基后）：`offlinePhaseOfLevel(level)`
   · 本段天数 = min(剩余预算 ÷ 该相位每游戏天的现实秒, 该相位剩余配额)
     练气 96 秒/天 · 配额 180 天；筑基后 4 秒/天 · 配额 180 天（设计值 3650，R33）
3. 用本段天数的终点调 `runOfflineSimulation` 的**同一个入口**，以「游戏天」为步长循环
   —— 每一步**调各模块自己的日推进函数**，不另写一套结算：
   · 桂冈日常（按§三.1 的三选一）
   · 封地税收 / 灵田产出 / 药浴池转换
   · 侍妾怀孕 / 子嗣出生
   · 灵力 → 修为（按当天有效练功时长）
   · 百艺成品
   · 子嗣修炼 / 子嗣历练 / 家族工作（全量）
4. 本段跑完再看境界：**变了**（离线期间筑基）⇒ 剩下的预算按新速率换算，回到第 2 步；
   **没变** ⇒ 预算或配额已经用尽，结算结束。报告用 `phases[]` 记下每一段的天数
5. 中断：某天触发「子嗣陨落」→ 立即停止后续天数，标记待处理
   （「封地告急」本轮**无对象**，见 §二 与 §七）
6. 汇总：灵石、材料、宝匣、子嗣出生、讣告、修为与突破、重大事件
```

> **为什么必须分段而不是按最终境界一刀切**：下线时练气、离线第 100 天筑基的话，
> 按最终境界算会把整段离线都当成 4 秒/天，等于白送 20 倍收益；按最初境界算又会
> 让破境后的玩家少拿。分段 = 「练气段烧掉 100 天 × 96 秒，余下的现实秒按 4 秒/天 换」。

- 纯函数，不碰 store；返回值交给 store 一次性入账。
- 掉帧跨多个月由 `checkBoundary` 补触发的老问题不在这里 —— 离线是**独立读档入口**。

### 3.1 三大挂机：**严格三选一**（2026-10-26 B1 定）

桂冈离线时不可能同时镇守、探索、秘境。读**下线瞬间的状态**：

| 下线时在 | 离线跑什么 |
|---|---|
| **镇守** | 日常循环（练功 / 炼体 / 百艺 / 互动） |
| **探索** | 探索事件结算（含叙事 20 秒自动善意） |
| **秘境** | 按天切片跑秘境挑战（一趟 `ceil(层数/10)` 天） |

**子嗣独立**：子嗣的**历练与家族工作全量参与**，不受桂冈三选一影响 ——
它们本来就是日结的。家族工作里的经济产出照常入库。

### 3.2 突破：满足即突破（2026-10-26 B1 定）

- 修为到当前境界上限、且**契合度 × 灵地都达标** → **自动突破**，与在线同一函数
  （`core.tryBreakthrough`）。突破结果进报告汇总。
- **不达标就锁死**：修为卡在 **100% 不溢出**，报告高亮「修为已满，请上线更换功法 / 同参 / 灵地」。
- **不做「替玩家换配置」**：换功法 / 同参是玩家的决定，离线只执行已有配置。

### 3.3 资源落账：与在线完全一致

| 类 | 离线处理 |
|---|---|
| **宝匣** | **不自动开**，进 `inventory.chests`（开箱是玩家操作） |
| 灵石 / 材料 / 残页 | 直接进背包，沿用在线获取逻辑 |
| 子嗣诞生 | 自动取名、**不用洗命符**（洗命符是手动道具） |
| 侍妾 / 子嗣寿终 | 聚合进报告【内宅讣告】，见 §四 |

### 3.4 讣告必须聚合

12 现实小时 = 450 游戏天 ≈ 凡人一生。寿终会有**几十条**，报告**不能逐条列**：

> 内宅讣告：妻妾 **X** 人、子嗣 **Y** 人已寿终正寝（已移入家族树）。[查看名单]

名单点开再看逐条（按辈分 / 生母分组），不进主报告。
