## 一、设计定位

结丹之时，修士要从自身感悟中体会出一条适合自己的道，当做立论，否则丹不能成。
结婴之时，再从丹论中悟出大道真意 —— **结丹之论与结婴息息相关**，不可草率。

落实到游戏里：

- **不是数值系统**：不加战力、不加契合度、不进门槛。
- **是一次重叙事节点**：形式和「筑基之途 · 仙凡永别」（`AscendedNotice.vue`）同构。
- **通知档不新增**：筑基那个是「模块解锁」档的一次应用，丹论同理并入**解锁档**，
  《模块解锁方针》§四 一个字都不用改。
- **候选来自玩家自己的存档**：用和成就系统一样的 `condition: player => boolean` 判定，
  跑出「你这一路走成了什么样」，给 3 条挑 1 条。**只复用判定写法，不复用成就的容器**。

## 二、触发与流程

| 项 | 规则 |
|---|---|
| 时机 | **金丹一层（内功 level 21）突破成功后**立即触发，挂在 `core.js` 的 `tryBreakthrough` 里 |
| 频率 | **一辈子一次**。`danLun` 已存在就不再弹 |
| 老档 | **不补弹**（2026-11-06 拍板）。已有金丹、没有 `danLun` 的档，修炼页显示「未立论」 |
| 离线突破 | 离线期间破了金丹 → **先确认离线报告，再弹**（同仙凡永别的排队方式） |
| 时钟 | **必须暂停**：`pauseForEvent('danlun')`，选完 `resumeFromEvent('danlun')`。金丹 168×，不暂停读 30 秒 = 走过 52 游戏天 |
| 关闭 | **不可关**（无 ESC、无遮罩关闭、无关闭按钮），必须立一条论才能继续 |
| 候选快照 | 判定字段随时在变，**候选列表在触发时存进存档**，刷新不重掷 |
| 展示位置 | 立论后，**修炼页**（`Cultivation.vue`）显示「丹论：水之污浊」，点开看全文 |

## 三、弹窗形态

照 `AscendedNotice.vue` 的体例，但多一层选择：

```
                    结  丹  之  论

  论曰：水无常形，浊者能容；容而成海，清者反枯。

        ┌────────────────────────────┐
        │  水 之 污 浊                │  ← 选中
        │  凿池求清，清极无鱼；       │
        │  引浊灌园，浑水生鳞。       │
        │  世人以清自矜，             │
        │  我以浊自广。               │
        │  · 你以《观潮经并注》入道   │
        └────────────────────────────┘
        ┌────────────────────────────┐
        │  守 拙                      │
        │  早开者早谢，慢行者不迷。   │
        │  今日之事今日毕 ——          │
        │  明日，自有机缘。           │
        │  · 你走得不快，可一步没落下 │
        └────────────────────────────┘

                    [ 立  此  论 ]

        此后结婴，皆从此论中求。
```

- 标题竖排金色，候选卡片选一张，底部确认。
- 每张卡片 = **论名 + 四句释义 + 一行出典**；论辞放弹窗顶部（选中后换成对应那条）。
- 体例基准 = `AscendedNotice.vue` 的四句文言：「昔王质入山观棋，斧柯尽烂…」

## 四、候选池（27 条 · 文言版）

### 选取规则

1. 跑一遍全部 `condition`，命中者进池。
2. 按 `weight` 降序；**同一 `theme` 最多取 1 条**。
3. 取前 3 条；不足用兜底（`theme: fallback`）按顺序补。
4. 3 条整体快照进 `danLunCandidates`，玩家选定后写 `danLun`。
