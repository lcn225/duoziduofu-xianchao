## 一、参战单位与编成

**一队 = 桂冈 + 3 名子嗣 + 1 只灵兽**（5 个坑，`companionSlots` 3 + `petSlots` 1）。
灵兽是**独立第 5 坑**，不与子嗣抢位置（P43，2026-10-25）。每层战斗对面**只有 1 个敌人**。

| 来源 | 构建函数 | 面板公式 |
|---|---|---|
| 桂冈 | `buildPlayerUnit(snapshot)` | 见 §二；快照由 store 的 `buildPlayerSnapshot()` 给 |
| 子嗣 | `buildOffspringUnit(child, { nowSeconds })` | 四属性 = `base × 境界系数 × 灵根 × 本命 × (1 + Σ词条)`，**装备加算在最后**、不吃任何乘区；速度 = `8 + 层号 × 0.2 + 装备速度` |
| 灵兽 | `buildPetUnit(pet)` | `petUnit.petPanelOf`：白板(T1~T5) × 成色 × 境界系数；旧实例上的百分比字段有就沿用 |
| 敌人 | `buildEnemy(floor, { difficulty })` | 等效境界曲线，**真源《三大挂机》§4.8**，这里不重复数字 |

- `base`（子嗣）= 生命 60 / 攻击 6 / 防御 3 / 速度 8（`TUNING.offspring.base`）。
- `境界系数`：练气一~十层线性 1.0 → 5.0，筑基 10.0，金丹 30.0；真源 `plugins/realmCoef.js`。
  灵兽与子嗣**共用同一个系数**，敌人曲线用它的连续版 `realmCoefAt(E)`。
- **出战门槛**（子嗣）：**有灵根 + 修为达到练气二层**（`innerCourt.TUNING.offspringCultivation.fightLevel`）。
  真源 `canFightOf`，秘境只转发不另立一套。`fallen` / `passed_away` 都不能上场。
- **编成方式两套**：秘境整备页玩家手选（默认填满）；飞鹰门杀怪任务**自动取战力最高的 3 名**（`buildFactionPartyUnits`）。

### 1.1 战力（只展示，不参与判定）

```
有效生命 = 气血 × (100 + 防御) / 100
战力     = 攻击 × 有效生命 / 100
```

- 与承伤公式同口径（防御 100 = 减伤一半），《数值真值表》§5.5。
- **速度不进战力** —— 它只决定出手顺序，不改变总输出。算进去会造出「战力高但打不动」的假象。
- 灵兽面板用 `attack`、子嗣/桂冈用 `damage`，两个键名都认。
- ⚠ 暴击/连击/闪避等百分比字段**不计入**，所以它是估算值，UI 显示用、不拿来做胜负判定。

## 二、桂冈面板（战斗侧唯一入口 = `combatPanel`）

```
combatPanel = (本体四属性 × 境界乘区 + 装备 + 灵宠 + 炼体)
            × (1 + 传承战力词条)
            × (1 + 非心法功法)

境界乘区 = 1 + 0.12 × powerLevelOf(层号)
```

- **只有本体吃境界乘区**；装备 / 灵宠 / 炼体是平加，避免被乘区二次放大（《装备系统》§十一）。
- 30 级表下必须过 `powerLevelOf` 映回 18 格：练气八层 ×**1.96**、练气二层 ×1.24。
- 后两个乘区跨系统乘算（《装备系统》§十 · 《功法系统》§5.4）；非心法四项各自先套软上限（P56-c）。
- ⚠ **成长幅度待定（P25，2026-11-07 用户评「太低」）**：现行 `0.12/层` 是 P36 第 2 步
  （2026-10-23）落的方向 ②。它**不是**「境界不加属性」—— 那条 2026-10-21 的旧描述已过期，
  别照着它改。要不要抬系数、要不要加灵根/装备侧联动，等 B10 定。
- ⚠ 顶栏、战斗、秘境快照**都读 `combatPanel`**；别再手拼 `baseAttributes`
  （它混着装备与灵宠，会被乘区二次放大）。

## 三、伤害结算（`resolveAttack`）

一次出手按顺序过九道：

| # | 判定 | 公式 / 效果 |
|---:|---|---|
| 1 | **闪避** | `clamp(守方 dodgeRate − 攻方 dodgeResist, 0, 1)` 命中则**本次 0 伤害、结束** |
| 2 | 基础伤害 | `攻击 × (1 + 攻方 combatBoost)` |
| 3 | **暴击** | `clamp(攻方 critRate×(1+combatBoost) − 守方 critResist×(1+resistanceBoost))`；命中 × `1.5 + critDamageBoost`（默认 0.5 ⇒ **×2.0**） |
| 4 | **连击** | `clamp(comboRate − comboResist)`；命中 ×1.3（与暴击可叠加） |
| 5 | 最终增伤 | × `(1 + finalDamageBoost)` |
| 6 | **防御减免** | × `100 / (100 + 守方防御 × (1 + 守方 combatBoost))` |
| 7 | 最终减伤 | × `(1 − clamp(finalDamageReduce, 0, 1))` |
| 8 | 保底 | **至少 1 点**（再高的防御也打不死免疫） |
| 9 | 附带 | **吸血**：`vampireRate − vampireResist` 命中 ⇒ 回**实际伤害的 20%**；**眩晕**：`stunRate − stunResist` ⇒ 目标**下一回合跳过** |

- 百分比字段共 19 个（`PERCENT_FIELDS`），`normalizeStats` 统一钳到 `0~10`（防脏档；
  正常取值 0~1）；`critRate` / `dodgeRate` 额外钳到 `0~1`，默认 **0.05**。
- ⚠ **敌人只带 `critRate`（普通 5% / Boss 10%）与 `dodgeRate`（3% / 5%）**，其余全 0；
  子嗣侧只有装备给主副属性、不给百分比。所以**连击 / 吸血 / 眩晕目前实际上只有桂冈和灵兽吃**，
  暴击也只在桂冈/灵兽/敌人之间出现 —— 这是现状，不是漏配。
- `healBoost` 字段有定义、**没有消费点**（治疗只有吸血那 20%），别以为它生效。

## 四、回合与出手顺序

1. 每回合把所有存活单位按**速度降序**排，同速按 `uid` 字典序（保证可复现）。
2. 每个单位行动一次，目标 = 对面**随机一个存活单位**（秘境对面只有 1 个）。
3. 被眩晕的单位**跳过本回合**并清掉标记。
4. 一方全灭即结束；否则打满 `maxRoundsPerBattle = 30` 回合。
   **超时**：开了自动撤退 ⇒ 按撤退收尾，否则按战败。
5. 战斗是**同步预演**：`runSegment` 一次算出整段的 `frames`，视图只按倍速回放。
   刷新最多丢动画、不丢结果；node 也能直接断言。

## 五、撤退（自动血线）

**按每个人自己判定，不按全队平均**（2026-10-23 用户拍板；旧「全队平均 / 一人触线整队回家」已作废）。

| 规则 | 口径 |
|---|---|
| 撤退线 | 整备页滑杆 **0~50%、5% 步进**，默认 **20%**；**设成 0 = 关闭自动撤退**（`autoRetreatPct > 0` 才算开） |
| 谁参与 | 只有 `side === 'ally'` 且**非灵兽**（`retreatEligible`） |
| 触线 | 受击后**立刻**判定：`hp% ≤ 撤退线` ⇒ 他退出本趟，其余人继续打 |
| 致命伤 | **开自动撤退时**：伤害压到「剩 1 血」，然后他自己退出 —— **不陨落** |
| 桂冈退出 | = **本趟挑战立即结束**（他带队），`outcome = 'retreated'` |
| 子嗣退出 | 只退他一个，下一层不再上场 |
| 跨层 | 退出名单存在 `run.withdrawn`，`runSegment` 每层先剔除再开打（否则 Buff 门会把他满血复活） |
| 灵兽 | **不参与撤退**：倒地记 `ko`，下一层 `cloneUnit` 满血复活，不进陨落账本、不带走任何人 |

- **退出 ≠ 倒下**：退出者 `alive = false` 但带 `withdrawn = true`，统计死亡时必须排掉，
  否则撤退会被算成阵亡（`deaths` 的 filter 已处理）。
- 一场里有人退出、其余全倒 ⇒ 按**撤退**收尾；没人退出、全倒 ⇒ **战败**。

## 六、陨落（只有秘境会死人）

| 环节 | 口径 |
|---|---|
| 开关 | 整备页勾「关闭自动撤退，允许子嗣陨落」= `permadeath: true`；**默认 false** |
| 谁能死 | **只有子嗣**（`source === 'offspring'` 且 `permadeath`）；桂冈与灵兽永不陨落 |
| 记凶手 | 敌人 `name`（形如「赤炎虎王·第35层」）随 `deaths[].killerName` 带回（B1） |
| 标记 | `status: 'fallen'`，**条目不删**（家族树 / 生母的 `childrenIds` 还指着它） |
| 落账 | `recordSecretRealmDeaths`：进英烈祠 + 返还**当前修为上限 × 5%**（`deathReturnRatio`）+ 返还词条 |
| 英烈祠 | 每块牌位 **+1% 打坐修为**（上限 10%）、**+0.1% 后代灵根**（上限 1%） |
| 提示 | **第 2 档横幅**：`emitNotice({ kind: 'fall' })` + `formatFallText`，**同结算周期合并一条**、不堆叠、不暂停 |
| 离线 | **进报告不弹**；子嗣陨落是离线结算的**唯一暂停点**（等确认才释放时钟） |

> ⚠ **看起来像 bug 的预期行为**：撤退线以下挨一刀会**留 1 血退出**，不是「该打死却没死」——
> 那是自动撤退的保护机制。想让子嗣真死，必须勾掉自动撤退。
>
> ⚠ 现存缺口：这是**死后**横幅（告诉你谁死了），没有「死前预警」。
> 原始诉求（P53 #12）若是「这一刀要打死他，先拦一下」，那还没做 —— 见 §八。

## 七、三个接入点（差异表）

| 系统 | 怎么打 | 撤退 | 陨落 | 时间成本 |
|---|---|---|---|---|
| **秘境** | `runSegment` 逐层预演，每 5 层停在 Buff 门 | 玩家设线 | 可开 | `ceil(max(0, 已通 Boss 层 − (起点−1)) / 10)` 游戏天 |
| **飞鹰门·杀怪任务** | **只打难度 D 的第 5 层 Boss**（前 4 层视为清场，血量不继承） | `autoRetreatPct: 0` **强制关** | `permadeath: false`，**永不死** | 1 游戏天（任务时长） |
| **探索** | **不跑战斗**，只掷胜率：同境界 70% / 高 1 层 90% / 高 2 层 100% | — | **永不陨落**，战败只回家养伤 | 按探索时长 |
| **镇守** | 无战斗（大本营经营） | — | — | — |

- 秘境与飞鹰门共用同一套 `buildPlayerUnit` / `buildOffspringUnit` / `buildPetUnit` / `buildEnemy` / `simulateBattle`。
- 飞鹰门杀怪**只打 Boss 是 MVP 口径**（`faction.js` 注释已标），逐层推已于 **2026-11-07 随 B10 降级到 v1.5 展望**，别当成「5 层只打了 1 层」的 bug。
- 探索的胜率**只看境界差**，不看攻防面板 —— 换装备不会提高探索胜率。
