一、核心机制与公式

1.1 连续契合度

系统不再使用 1.0/0.8/0.6/0.4/0.25/0.1 的六档，改为 0% ~ 100% 的连续小数（如 0.50）。

1.2 权重计算公式

```
契合度 = 交集标签权重之和 / 本命标签总权重
```

· 分母：永远固定为本命的总权重（单向除法）。

· 含义：同参只要能提供本命需要的核心标签，分数就高。不惩罚同参自身标签少（支持诡代法）。

· 顶层标签不是扁平词表（2026-10-23 补）：同源可**衍生**（玲珑 → 七窍 / 通透），
  异词可**上位相通**（趋吉避凶 ⊃ 避死延生）。分子按这层关系算，不按字面撞词算。
  详见 §3.2 的重写示例。

· **不加防呆**（2026-10-23 拍板 C）：同型物品撞上几个中/底层标签就能拿到相应的分数，
  那是权重体系的正常结果 —— 顶层每个 1.0，撞不上顶层就拿不到那 61%。
  实测 0.39 × 功法 0.40 = 0.156，只够练气三层（0.15），**打不开任何一扇门**。
  门槛配平按真实分布算，别为它加惩罚项。

二、标签池规范（Tag Dictionary）

所有物品（包括作本命的物品）必须打上三级标签：

标签层级 权重 含义与示例 来源

顶层（核心意象） 1.0 物品的灵魂。如 饕餮纹、玲珑、七窍、镇邪、吞噬、三花 人工精标 / AI提取

中层（形态/材质） 0.4 物品的物理特征。如 剑、盾、牌、猪、青金石、暗金、玉 规则映射 / 词库

底层（大类归属） 0.25 物品的底层分类。如 灵器、灵兽、灵植、灵材 脚本强制打标

2.1 打标工程要求（AI/人工执行标准）

1. 三阶及以上物品：必须识别并赋予 1 个以上的顶层标签。

2. 一阶、二阶物品：凑合就行，不强制要求顶层标签。

3. 本命复用：本命就是物品，直接复用物品身上的标签，无需另外单独打标。

三、契合度计算示例

3.1 开局【风磨铜盾】对本命【饕餮玉牌】

· 本命标签：灵器(0.25)、牌(0.25)、青金石(0.4)、玉(0.4)、饕餮纹(1.0)、暗金(1.0)

· 总权重 = 3.3

· 同参【风磨铜盾】标签：灵器(0.25)、盾(0.4)、风磨铜(0.4)、坚固(0.4)、饕餮纹(1.0)、青金石(0.4)

· 交集标签：灵器(0.25) + 青金石(0.4) + 饕餮纹(1.0) = 1.65

· 契合度 = 1.65 / 3.3 = 50%

3.2 诡代法示例（**2026-10-23 重写 —— 旧版这个例子的说法是错的，作废**）

原作里其实是两件不同的事，不能混：

· **玲珑塔 ↔ 玲珑心 = 同源同参，不是诡代。** 「玲珑」在两件物品里都占比极高，
  这类顶层标签会**大量衍生**（玲珑 → 七窍 / 通透 / 机巧 …），交集本来就是一大片。
  高契合度是靠在「玲珑」这个核心上堆量堆出来的，不需要任何特殊规则。

· **玲珑心 → 赤尻马猴 = 诡代。** 成立的依据**不是撞上某一个 1.0 标签**，
  而是**上位语义相通**：赤尻马猴「晓阴阳、知人事、善出入、避死延生」，
  玲珑心「七窍通明、趋吉避凶」在更高一层讲的是同一件事。

→ 对打标工程的两条新增要求：

1. 顶层标签要留**衍生物**：「玲珑」与「七窍 / 通透」不是同一个词，但同源，要能关联。
2. 顶层标签要能标**上位关系**：「趋吉避凶」是「避死延生」的上位/同义，要能关联。

> 旧版按字面标签算出的「避死延生 = 1.0，1.0 / 2.65 = 37%」**不反映真实机制**：
> 玲珑心一个字面都撞不上「避死延生」，字面撞词的算法会把这种正经诡代算低。
> 37% / 39% 这两个数字不再当例子用（2026-10-23 拍板 C：契合度不加防呆）。

该例子未必符合原作，仅供参考

四、数值与门槛重构方案

4.1 动作路线解绑

· 突破门槛的判定依然是 功法 × 同参 × 灵地。

· 同参的变量变成了 0.00 ~ 1.00 的连续值。

· 不再强制“卡哪个槽”：如果玩家（或换人玩）带着满标签的完美同参、完美功法、完美灵地开局，综合契合度直接起飞，系统直接保送突破，无需强制干预。

4.2 重算突破门槛（**2026-10-23 拍板时机：打标跑完后一次性重算，不做六档兼容期**）

· 只重算一次：575 件标签打完 → `sim:fates` 全量仿真 → 定新的 0.15/0.24/0.40… 和 K。

· **不搞「六档旧值 + 连续新值」双轨**：没有兼容期，老档读档时按 §6.1 直接重算覆盖。

因为同参数值从离散变成了连续，原有的门槛（0.15 / 0.24 / 0.40 等）需要重新配平。

· 开发需编写一个仿真脚本，模拟玩家在不同阶段能获取的标签组合，算出期望的 综合契合度。

· 根据这个期望值，微调各个境界的 BREAKTHROUGH_THRESHOLDS。

· 如果算出来开局太容易过三层，不调同参，去调功法（如降低桂氏基础）或灵地（快子峰契合度）。

五、子嗣同参接入与性能优化

子嗣不再固定 0.6，彻底接入标签系统。但为保障“500 子嗣、全物品”的一键装备不卡顿，需采用缓存降维算法：

5.1 同类本命缓存（Top N 预计算）

1. 将全服 500 个子嗣按“本命物品 id”分组（比如 50 个都是猪本命，30 个是牌本命）。

2. 当背包物品发生变化（新获得/卖出）时，触发一次后台计算：

· 计算这些物品对所有已存在本命种类的契合度，排序取 Top 5 推荐列表。

· 结果存入缓存 Cache[本命id] = [物品A, 物品B...]。

3. 子嗣一键装备时，直接从缓存取第一名，O(1) 复杂度，瞬间完成 500 人替换。
