# 模块解锁方针 v1.1（显性条件版）

> **2026-10-26 定稿**。来源：`90-历史归档/讨论-2026-10-26/原始/《模块解锁设计方针 v1.1》（显性条件版）.md`
> 的正文 + 两个自留问题（已拍）。**这是所有「未开放」入口的统一口径**，不要各模块自己写一套。
>
> 前身是「隐性引导 / 痛点驱动」：玩家遇到痛点 → 自己去找解法。
> 放置游戏里这条不成立 —— **摸不到头脑的玩家不是去探索，是直接关掉游戏**。
> 所以改成 **「显性条件，柔性体验」**：条件全写出来，痛点只做包装。

---

## 一、底层逻辑

1. **痛点只做包装**：日志 / NPC 对话只说「你缺什么」（灵石见底、买不起侍妾），
   **不说去哪解锁** —— 去哪由 Checklist 说。
2. **条件必须明示**：未解锁的模块**不能纯隐藏**，必须占位 + 给可读的获取条件。
3. **达成后给动作，不给说明书**：一个点击就能完成的**破冰任务**，比十行说明有效。

---

## 二、四种 UI 状态

| 状态 | 触发 | 表现 |
|---|---|---|
| **① 锁定占位** | 条件未达成 | 导航栏图标**灰显 + 锁形**，位置固定（不随解锁重排） |
| **② 悬停 Checklist** | 悬停 / 点击锁态图标 | 弹提示框，列出条件 + 当前进度 + 解锁后能得到什么 |
| **③ 接近预兆** | 差一项 / 差一点数值 | 图标**闪烁或红点** + 一条日志预告（不弹窗） |
| **④ 达成** | 条件满足瞬间 | **居中弹窗**（带剧情包装）→ 立刻给破冰任务 |

**②  Checklist 长这样**（唯一格式）：

```
🔒【飞鹰门 · 内政】尚未解锁
  · 突破练气六层            当前：练气四层 45%
  · 建造乡侯府并升到 Lv.1    当前：未建造
  解锁后：贡献点任务 / 秘库兑换 / 门派俸禄
```

- **放导航栏**（用户 2026-10-26 拍板），不单做「目标 / 进度」面板。
- 条件按「境界 → 建筑 → 物品」排序，**最多 3 条**；超出的收进「其他条件」。
- 进度条只显示**缺的那一项**的数值，不显示内部公式。

---

## 三、破冰任务与奖励

- **弱引导**（用户 2026-10-26 拍板）：破冰任务**不阻塞**其他操作，玩家可以无视。
- 形式：一条任务卡 + 高亮目标控件，**点击一次即完成**。
- 奖励：**一次性**，登记在《产出登记表》O 类（不计入挂机曲线）。

| 解锁 | 破冰任务 | 奖励 |
|---|---|---|
| 封地经营 | 建造第一座【灵田】 | **100 一阶灵石**（O05） |
| 百艺 | 去百艺页排一次班 | 首个配方免费（不消耗材料） |
| 内政 | 接取第一个普通任务 | 30 贡献点（即首个任务报酬，不额外加） |

> 奖励刻意做小：它的作用是**把玩家推到那个界面**，不是变强。

## 四、通知分四档（**唯一口径**）

> 2026-10-26 拍板。所有系统只准用这四档，**新增通知前先对号入座**。

| 档 | 形态 | 用在哪 | 打断操作？ |
|---|---|---|---|
| **0 静默** | 只进流水账 / 日志 | 常规日结、子嗣成长、产出入库 | ❌ |
| **1 红点** | 入口上的小红点 | 「有东西可领 / 可处理」但可等：可升级、可开箱、欠俸 | ❌ |
| **2 横幅** | 顶部横条，可滑走 | 需要知道但不急：欠俸停摆、修为已满、某系药力到顶、**寿终讣告**、**子嗣陨落** | ❌ |
| **3 居中弹窗** | 模态，必须处理 | **只有四类**：模块解锁、离线报告、二选一叙事事件、**突破** | ✅ |

- **不许自造第 5 档**（如「闪烁图标 + 音效 + 弹窗」三连）；要更强的表达，先把第 3 档用对。
- 同一事件**只发一档**：发了弹窗就不再发横幅，发了横幅就不再点红点。

> **2026-10-30 三处归类（A1-3 / C1 / B1，用户当天拍板）**：
> - **突破**从第 2 档升到第 3 档弹窗（弹窗从四类 → **五类的那一次**，随后又被下一条收回，见下）。
>   **不暂停时钟**；同一次结算连升多级合并一条，跨结算分开弹、**队列上限 5**，
>   溢出合并成「突破至练气 N 层（共 M 次）」放队尾；离线只进报告不弹。细则见《下一步》A1-3。
> - **寿终讣告**从第 3 档弹窗**降到第 2 档横幅**（2026-10-30 用户拍板：**原作没出现过讣告**，
>   改成**模仿「受精时叮」的全局系统提示**，同档、不暂停时钟）。聚合格式见《模块二》§15.5.2。
> - **子嗣陨落**走**第 2 档横幅**，**不进弹窗**（陨落是「已经发生」，不需要玩家确认）。
>   同一次结算合并成一条、跨结算各出一条、不堆叠；离线进报告不弹。详见《模块二》§15.5.3。
>
> 净结果：**弹窗仍是四类**（模块解锁 / 离线报告 / 二选一叙事 / 突破），
> 与 2026-10-26 的「四类」相比**只换了一格**：寿终讣告让位给突破。
- 视觉实现见 [《UI 视觉规范》](UI%20视觉规范.md)；弹窗版式走 `n-modal` 的既定卡片。

## 六、实战推演：百艺

**痛点（日志 / NPC）**：老九看玩家背包里一堆杂草废铁：

> 「东家，这漫山遍野的东西，烧了多可惜，不如给我在乡里建个工坊，我教你把它们炼成宝贝换钱。」

**显性条件（Checklist）**：练气四层 + 拥有工坊（灵田/工坊建成）。

**达成**：居中弹窗「【百艺】已解锁」→ 破冰任务「去百艺页排一次班」→
首个配方免费，第二天拿到凡俗金器，卖钱成功，痛点解决。

> 这套「**显性条件 + 痛点包装 + 破冰任务**」三步走，以后任何新系统（含筑基后的）都照用。

## 七、落地约束与自检

1. **锁态占位不允许隐藏**：入口消失了，玩家就不知道有这个系统 —— 这违背第一条。
2. **导航栏位置固定**：解锁前后不重排，否则玩家的肌肉记忆每次都重建。
3. **条件只用玩家看得懂的三个维度**：境界 / 建筑等级 / 物品数量。**不写内部系数、契合度百分比**。
4. **未定条件不加锁**（见 §五 ⬜）：宁可晚锁，不要提前把已有功能关掉。
5. **通知分级统一走 §四**；模块文档里写「弹窗」的，先确认它是不是那四类之一。
6. 新增解锁点 = 一次产出变更：**破冰奖励一律登记 O 类**（《产出登记表》）。
