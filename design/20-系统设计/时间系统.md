## 一、模块定位

时间系统是所有模块的**底层骨架**，负责统一驱动修行、内宅、封地、经济、事件等所有跟时间相关的系统。

**核心设计**：时间有三种状态，由玩家当前所在模块决定。

| 状态        | 触发条件          | 时间推进     | 事件处理            |
| --------- | ------------- | -------- | --------------- |
| **自动推进**  | 修炼、探索等挂机模式    | 按 B 速度推进 | 普通事件进流水账，特殊事件弹窗 |
| **暂停**    | 内政、装备、内宅管理等模块 | 停止       | 无事件触发           |
| **暂停+弹窗** | 特殊事件触发        | 停止       | 弹窗等玩家处理         |

**关键规则**：时间只在“自动模式”下推进。玩家进入任何管理界面，时间立即暂停。

## 二、时间换算（B 速度）

### 2.1 基础换算

**2026-10-29 P55-b 起时钟按境界分两速**，分界点唯一 = `realm.isAscendedLevelOf`（内功 ≥ 11）。

**① 练气期（1:1）—— `SECONDS_PER_GAME_HOUR = 0.25`**

```
1 现实秒   = 0.25 游戏小时（15 游戏分钟）
1 游戏小时 = 4 现实秒
1 游戏天   = 24 游戏小时 = 96 现实秒 = 1.6 现实分钟
1 游戏月   = 30 游戏天 = 2,880 现实秒 = 48 现实分钟
1 游戏年   = 365 游戏天 = 35,040 现实秒 = 584 现实分钟 = 9.73 现实小时
```

**② 筑基后（24×）—— `SECONDS_PER_GAME_HOUR = 6`**

```
1 现实秒   = 6 游戏小时（24 个 15 分整步）
1 游戏天   = 4 现实秒
1 游戏月   = 2 现实分钟
1 游戏年   = 1,460 现实秒 = 24.3 现实分钟      ← ≈ P14 原始节奏（24 分钟/年），差 1.2%
1 现实小时 = 900 游戏天 = 2.47 游戏年
```

> ⚠ **24 这个数是反推的**：`365 ÷ 15 = 24.33 ≈ 24` —— P14 的原始刻度是 15 游戏天/岁
> （1 游戏年 = 24 现实分钟）。P54 的「45 天/岁（3×）」夹在中间两头不靠，**整层作废**。
> 现在 = 练气期用真实年龄（代入感）+ 筑基后回到 P14 压缩节奏（爽感）。
>
> **唯一锚点（2026-10-26 定）：96 现实秒 = 1 游戏天**（**练气期**）。筑基后仍是同一条锚点
> 被 24× 压成 4 秒 —— 不是第二个锚点。
> **「1 游戏月 = 48 现实分钟」是名义值**（按 30 天 × 24 小时全速算，**完全不睡**）。
> 实际日常循环里睡觉会加速播片，**真实约 34~42 分钟/月**（取决于当天互动次数与睡眠时长）。
> 凡是写「现实时间」的地方（秘库刷新、老九订货、离线报告）都要标明是名义还是实际、
> **以及是哪一速**：
> - **名义值**用于数值配平（月产 690 贡献点、月俸、税收）；
> - **实际值**用于玩家预期（「大概半小时一个月」）；
> - **筑基后所有「现实小时」口径 ×24**（1 现实小时 = 2.47 游戏年）—— B8 二阶重定价
>   被强制排在这一批之后，就是因为这个。
> 游戏秒 ↔ 现实秒的换算**只在小循环里成立**（P51 #16），日结/月结按游戏天，不按现实秒反推。

### 5.2 钩子实现

```javascript
class GameClock {
  constructor() {
    this.currentTime = 0;
    this.state = 'running';
    this.lastTickRealTime = Date.now();
    this.hooks = {
      tick: [], hour: [], day: [], month: [], year: []
    };
  }

  register(level, callback) {
    this.hooks[level].push(callback);
  }

  tick() {
    if (this.state !== 'running') return;

    const now = Date.now();
    const deltaRealSeconds = (now - this.lastTickRealTime) / 1000;
    // 1 现实秒 = 1 步 = 15 游戏分 = 900 游戏秒；按整步推进（见 §8.5）
    const steps = Math.round(Math.min(deltaRealSeconds, 5));
    const deltaGameSeconds = steps * 900;
    this.lastTickRealTime = now;

    const prevTime = this.currentTime;
    this.currentTime += deltaGameSeconds;

    // 每秒钩子（灵力积累等）
    this.hooks.tick.forEach(cb => cb(this.currentTime));

    // 检查跨越的时间边界
    this.checkBoundary('hour', prevTime, this.currentTime, 3600);
    this.checkBoundary('day', prevTime, this.currentTime, 86400);
    this.checkBoundary('month', prevTime, this.currentTime, 86400 * 30);
    this.checkBoundary('year', prevTime, this.currentTime, 86400 * 365);

    // 普通事件进流水账
    // 特殊事件入队，暂停时间
  }

  checkBoundary(level, prevTime, currentTime, unitSeconds) {
    const prevUnit = Math.floor(prevTime / unitSeconds);
    const currentUnit = Math.floor(currentTime / unitSeconds);

    for (let i = prevUnit + 1; i <= currentUnit; i++) {
      this.hooks[level].forEach(cb => cb(i * unitSeconds, i));
    }
  }

  pause() { this.state = 'paused'; }
  resume() { 
    this.state = 'running';
    this.lastTickRealTime = Date.now();
  }
}
```

### 8.5 倒计时显示口径与时钟整步

- **时钟侧**（`gameClock.js`）：`advance()` 按 **15 游戏分整步**推进
  （`GAME_STEP_SECONDS = 900`），tick 永远落在 15 分格点上；老档 / 离线落点带零头时
  先向下对齐。任务边界（06:00 + S、练功 1 小时、百艺 45 分）都是 15 分的整数倍，
  所以 1 小时轮**正好 4 个 tick** 结束，不会多拖一个 tick。
- **显示侧**（`dayDate.js` 的 `formatCountdown`）：倒计时再向下取整到 15 分档，
  兜住异常落点。1 小时轮 → `45 / 30 / 15`；45 分轮 → `30 / 15`；不足 15 分 → `不足 15 分`。
- 为什么两处都要：只对齐时钟不够（历史落点可能仍带零头），只改显示也不够
  （任务仍会拖到第 5 个 tick 才切换 —— 2026-10-27 用户反馈的「4 跳变 5 跳」）。
- 这是**显示层 + 时间推进粒度**的规则，不改变任何结算金额；
  「本轮 1 小时」这类静态时长仍用 `formatDuration`。

## 九、关键设计原则

| 原则          | 说明                   |
| ----------- | -------------------- |
| 时间只在自动模式下推进 | 管理模块时间暂停             |
| 普通事件进流水账    | 不打扰玩家                |
| 特殊事件弹窗      | 时间暂停，等玩家处理           |
| 晚间互动不占现实时间  | 玩家可慢慢操作              |
| 特殊事件不丢失     | 挂机期间触发的特殊事件会排队       |
| 流水账不需要筛选导出  | 只保留清空                |
| 统一时间轴       | 所有系统用同一个 currentTime |

## 十一、时间尺度决策（2026-10-19）

> 完整讨论存档见 [`90-历史归档/旧版设计/时间系统备忘录-2026-10-19.md`](../90-历史归档/旧版设计/时间系统备忘录-2026-10-19.md)。
> 这里只记**生效口径**。

### 11.1 路线 A（已落地）

- 1 游戏天 = **96 现实秒**不变；1 现实秒 = 0.25 游戏小时。（**练气期**；筑基后 24× 见 §2.1）
- 宪法第二章突破时间表**现实锚点一个字没改**；但游戏内时间要**分段换算**：
  ~~练气 0.48 年、筑基 3.4 年、结丹 21.9 年~~（旧单速口径，**作废**）
  → 现行 **筑基初期 0.77 岁 / 筑基圆满 60.9 岁 / 结丹圆满 445.6 岁**
  （`数值真值表` §1.2「游戏内累计」列）。
  结丹段原锚点会推到 506 岁 > 结丹寿元 500，**2026-10-29 已收窄为 24/32/40/60 小时** ⇒ 445.6 岁。
- 叙事时间 = 游戏时间 / 365，不与现实时间解耦。
- **经济横轴**用宪法第二章的月数（生存 5.9 / 扎根 35.4 / 扩张 225.8），与周循环、离线快进解耦。
  ⚠ 这些是**游戏内月数**，不受 24× 影响；「对应多少现实时间」则要分两速。

### 11.2 周循环（备选，暂不上线）

- 循环粒度从「一天」改成「一周」，播片仍按天播；循环时长 T 只影响游戏时间速率。
- 推荐 **T = 70 秒或 56 秒**（28 秒播片太短，看不清）。
- 上线条件：原作里桂冈解决专注力问题（推测筑基后）。
- 上线时要定：筑基前后速率切换规则；逐阶段调 T 还是全局统一。

### 11.3 离线快进（挂起，等模块九）

- 分工哲学：在线看日常动画 + 流水账；离线回来体会时光荏苒。两层不互相替代。
- 建议：**5 倍、上限 8 小时、自动托管**。
- 真正的障碍不是倍率，而是「离线占比 97% 时日常循环被稀释」和「离线时谁做决策」。

### 11.4 当前生效口径

1. 路线 A；宪法第二章的**现实锚点不重算**，但**游戏年龄要按 §2.1 两速重算**
   （2026-10-29 P55-b）。
2. 周循环备选；T = 70/56 秒；筑基后再议（24× 落地后这一项基本被取代，见下）。
3. 离线快进：**模块九 B2 已落地**（上限 180 游戏天，按境界两套，见《模块九》§一）。
4. **2026-10-29 P55-b**：筑基后在线时钟 ×24（1 游戏天 = 4 现实秒）。§11.1 的「练气 0.48 年 /
   筑基 3.4 年 / 结丹 21.9 年」是**旧单速口径，已作废**。

> **§11.2 周循环怎么办**：它当初的动机是「筑基后想要更快的节奏」。24× 已经把这个需求吃掉了
> —— 筑基后 1 现实小时 = 2.47 游戏年，比任何周循环都激进。**先挂起，等实机反馈再定**。
4. 经济横轴用宪法第二章月数，与周循环/离线解耦。
