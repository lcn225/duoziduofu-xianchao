**基阶系数：×3^(阶−1)（几何）。** T1 基值不动；旧版线性 ×1/2/3/4/5 作废。

### 5.4 确定性生成

```js
const seed = hash(series + ',' + tier)
主属性数值 = 基础值(tier) × (0.85 + 0.30 × seededFloat01(seed))   // ±15%
```

- **同 series 同 tier 永远一样**（玩家可预期、可查表）。
- **不同 series 同 tier 不同**。
- 「攻击 或 防御 / 速度 或 生命」的二选一也吃同一个 seed，保证稳定。

词条最终落到**一个真实的 stat key** 上，不是「效果=0 的皮肤」。

| 槽 | 可 roll 的目标属性 |
|---|---|
| 武器 | `attackPct`、`critRate`、`comboRate`、`counterRate`、`stunRate`、`dodgeResist`（命中映射） |
| 防具 | `defensePct`、`healthPct`、`dodgeRate`、`critResist`、`comboResist`、`counterResist` |
| 头饰 | `healthPct`、`defensePct`、`stunResist`、`dodgeResist`、`vampireResist` |

| 法宝 | `healthPct`、`attackPct`、`defensePct`、`counterRate`、`comboRate`、`finalDamageReduce` |

> `attackPct` / `defensePct` / `healthPct` / `speedPct` 是**新增的百分比属性**（旧装备只有绝对值 + 几率类）。写代码时要在 `stats.js` 补中文名，并在合并属性时作为乘区结算。

### 6.5 去重规则（本次拍板）

- **按最终目标属性去重**：一件装备不会出现两个 `attackPct`。
- 因此【锋锐】和【极锋锐】同件时只保留一条（roll 时先撞到哪条算哪条，第二条重抽）。
- **复合类词条占 1 个词条位、影响 2 个目标属性**；去重时两个属性都算占用。
- 重抽上限 10 次；仍撞车则降为同池未占用的属性；池已尽则本条作废（该件少一条词条）。

## 十、桂冈境界成长

```
桂冈四属性 = baseAttributes × (1 + 内功层数 × 0.12) + 装备面板 + 炼体加成
```

**内功层数 = `realm.js` 的扁平索引 1..18**（1~10 练气、11~14 筑基、15~18 结丹），
不是「练气几层」。原文「筑基初期 ×2.44」是把它当成第 12 层算错了，
**筑基初期 = 第 11 层 = ×2.32**（×2.44 是筑基中期）。

| 境界 | 层数 | 乘数 | 攻击（base 10） | 生命（base 100） |
|---|---:|---:|---:|---:|
| 练气一层 | 1 | ×1.12 | 11.2 | 112 |
| 练气三层 | 3 | ×1.36 | 13.6 | 136 |
| 练气六层 | 6 | ×1.72 | 17.2 | 172 |
| 练气八层 | 8 | ×1.96 | 19.6 | 196 |
| 练气十层 | 10 | ×2.20 | 22.0 | 220 |
| **筑基初期** | **11** | **×2.32** | 23.2 | 232 |
| 筑基圆满 | 14 | ×2.68 | 26.8 | 268 |
| 结丹初期 | 15 | ×2.80 | 28.0 | 280 |
| 结丹圆满 | 18 | ×3.16 | 31.6 | 316 |

**`+ 炼体加成` 的公式**（2026-10-23 补齐，详见《[跨文档缺口补丁 v1.0](../90-历史归档/讨论-2026-10-23/跨文档缺口补丁%20v1.0.md)》§2）：

```
炼体加成·生命 = floor(20 × L外 × (1 + L外/18))
炼体加成·防御 = floor( 2 × L外 × (1 + L外/18))
炼体加成·攻击 = 0   炼体加成·速度 = 0
```

炼体加成由**外功境界等级**派生（沿用现网 `bodyBonus`），不是由炼体修为直接换算；
药浴只负责喂修为，修为 → 外功境界走 `realm.js` 的 `CULTIVATION_CURVE.outer`。
外功与内功两条线**互不前置**，所以 `L外` 和 `L内` 各算各的。

## 十二、一键装备 / 一键卖出

> **代码状态（2026-10-23 P36 第 9 步）**：一键装备 ✅ 已落地（`plugins/autoEquip.js` +
> `inventory.autoEquipAll` + 背包装备页按钮）；一键卖出仍是旧口径，见 §12.2。

### 12.1 评分公式（占位权重，待 §十七 第 8 条验算）

```
基础分（攻） = 攻 × 1.0 + 速度 × 1.5
基础分（防） = 防 × 0.6 + 生命 × 0.15

进攻侧 = 基础分（攻） × (1 + 攻% + 暴击%×1.5 + 连击%×1.3
                              + 反击%×1.0 + 眩晕%×1.0 + 吸血%×0.8)

防御侧 = 基础分（防） × (1 + 防% + 生命% + 闪避%×0.8 + Σ抗性%×0.5
                              + 最终减伤%×1.0)

总分 = 进攻侧 + 防御侧
```

选装规则：
1. 遍历 5 个槽，从背包里选总分最高的一件。
2. 同分按成色（极 > 上 > 中 > 下）。
3. **已锁定（品种锁）的不参与，也不会被替换。**
4. 已装备的非锁定物品，新物品总分更高则替换，换下的回背包。

### 12.1b 子嗣评分 + 分配顺序（✅ 2026-10-23 落地）

《模块二》§15.4 的「自动给桂冈**和所有出战子嗣**穿满」在代码里是这样切的：

**子嗣评分**（与桂冈同一套权重，**只算四条本体属性**）：

```
子嗣分 = 攻 × 1.0 + 速 × 1.5 + 防 × 0.6 + 生命 × 0.15
```

> 暴击 / 连击 / 闪避 / 抗性 / 最终减伤**一分不给** —— 子嗣战斗被简化成「气血 / 战力」
> （《模块二》§15.3），这些词条在子嗣身上**根本不生效**，给分会让一键装备挑出没用的件。
> 所以同一条词条对桂冈是加分项、对子嗣是 0 分，**这是预期行为**。

**分配顺序**（谁先挑）：

1. 桂冈 5 槽先选满；
2. 再按「境界降序 → 出生时间升序 → id 升序」遍历**可出战子嗣**（有灵根 + 练气二层起），
   与 `pickExpeditionChildren` 同一套排序 —— **强的人先挑**；
3. 每人按 攻 → 防 顺序选当前池子里分最高的一件。

**池子规则**：被换下来的旧件（桂冈的和子嗣的都算）**回池**，后面的人还能接着挑；
没人要的最后回背包，**不自动卖**。所以一键装备不会浪费一件好装备。

**只升不降**：候选必须比现有件分更高（同分则成色更高）才换 —— 反复点击不会来回倒腾。

**不参与的人**：陨落 / 已故 / 无灵根 / 未到练气二层的子嗣一律跳过，**身上装备原样留着**。
