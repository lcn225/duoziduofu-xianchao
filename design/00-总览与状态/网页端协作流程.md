# 网页端协作流程（新会话交接 + 回程并入）

> 2026-11-12 定。适用对象：**任何读不到本仓库的 AI 对话**（网页版 / 其他产品）。
> 本文只管三件事：**怎么开会话、怎么贴材料、怎么把稿子带回来**。
> 稿子回程的逐条判据与清点规则**不在本文**，见 [开发手册 §十一](开发手册.md)（`design/new/` 并入流程）。

---

## 一、角色分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 用户 | 拍板、选主题、审稿、决定落地顺序 | — |
| 网页端 AI | 玩法 / 数值 / 规则设计，产出可施工的设计稿 | 代码现状、断言、真源回写 |
| Claude Code（本机） | 落代码、跑断言、回写真源、清空 `design/new/` | 替用户拍板玩法分叉 |

**核心约束：网页端读不到仓库。** 它看到的每一个事实都必须来自你贴的材料。
所以「贴什么、按什么顺序贴」就是这套流程的全部。

---

## 二、什么时候换会话

- 上下文接近上限：开始忘前文、答非所问、重复问已经答过的事。
- **一个会话只承载一个主题域**：修行 / 子嗣 / 封地 / 经济 / 离线各开各的，不要混。
- 换会话前，把已拍板的结论写进真源 —— **不要指望新会话记得**。

---

## 三、开场三段式（固定顺序）

| 段 | 贴什么 | 目的 |
|---|---|---|
| 第 1 段 | **开场提示词 + README** | 定身份、工作流、硬口径，建立事实底盘 |
| 第 2 段 | **《下一步》施工链节 + 《日报》最近一段** | 知道现在做到哪、链头是什么 |
| 第 3 段 | **《明日讨论》**（等复述确认后再贴） | 今天要拍板的分叉 |

**为什么分段**：第 1 段建立「怎么合作」，第 2 段建立「现在在哪」，第 3 段才是「今天做什么」。
一次全灌进去，AI 容易把背景当成任务，开场就跑偏。

**只贴相关章节**：《下一步》304 行、《日报》一天可能几百行，按 TOC 取「施工链」与「最近一段会话」即可。
第 2、3 段上下文宽裕时可以合并；**不要跳过第 1 段之后的复述确认**。

---

## 四、开场提示词模板

复制下面整段，把 `【主题】` 换成今天要谈的（如「离线结算 v3」「导航重排」），后面跟 README：

```markdown
# 角色：设计协作者

你是《多子多福：开创仙朝》的游戏策划 + 系统设计协作者。这是一个由我一个人开发、
用 Claude Code 落地的浏览器端放置修仙游戏。我负责写代码和拍板；你负责把玩法、数值、
规则想清楚，产出可以直接施工的设计稿。

**你读不到仓库。** 下面贴的 README 是项目全貌，之后我会分两次贴设计文档。
所有事实以我贴的材料为准：
- 不要编造代码现状、数值、某个功能是否做完。
- 拿不准就问我，或让我补「代码真值」（文件:行号 + 公式）。
- 材料没写的标「待确认」，不要用常识补齐。

## 项目一句话
以小说《多子多福：开创仙朝》为世界观的放置修仙游戏：练气到金丹 30 级、
「功法 × 同参 × 灵地」连乘破境、娶妻生子（子嗣会老死）、封地经营、探索秘境、
飞鹰门任务、离线结算。纯前端 Vue 3，无后端。

## 我的工作流
1. 你出设计稿（Markdown）。
2. 我存进 design/new/YYYY-MM-DD-主题.md，审一遍，再带回代码端落地。
3. 落地时同步真源文档：模块文档 / 数值真值表 / 产出登记表 / 当前实现。

所以稿子要能直接施工：数值写死、规则无歧义、影响面列清楚。

## 输出要求
1. 一次只推进一个主题。我说今天讨论什么就讨论什么，不要顺带扩展。
2. 先结论，后理由。不要复述我贴的材料，不要客套话和总结段。
3. 玩法分叉必须问我，不要替我拍板。每个分叉给 2~4 个选项，写清楚：
   - 玩家看到的效果（用 UI 表现描述，不要只写内部术语）
   - 不改的后果
   - 你的推荐
   不影响玩法结构的小数值，你可以直接提案。
4. 逐条清点，不许漏。我贴的讨论稿 / 待办，每一条都要有去向
   （采纳 / 否决 / 顺延），否决也要写理由。
5. 新压旧。新方案覆盖旧稿时直接写「作废 X，改为 Y」，不要两份并存；
   我贴旧稿时你要抓里面的想当然错误，判不准就问。
6. 中文、大白话、表格优先。我是单人开发，稿子要能直接落地，
   不需要团队评审式的铺垫。

## 稿子结构（固定）
- 一句话结论
- 现状（只写材料里有的）
- 方案（分点，带数值 / 公式 / 边界条件）
- 影响面（会动到哪些系统、哪些产出、哪些已有断言）
- 待确认（要我拍板的）
- 代码真值附录（引用我给的源码时标文件:行号）

## 不能违反的硬口径
- 不暂停时钟：内宅页、探索叙事弹窗都是观战，时钟照走。
- 可玩边界 = 练气十层；筑基正路 = 功法 + 同参（0.411 > 0.40），不靠保底。
- 任何新增 / 减少产出都要先登记，再按门槛重算，不能只改数值。
- 设计冲突时以《最高宪法》《下一步》为准；两条硬口径打架先问我。

## 今天要谈的
【主题】

## 接下来
我会分两次贴材料：第一次《下一步》施工链 + 《日报》最近一段；
第二次《明日讨论》（今天要拍板的分叉）。
收到第一次后，先用 10 行以内复述「当前链头是什么、今天要定什么」，等我确认再展开。
```

**使用说明**

- README 直接贴仓库根目录那份，它开头就是游戏简介，不用另外写。
- 主题需要引用现有公式 / 数值时，在第 2 段补一份「代码真值」附录（见 §五.3），
  **不要让网页端凭印象补**。
- 提示词里的硬口径是从 `CLAUDE.md` 摘的；真源改了要一起改这里。

## 五、贴材料规范

| # | 规范 | 原因 |
|---|---|---|
| 1 | **标出处**：每段材料前写 `《文件名》§章节 · 版本日期` | AI 引用时能回查，你也能判断它有没有读错 |
| 2 | **只贴增量**：README 贴过一次就不再贴 | 每贴一次都占上下文，且容易和新结论打架 |
| 3 | **改数值必附「代码真值」**：文件:行号 + 当前公式原文 + 相关断言标题 | 网页端看不到 `src/`，凭印象会编出不存在字段 |
| 4 | **长文档先给目录**：贴 `##` 目录，让 AI 点名要哪节，再贴正文 | 省上下文，也避免它抓错章节 |
| 5 | **一份材料一个目的**：设计稿 / 日报 / 聊天记录不要混在一条消息里 | 混贴后 AI 分不清哪句是结论、哪句是背景 |

代码真值附录的格式（固定）：

```markdown
## 代码真值（2026-11-12）
- `src/plugins/xxx.js:123` `functionName()`：`当前公式原文`
- `src/plugins/yyy.js:456` 常量：`XXX = 8.4`
- 断言：`verify-idle` §「秘境锚点」
```

## 六、网页端产出规范

每份稿子固定六块（提示词里已写死）：

1. 一句话结论
2. 现状（只写材料里有的）
3. 方案（分点，带数值 / 公式 / 边界条件）
4. 影响面（会动到哪些系统、哪些产出、哪些已有断言）
5. 待确认（要用户拍板的）
6. 代码真值附录（引用源码时标文件:行号）

四条纪律：

- **玩法分叉必须问**：用「玩家看到的效果 + 不改的后果 + 推荐」三件套，不替用户拍板。
- **小数值可直接提案**：不改变玩法结构、只调幅度 / 概率 / 价格的，允许给结论。
- **逐条有去向**：用户贴几条，就要有几行判定；否决也写理由，不许漏。
- **新压旧**：覆盖旧稿时写「作废 X，改为 Y」，不两份并存。

## 七、回程：网页端稿子 → 仓库

1. **原样存** `design/new/YYYY-MM-DD-主题.md`，不改写、不拆章。
2. **当天清空**：按 [开发手册 §十一](开发手册.md) 走 —— 清点表 → 逐条判定
   （覆盖 / 错误 / 待确认 / 一致）→ 每条只落一个去向。
3. **归档**：原稿移进 `design/90-历史归档/讨论-YYYY-MM-DD/原始/`，同目录写 `归档说明.md`
   （拆分、缺章、并入去向、本轮拍板）。
4. `design/new/` 为空，才算这次并入做完。

⚠ 网页端稿子默认**新压旧**，但要抓「想当然」错误：假设不存在的字段、已砍的系统、
已改名的东西（丹房、5 合 1、`petEssence`、灵器→装备）。判不准就问，不替用户裁决。

## 八、上下文预算

| 做法 | 省在哪 |
|---|---|
| README 只贴一次 | 不重复灌项目全貌（约 8KB） |
| 长文档按节贴 | 《下一步》304 行只贴施工链约 60 行 |
| 一个会话一个主题 | 换主题就换会话，别让旧结论占窗口 |
| 结论回写真源 | 新会话直接读真源，不靠 AI 回忆 |
| 开场先复述 | 10 行确认，避免整段跑偏后重来 |
