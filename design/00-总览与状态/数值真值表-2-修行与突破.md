## 2.1 变量

| 变量 | 含义 | 取值 / 来源 | 状态 |
|---|---|---|---:|
| `Base_Exp(L)` | 基础修为上限 | §1.2，22 级 | ✅ |
| `K(L)` | 配平系数 | §2.4 反推，**0.907~2.209**（元婴沿用 L17 = 1.435） | ✅（元婴待定） |
| `Child` | 子嗣修炼加成 | 0 起，无上限 | ✅ |
| `Other` | 其他速度加成 | 散功 `1+0.1×n`、丹药等 | ✅ |
| `Fit` | 综合契合度 | 功法 × 同参 × 灵地 | ✅ |
| `Land` | 灵地基础产出 | 20~140，§1.4（5 阶灵地） | ✅ |
| `Fate_Coef` | 本命数量系数 | 单 1.0 / 双单根 0.9 / 双双根 0.8 / 三 0.7 / 四+ 0.6 | ✅ |
| `spiritRate` | 突破倍率 | `1.1^(L-1)` | ✅ |
| `Bandwidth` | 行功带宽 | 恒 1.0（占位） | 🟡 |
| `k(L)` | 打坐转化率 | `0.1 × 0.8^(L-1) × (1+0.3×luck) × Shrine` | ✅ |
| `luck` | 幸运 | 默认 1 → 暴击期望 ×1.3 | ✅ |
| `Shrine` | 英烈祠 | `1 + min(0.01×牌位, 0.10)` | ✅ |

**打坐转化率的来源**（`cultivationMath.js`）：
每次打坐消耗 `floor(10 × 1.5^(L-1))` 灵力，获得 `floor(1 × 1.2^(L-1))` 修为，
30%×luck 概率本次翻倍。所以：

```
k(L) = 1.2^(L-1) / 1.5^(L-1) × (1 + 0.3×luck)
     = 0.8^(L-1) × 1.3
```

⚠ 这个 0.8 的指数是**后期变慢的主刹车**：L18 时 0.8^17 = 0.0225，即 1 点修为要 44 点灵力。
它比灵地产出涨得慢，所以后期必须靠 `K` 抬门槛。

## 2.2 公式（本表采用，已修正）

```
① 灵力产出（全天等效，现实秒）
R(L) = Land(L)
     × (0.98 + 0.32 × Fit)
     × Fate_Coef
     × spiritRate
     × Bandwidth
     × (1 + Child)
     × (1 + Other)

② 打坐转化率
k(L) = 0.1 × 0.8^(L-1) × (1 + 0.3×luck) × Shrine

③ 修为产出
e(L) = R(L) × k(L)

④ 实际修为上限
Cap_eff(L) = Base_Exp(L) × K(L) × (1 + Child)

⑤ 突破耗时（现实秒）
Time(L) = Cap_eff / e
        = Base_Exp × K / [Land × (0.98+0.32Fit) × Fate × spiritRate
                          × Bandwidth × (1+Other) × k(L)]
```

> ✅ **2026-10-19 口径已统一**：代码速度项是 `0.98 + 0.32×Fit`（《模块一》§5.1），
> 本表的公式与 §2.4 的 `K` 都已按它重算（K 范围 **0.907~2.209**）。
> 旧版「`0.5 + 1.5×Fit` + 新速度项两套不要混用」的警告作废。
> 算突破时间直接用本表公式 + §2.4 的新 K，不要再拿旧 K。

**⑤ 里没有 `Child`** —— 这就是「子嗣加成被完全吃掉」的数学证明。
子嗣让 `Cap_eff` 和 `R` 同乘 `(1+Child)`，分子分母对消；玩家看到的是**上限和灵力数字都变大**，
但突破时间一格不变。`Other` 只乘在分母，所以它是真的加速。

## 2.3 与原式的对照

| 项 | 你给的原式 | 本表 | 差异 |
|---|---|---|---|
| 上限 | `Base × (1+Child+Other)` | `Base × K × (1+Child)` | `Other` 移出上限；新增 `K` |
| 速度 | `× (1+Child)` | `× (1+Child) × (1+Other)` | `Other` 移入速度 |
| 子嗣净效果 | 略微拖慢（`1+O/(1+C)`） | **精确为 0** | 修正 |
| 其他加成 | 拖慢 | 加速 | 修正 |
| 节奏校准 | 无 | `K(L)` 由宪法第二章反推 | 新增 |

**如果坚持原式**，请把「其他加成」理解为**惩罚项**（例如心魔、伤势），并在 UI 上写成负加成；
否则不要用它。

## 2.4 配平系数 K（本表的核心新增）

**定义：**

```
K(L) = 目标本层耗时(L) / 裸公式耗时(L)
裸公式耗时(L) = Base_Exp(L) / [Land × (0.98+0.32Fit) × Fate × spiritRate × k(L)]
```

`K` **不是拍脑袋的常数**，是宪法第二章的逐节点时间表反推出来的。流程：

```
① 取 8 个锚点：L2 60s、L3 180s、L6 1080s、L10 6000s、
             L11 10800s、L14 43200s、L15 86400s、L18 216000s
             （2026-10-29 P55-d：L18 由 259200s = 72h 收窄到 **216000s = 60h**，见 §1.2）
② 未列出的中间级用几何插值补全（例：L3~L6 三级，公比 (1080/180)^(1/3)=1.817）
③ K = 目标 / 裸公式
④ 有效上限 = Base × K，写进 realm.js（或单独一张 PACE 表）
```

## 2.4d 外功 PACE（2026-11-01 B9-c，**现行口径**）

**口径（`npm run sim:body`，真源 `scripts/sim-body.mjs`）**

```
OUTER_PACE(L) = 5 轮/天 × gain(L) × 目标天数(L)
目标天数(L)   = 内功目标秒数(L)（§2.4c） ÷ 每游戏天的现实秒数(L)
每游戏天的现实秒数：练气 96 / 筑基后 4（P55-b 的 24×）
```

1. **外功每一级的现实耗时 = 内功同级** —— 这就是「外功套用内功时间表」的落地形态。
2. **锻骨 / 洗髓必须放大 14~33 倍，唯一原因是 24×**：同样的「5 轮/游戏天」到筑基后只占
   **4 现实秒**，外功按现实时间看产出快 24 倍，门槛不跟着抬就变成「几分钟走完整段」。
3. **`gain` 不决定节奏**：门槛里自带 `5 × gain`，改 gain 只是把进度条数字一起放缩
   （每轮仍是 `+gain`，填满时间不变）。真正的节奏旋钮是 `OUTER_PACE`。

**现状 vs 目标（`npm run sim:body` 输出，24× 已计入）**

换成代码的 `0.98 + 0.32×Fit`：

```
K_new = K_old × (0.98 + 0.32×Fit) / (0.5 + 1.5×Fit)
```

⚠ **方向别写反**：新速度项在低 Fit 时更快（L1: 0.62 → 1.0056），所以 K 要**调高**；
在高 Fit 时更慢（L10: 1.22 → 1.1336），K 要**调低**。写成倒数会让 L1 从 1.255 掉到 0.477。
**L19~22 没有时间锚点**，1.435 只是沿用 L17 的占位，标 ❓，不是定稿。

⚠ **2026-10-29 P55-d：L16~L18 的 K 未重算。** 结丹段锚点收窄了（见 §1.2），
这三格的 `K` 理论上要按比例下调（约 ×0.925 / ×0.802 / ×0.833），但 `K` **尚未进代码**、
`PACE` 也无单位对齐 ⇒ 等 PACE 落地时连同 `§2.5` 一起整表重跑。**别把表中的 L16~L18 当定稿。**

⚠ `K` 不必单调。有效上限 `Base × K` 是单调的（见 2.5 表），这才是玩家看到的门槛。
⚠ **L9 / L10 的 K < 1**：按 5 阶灵地的基准路线，裸公式已经比宪法目标**略慢**，
需要把有效上限压到 `Base_Exp` 以下（L9 5,079 < 5,600；L10 8,067 < 8,500）。有效上限仍单调，属预期；
实装时直接 `有效上限 = round(Base × K)`，不要再额外夹 `≥ Base`。
⚠ `K` 是**按基准路线**（默认灵地/Fit、**0 熟练度**）算的。如果改基准路线，K 必须重算。
⚠ 实际「熟练度」已并入心法等级加成（P56-a，2026-10-31），经 `0.98+0.32Fit` 的窄斜率后约带来

> 本表是设计配平表，不要把「K 已重算」说成「代码已修」；K 进代码需先对齐
> 「设计层现实秒」与「代码层游戏小时 + 9.6 补偿」的单位。

**B7（2026-10-28）复核**：同参换成标签连续值后，基准路线各段的 `Fit` 变了，
