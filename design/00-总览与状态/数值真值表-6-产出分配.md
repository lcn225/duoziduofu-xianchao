## 6.2 镇守产出（每游戏天）

**练功产出**（默认 10 轮，`R` 见 Sheet 2）：

```
每日灵力 = 10 × 9.6 × R(L) = 96 × R(L)
每日修为 = 每日灵力 × k(L) = 96 × e(L)
```

⚠ 每日修为在中后期**不升反降**，因为 `k` 的 0.8 指数比 `R` 涨得快。

**战败截断后的实际值（重要）**

同境界每事件战败率 `h = 15% × 30% = 4.5%`；战败即停 + 养伤 **半天（12 游戏小时）**
（2026-10-20 用户反馈后从 1 天下调；属**收益增加**）：

```text
E[事件数/轮] = (1 - 0.955^12) / 0.045 ≈ 9.43
周期 = 9.43×2h + 12h = 30.86 游戏小时
长期 = 9.43 × 24 / 30.86 ≈ 7.33 事件/天
高 1 境（90%）：11.03×24 / (11.03×2 + 12) ≈ 7.77 事件/天
```

> 这是设计选择：同级新图有风险，退一张图才是稳定刷。

**推导（T1 示例）**

```text
空包 .35×0 + 采植 .20×1.5 + 采材 .10×1.5 + 拾遗 .10×3.5
   + 战斗 .15×(0.70×3.5) + 奇遇 .05×4 + 叙事 .05×2
```

## 6.7 预期日产出（调试对照 · P15.6 已落地）

> 调试日志（GM 页 →「调试日志」页签）每天用这张表算一次「计划值」。
> **计划值不是静态数字**：练功小时由当天勾选的巡视 / 炼体 / 百艺决定，

**时间结构**（与 §4.1 / §4.3 同源；代码里是 `loopStartOf` / `offWorkOf`）：

```
L = 18:00 − max(08:00, 06:00 + S)      // S = 巡视小时；默认 2 → L=10；S=5 → L=7
C = 1 + B + 0.75×N                     // 一个周期：练功 1h + 炼体 B×1h + N 个百艺×45m
k = floor(L / C)，r = L − k×C
任务 i 的轮次 = k + (r ≥ 队列前 i 项时长之和 ? 1 : 0)
```

| 配置 | 练功 | 炼体 | 每种百艺 |
|---|---:|---:|---:|
| 无勾选 | 10 | 0 | 0 |
| 炼器 | 6 | 0 | 5 |
| 炼体 | 5 | 5 | 0 |
| 炼体 + 炼器 | 4 | 3 | 3 |
| 两种百艺 | 4 | 0 | 4 |

**产出计划**：

```
计划灵力 = 日初 spiritPerGameHour × 计划练功轮次
计划修为 = min(60 × 计划练功轮次, 计划灵力 / 打坐成本) × 每次修为 × (1 + 0.3×幸运)
计划体魄 = 同上，用外功等级与计划炼体轮次；内外功按各自可打坐次数分配灵力
计划体力 = S×10 + 练功轮次×3 + 炼体轮次×15 + Σ(百艺轮次×0.75×该艺体力/h)
计划熟练度 = 计划练功小时 / 50 / 100     // 1% / 50 游戏小时 → 0.0002/小时
```

> ✅ **2026-10-19 起代码已按 1%/50h 返工**（`0.0002/小时`），日志上的「熟练度达成率」
> 应与计划一致（约 100%）。旧版稳定显示 50% 的「设计 vs 代码」差已关闭。
> 调试日志仍保留 `codeHoursPerPercent` / `designHoursPerPercent` 两个字段，方便以后再出现分叉时一眼看出来。
>
> ⚠ §6.2 的「每日灵力 / 每日修为」是**设计目标**（Sheet 2 的 `R(L) / e(L)` 口径），
> 与当前代码的 `spiritPerGameHour × 练功小时` 不是同一套数。调试日志一律按**代码现值**算计划，
> 避免日志自己变成第二个真源 —— 两边对不上是已知的返工项，不是日志算错。
>
> ⚠ **体力计划只算白天**（巡视 + 练功 + 炼体 + 百艺），不含晚间互动 ——
> 互动次数本身取决于剩余体力，算进去会变成循环定义。实际值包含互动消耗，所以会略高于计划。
>

> 看几天趋势，不要拿单日 90% / 110% 当异常。
