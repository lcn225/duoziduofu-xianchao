一、核心设计哲学（四条铁律）

1. 本命决定灵根，不是灵根决定本命。 修士因为本命是【火鸦】才有兽灵根，不是因为有了火灵根才去抓火鸦。

2. 同参是用途，不是分类。 数据库里没有“同参表”。一件物品能不能当同参，取决于它的 series 与本命的匹配度。

3. 底材与实例分离。 池子里只存底材（模板，无成色）；掉落后才生成实例（具体一件，有下/中/上/极品成色 + 战斗面板）。

4. 品阶封顶是硬钳制，不乘进契合度。 同参契合只由接近度决定；品阶封顶只决定“这件同参能发挥到第几阶的面板/词条”。一阶本命拿五阶同参，契合度仍按接近度算，但面板按一阶算。

二、四池分类

category 定位 来源 能否当同参 能否当子嗣本命

灵器 法宝、法器、饰品 抽奖 / 秘境 / 炼器 ✅ ✅

灵兽 灵宠、妖兽 抽奖 / 秘境 / 捕捉 ✅ ✅

灵植 活体植株（草/花/树/藤） 探索 / 封地药圃 ✅ ✅

灵材 采集物、炼器材料 探索 / 封地矿场 / 秘境 ✅ ✅

灵植 vs 灵材的边界：整株活体 → 灵植（type = 草/花/树/藤）；摘下来的部位 → 灵材（type = 花/果/叶/金属/宝晶/灵土/灵木/骨材）。

例：一株灵桃树 = 灵植（type 树）；它结的桃 = 灵材（type 果）。同一株植物，整株和部位分属两池，不重复录入。

三、底材字段规范

3.1 字段表（池子里只存这 8 个）

字段 类型 必填 说明

id string ✅ 全局唯一。格式 {type英文}_{系列名}_{阶数}，如 sword_xuanbing_1

name string ✅ 物品名。同 series 内不重复（正主判定靠它）

category string ✅ 灵器 / 灵兽 / 灵植 / 灵材

type string ✅ 见 §3.2 枚举

series string ✅ 系列标签，见 §3.3

tier int ✅ 整数 1~5，纯阶数，不带成色

fateElement string ✅ 单值，枚举 金/木/水/火/土/兽/器

description string ⬜ 风味文本，不影响判定

已删除字段：quality（成色）、displayName（派生显示名）。理由：一阶渡厄剑应同时有下/中/上/极品，成色在掉落时 roll，不在池子里定死。

3.3 series 命名规则

· 格式：{type英文}_{系列名}，如 sword_xuanbing / boar_wu / herb_huichun / ore_xuantie

· 同参判定时先比 category，再比 series —— 跨池同名 series 不会撞车

四、底材 vs 实例：两层模型

这是删 quality 后的核心结构。不理解这一层，后面的掉落、装备、同参全错。

4.1 底材（池子里）

· 只有 8 个字段，无成色、无战斗面板

· 用途：同参判定、子嗣本命抽取、掉落模板、显示名的基础

· 例：{ id: "sword_xuanbing_1", name: "寒冰刺", tier: 1, ... }

4.2 实例（掉落后进背包/装备）

```jsonc
{

"instanceId": "inst_8f3a2b", // 全局唯一实例 id

"baseId": "sword_xuanbing_1", // 指回底材

"quality": "极", // 下/中/上/极，掉落时 roll

"stats": { ... }, // generateEquipmentStats(type, tier, quality) 生成

"displayName": "一阶极品【寒冰刺】", // 运行时拼接

"equippedBy": null, // 装备者 id（桂冈/子嗣/无）

"location": "inventory" // inventory / equipped / petSlot / ...

}
```

4.3 两层模型的分工

操作 读哪层 说明

同参判定 底材 只看 category / series / name，不看成色

子嗣本命抽取 底材 抽到底材快照，无成色

掉落生成 底材 → 实例 底材 + roll 成色 + 生成 stats

装备战斗面板 实例 读 stats

显示名 实例 {tier}阶{quality}品【{name}】；底材预览时用 {tier}阶【{name}】

一句话：底材是“寒冰刺这个模板”，实例是“我背包里那把一阶极品寒冰刺”。同参和本命永远只看模板，战斗永远看实例。

五、本命系统

5.1 桂冈本命（固定，小说设定）

本命 category series tier fateElement 灵根

刃背乌鬣猪 灵兽 boar_wu 4 兽 兽灵根

饕餮纹暗金镶青金石玉牌 灵器 shield_taotie 4 器 器灵根

· 双本命双灵根 → 数量系数 0.8×（模块一 §1.3）

· 品阶封顶 = 4：桂冈的同参最高发挥到四阶（五阶同参给桂冈，只算四阶面板）

· 这两件必须在灵兽池 / 灵器池里存在，id 待填池时确定

5.2 子嗣本命（出生抽，1~5 件）

**本命数量分布**（1~5 件）：

| 本命数量 | 概率 |
|---|---:|
| 单本命 | 3% |
| 双本命 | 12% |
| 三本命 | 10% |
| 四本命 | 15% |
| 五本命 | 60% |

**灵根 = 本命 `fateElement` 的去重集合**，灵根数量 = 去重后的大小。
**本命数量 ≠ 灵根数量**：3 件木系本命 = 单木灵根；5 件不同属性 = 五灵根。

**实际灵根数量分布**（7 类灵气、允许重复；20 万次实测）：

| 灵根数量 | 概率 | 根系数 | 本命阶数上限 | 灵根质量 |
|---|---:|---:|---|---|
| 单灵根 | **4.7%** | **0.24** | 1–5 阶 | 最好 |
| 双灵根 | **17.1%** | **0.12** | 1–4 阶 | 好 |
| 三灵根 | **30.2%** | **0.06** | 1–2 阶 | 中 |
| 四灵根 | **36.6%** | **0.03** | 1–2 阶 | 差 |
| 五灵根 | **11.4%** | **0.012** | **1 阶** | 最差 |

> **根系数**以 `plugins/innerCourt.js` 的 `TUNING.bonus.rootCountCoef` 为准。
> 2026-10-19 允许灵气重复后，灵根分布从 3/12/10/15/60 变成约 5/17/30/37/11，
> 本表整体乘 0.6 保持总期望（旧 0.02/0.05/0.10/0.20/0.40 → 新值）。
> 旧表写的 1.0 / 0.8 / 0.7 / 0.6 / 0.6 是另一套口径，已作废。

· 只看灵根数量，数量决定品质。单灵根最好、五灵根最差。
· **本命按物品池的 1–5 阶命名**：1 阶灵兽就叫「1 阶灵兽」，不再叫凡兽；
  灵器 / 灵植 / 灵材同理。旧词「凡兽 / 灵兽 / 王级变异兽 / 神兽·仙器」作废。

· 每件本命从四池随机抽底材，只存底材快照，不进背包：

```jsonc
// 子嗣身上的本命字段

fates: [

{ "baseId": "boar_wu_1", "name": "乌鬣猪", "category": "灵兽",

"series": "boar_wu", "tier": 1, "fateElement": "兽" },

{ "baseId": "sword_xuanbing_1", "name": "寒冰刺", "category": "灵器",

"series": "sword_xuanbing", "tier": 1, "fateElement": "器" }

]
```

· 子嗣灵根 = 本命 fateElement 的**去重集合**。3 件木系本命 = 单木灵根；
  抽到 5 件不同属性 = 五灵根；灵根数量可以小于本命数量。

· **子嗣本命有品阶上限**（2026-10-19 定）：**灵根数量**决定 `maxTier` ——
  **5→1、4/3→2、2→4、1→5**。这是**上限，不是保底**：单灵根也可以抽到 1 阶，
  五灵根只能抽到 1 阶。子嗣同参槽的封顶规则等子嗣修炼系统落地再定。
  代码真源：`innerCourt.js` 的 `FATE_TIER_CAP` / `fateTierCapOf`；
  `items.js` 的 `rollFateSet` / `clampFateTiers`（先定本命，再按灵根数压阶）。

· 不存 quality：本命是底材快照，成色与本命无关。

5.3 抽本命算法（伪代码）

```js
function rollOffspringFates(pools) {

// ① 先定本命数量（不是灵根数量）
const fateCount = weightedPick({ 1: 0.03, 2: 0.12, 3: 0.10, 4: 0.15, 5: 0.60 })

const fates = []

const usedSeries = new Set()

while (fates.length < fateCount) {

const pool = randomPoolOf(pools) // 四池均匀

const item = randomItemOf(pool) // 灵气可重复；tier 暂不设限

if (usedSeries.has(`${item.category}:${item.series}`)) continue // 同系列不重复

fates.push(snapshot(item)) // 底材快照

usedSeries.add(`${item.category}:${item.series}`)

}

// ② 灵根 = 本命属性去重；3 件木系本命 = 单木灵根
const roots = [...new Set(fates.map(f => f.fateElement))]

// ③ 再按灵根数压阶（上限，不是保底）
const maxTier = { 5: 1, 4: 2, 3: 2, 2: 4, 1: 5 }[roots.length]

return clampTiers(fates, maxTier)

}
```

randomItemOf 的 tier 权重待定。**tier 现在只作为「可抽范围」的上限（§5.2），不直接进加成公式**：
同一灵根数量下，抽到 1 阶还是 2 阶本命，加成相同（加成只看灵根数量、本命关系、词条）。
上限内仍按均匀抽；以后要按境界加权再接。

六、同参系统

> **2026-10-19 修正**：本节原文写「五档」，是网页端的误记；**维持六档**。
> 真源见 [《模块一》§4.3](../10-模块设计/模块一-修行与突破.md)。

### 6.1 六档亲和度

| 档 | 系数 | 判定 |
|---|---:|---|
| 正主 | 1.0 | `name` 完全相同 |
| 准正主 | 0.8 | 同 category + 同 series + 名字近似 |
| 同系列 | 0.6 | 同 category + 同 series，名字不近似 |
| 近类型 | 0.4 | 同 category，type/kind 相近但 series 不同 |
| 同类型 | 0.25 | 同 category，type 相同但 series 不同 |
| 无关 | 0.1 | 其余 |

> 现有代码：开局五件同参硬编为「近类型 0.4」，所以开局 `0.20 × 0.40 × 1.00 = 0.08` 成立；
> **不要按五档把它改成 0.25**，否则第一门槛直接断。

### 6.2 同参契合公式（A 硬钳制）

```
同参契合 = 接近度系数        // 只由六档决定，不乘品阶
有效品阶 = min(同参.tier, 本命.tier)  // 硬钳制，用于面板/词条
```

- 接近度系数直接进综合契合度（模块一 §4.3 的六档）。
- 有效品阶**不乘进契合度**，只决定这件同参的「实际发挥阶数」：五阶同参给四阶本命，契合度仍按接近度算，但面板按四阶算。
- 这样模块一的现有数学（开局 0.08 / 吕氏 0.152 / 六层 0.24→0.27 / 九层 0.48 / 筑基 0.56 / 结丹 0.80）全部不动。

### 6.3 判定伪代码

```js
function affinityOf(item, master) {
  // master = { category, series, name, tier }
  if (item.name === master.name) return { tier: '正主', coef: 1.0 }
  if (item.category === master.category && item.series === master.series) {
    if (isNearName(item.name, master.name)) return { tier: '准正主', coef: 0.8 }
    return { tier: '同系列', coef: 0.6 }
  }
  if (item.category === master.category && isNearKind(item.kind, master.kind)) {
    return { tier: '近类型', coef: 0.4 }
  }
  if (item.category === master.category) return { tier: '同类型', coef: 0.25 }
  return { tier: '无关', coef: 0.1 }
}
```

item 读的是底材（或实例的 `baseId` 反查），不读实例的 stats/quality。
