## 六、附：练气三层 54.4% —— 公式没错，但过槛方式违背宪法

> ✅ **当日晚已解决（P13.4，commit `2453b50`）**：连乘重构 + 吕氏 `baseFit 0.38`，
> `0.38×0.40×1.00=0.152` 过三层，不再需要熬熟练度。下面保留当时的分析。

换《元氏修命经》后：
`54.4% = 24.5%×0.5 + 100%×0.35 + 47.4%×0.15`

- 元氏品阶分 40%，熟练度约 7.4%，合计 47.4%；
- 综合 = `0.35 + 0.1225 + 0.0711` = **54.36%**，门槛 55% —— 公式没错。
- 设计路径是「元氏 + 熟练度 **12%**」：`0.5325 + 0.018 = 55.05%`，只高出 0.05 个百分点；
  还差约 4.3% 熟练度 ≈ **427 游戏小时练功 ≈ 70 现实分钟**。

**但这不是可以接受的「设计如此」**：
- 宪法第二章要求练气三层在 **3 现实分钟**内到；现在慢 20 倍以上。
- 宪法第三章要求第一门槛的动作是「**换功法**」，「熬熟练度」是**筑基门槛**的事。
- 根因是《兽器双修经》（换上去 0 熟练度即可过）**没有任何获取途径**，玩家只能退化成挂机。

已记入《下一步》**P13.4**，列为设计检讨：优先方案 A —— 练气二层圆满时补一条一次性获取
《兽器双修经》的途径，把动作还给「换功法」；拍板前不改数值。

## 十四、睡觉改成加速播放（✅ 已完成）

**问题**：睡觉原先由 `sleepToDawn()` 用 `skipTo()` 瞬间跳到次日 06:00，左侧睡觉动画与读条根本看不见。

**改法**：
- `gameClock` 新增 `setTimeScale()` / `setAdvanceLimit()` / `clearTimeScale()`（模块闭包）；
  `advance()` 按 `timeScale` 放大游戏时间，并用 `advanceLimit` 防止后台 5 秒 tick 冲过天亮。
- 进入 `sleep` 时 `startSleepFastForward()`：倍率 = 剩余睡眠 /（目标现实秒 × 900），
  目标现实秒取 `TUNING.sleep.fastForwardSeconds`（默认 **3 秒 ≈ 一轮炼器**）。
- 睡眠仍由 `stepDay` 按正常 tick 切片结算（体力回满、精力 +5/h、换日、流水），
  没有第二套计时器；`skipTo` 不再参与睡觉。
- 离开睡觉 / 离开镇守（`idle.switchIdleMode`）/ `resetDayLoop()` 都会 `stopSleepFastForward()`，
  防止把探索的时间一起加速。
- 「当前任务」标签显示「睡觉（加速中）」，进度条按 tick 更新。

**实机验证**：9 小时睡眠倍率 12，3 个 tick 推进到 06:00（33% → 67% → 换日），
结束后倍率回 1、精力 65→100、体力回满；左侧睡觉 WebP 正常播放，console 零报错。

**验证**：`npm run verify` 553/553；`vite build` 通过。
