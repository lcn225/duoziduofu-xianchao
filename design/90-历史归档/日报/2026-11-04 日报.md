## 三、B15-c #3 / #4 落地（飞鹰门窄屏 + 现实秒倒计时）

**范围**

- 用户 2026-11-04 真机反馈两条，登记在 B15-c（原判「填缝」），本次提前做掉：
  #3 手机上选完驻守子嗣后「接取」按钮看不见；#4 任务页的日期 / 倒计时不动。

**根因（两条都不是「没写」，是写错了口径）**

| # | 根因 | 为什么之前看不出来 |
|---:|---|---|
| 3 | `.task-row` 横向排 + `.task-actions { flex: none }`，选完子嗣后 `n-select` 的标签把选择器撑宽，按钮被 `.zone { overflow: hidden }` 裁掉 | 桌面宽度够，选择器从没撑到临界 |
| 4 | 倒计时走 `formatDuration`（**四舍五入到分钟**），而飞鹰门全按现实秒记账：一游戏天 96 秒、一周 672 秒、一月 2,880 秒 | 96 秒的任务全程只显示「2 分」，一周的刷新整整一分钟才动一格 ⇒ 看起来是「静止」 |

**落地内容**

- `src/plugins/dayDate.js`：新增 **`formatRealCountdown`**（现实秒 → `1:36` / `11:12` / `48:00`，跨小时 `1:02:03`），
  与游戏内的 `formatDuration`（分钟档）/ `formatCountdown`（15 分档）**并列第三个口径**，注释里写明各自适用面。
- `src/views/Faction.vue`：任务剩余 / 周刷新 / 月刷新 / 老九到货**四处倒计时**全部改走 `formatRealCountdown`；
  驻扎选择器从内联 `style="min-width:200px"` 改成 `.garrison-select` 类；
  新增 `@media (max-width: 720px)`：`.zone` 收边距、`.task-row` 改上下排、`.task-actions` 铺满换行、选择器 `width:100%`。
- `scripts/verify-dayloop.mjs`：+8 条 `formatRealCountdown` 断言（含「96 秒在 `formatDuration` 里只剩 2 分」这条对照）。

**口径**

- **飞鹰门的时间轴不变**：仍是现实秒（96 秒/游戏天），本次只改显示粒度，不碰 `faction.realSeconds` 与任何结算。
- 窄屏断点取 **720px**，与 `Estate.vue` / `Day.vue` / `Exploration.vue` 一致；`.garrison-select` 是桌面定宽 + 窄屏铺满。
- **内联 `min-width` 不能写回模板** —— 内联样式赢不过媒体查询，写回去窄屏就又裁了（代码里已留注释）。
- 不触发任何数值 / 产出重算。

**已知边界**

- 480~720px 之间（平板竖屏）选择器也是 100% 宽，比桌面松一点，属可接受。
- 倒计时精确到秒后，数字每格宽度会变；未加 `tabular-nums`，若有跳动感再说。
