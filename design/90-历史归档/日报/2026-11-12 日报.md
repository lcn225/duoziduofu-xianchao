## 二、离线秘境口径拍板：改成扫荡（v2 → v3）

用户先问「难道离线秘境是默认打新层？」，核对代码后事实是**是的**：

- `settleOfflineSecretRealm` 续跑存档里那趟 run，逐段推新层、逐趟写首破（`offline.js:330-431`，`:407`）。
- 扫荡（`startSecretRealmSweep`）是**在线**按钮，且 `secretRealm.js:567` 直接拦
  `if (this.idleMode !== MODES.GARRISON) return { ok: false, reason: '请先回镇守' }`，
  不写首破、不给 50 层首杀（`:564-587`）。

用户拍板**改成扫荡口径**。稿子里改写步骤 4.2 并列出连带口径：

| 变化 | 说明 |
|---|---|
| 离线秘境 = 反复扫荡 | 不续跑、不推新层、不写首破、不给 50 层首杀、不消耗消耗品、不吃 buff |
| 每趟成本 | `sweepLoot(sweepLimitOf(...))` + `timeCostDaysOf(cap)` 天；N 天扫 `floor(N ÷ 每趟天数)` 趟，余数不结算 |
| 精度 | 逐趟掷骰即可（上限约 6,048 趟），**秘境线零精度损失**，不需要期望值 |
| 「唯一暂停点 = 子嗣陨落」 | 在秘境离线模式**不再触发**（扫荡没有战斗）—— CLAUDE.md 硬口径要加例外 |
| 首破 / 50 层首杀 | **只能在线拿到**，产出登记表秘境相关行要改 |
| 下线时进行中的 run | **冻结**，上线后原样继续（开发组默认口径） |
| 在线扫荡要求镇守 vs 离线秘境扫荡 | 不对称，写成《模块九》的特殊口径，不改在线限制 |

`cap = 0`（一个 Boss 都没通）⇒ 离线秘境不产出、只推进时间。

**待确认表已清空**：㉓㉔㉕㉖㉗ 全部结案；㉕（秘境真档）与 ㉗（断言写法）判定为**不需要用户拍板**。
