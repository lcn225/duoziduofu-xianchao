## 四、线上故障「卡在离线结算」：已定位并修复（第 3 段）

**用户反馈（第 2 段收尾时）**：网页打不开，卡在离线结算。第 3 段用真档
（金丹十层 / 1,436 子嗣 / 1,338 条背包 / 4.7MB 密文）复现：**不是死循环，是慢**。

### 1. 根因（读档 191~214 秒，其中离线结算 206 秒）

| 环节 | 耗时 | 原因 |
|---|---|---|
| `gainInto` | **119 秒** | 每掉一件东西线性扫全背包 1,338 条找可合并堆；1,500 天家族工作天天掉 |
| `advanceInnerCourtDay` | 37 秒 | 每天扫全族：修炼 / 家族工作 / 繁育 / 寿终 / 历练 |
| 药浴池逐日转换 | 26 秒 | 每次转换都对 4,512 件池内存量重排一遍 |
| 桂冈日常循环 | 14 秒 | 逐日 24 小时状态机，未动 |

### 2. 修复（提交 `d40b7a2`）

1. **`gainInto` 堆叠索引**（精确优化）：WeakMap「堆叠键 → 下标」，数组被 `splice` /
   同长度替换时靠键校验自愈。结果完全不变，单项 **119 → 1.3 秒**。
2. **粗颗粒度块结算**（用户拍板「不需要那么精确，用粗颗粒度换速度」）：
   `OFFLINE_TUNING.blockDays` = 练气 **1** / 筑基 **7** / 金丹 **30** 游戏天。
   内宅日结、子嗣修炼、家族工作、历练、药浴池按块结算、线性产出乘块长；
   封地与桂冈日常仍逐日。镇守 / 探索 / 秘境三条线统一走 `settleOfflineBlock`。
   有意近似（写进代码注释与《模块九》§3.5）：诞生/寿终按**块末**判定（最多晚一个块长）、
   繁育按 `1−(1−p)^days` 折算、药浴池块末转换一次。

**结果：读档 214 → 14.8 秒（离线 206 → 11.7 秒）。**

## 五、B1 R34 聚合引擎：上限抬到目标态（第 4 段）

用户拍板「一次性到位」（离线聚合只做离线，在线 77ms/tick 不动），并把
「R34 ⇐ B17-b」的依赖**收窄**为「金丹周引擎那一半 ⇐ B17-b」—— 离线聚合与周引擎无关。

### 1. 做法

1. **日常循环块化**：块内第一天完整跑 `advanceDayLoop`，产出记成「一天模板」
   （练功秒数 / 修为 / 灵兽 xp / 炼体轮 / 百艺轮 / 互动人数）；
   其余天走 `applyOfflineDayTemplate` 逐天重放，**材料与药力照常扣、突破即停**。
2. **上限抬到目标态**：`maxGameDays` 1,500 / 1,500 → **4,320 / 30,240**；`maxWindows` → 32,000。
3. **金丹块长 30 → 180 天**：实测倒推（30 天 136 秒 → 90 天 77 秒 → 180 天 54 秒）。
4. **封地逐日结算去掉每轮的 `normalizeEstate`**（块首一次即可），省约 5 秒。

### 2. 实测（真档金丹十层 / 1,436 子嗣 / 4.7MB）
