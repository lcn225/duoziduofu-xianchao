## 五、合并时发现的问题（这轮的主要产出）

### 1. 课题 A 内部有三套词条体系（同一个文档包）

- 主方案 §五：固定值（锋锐攻 +3%、极坚固防 +6%）+ 极品固定「1 普 + 1 稀 + 1 传」= +19%。
- 附件 2 §三：词条是衍生属性（暴击/连击/闪避），按 tier×品质**区间随机**，品质本身是概率。
- 附件 3 §三：按类别再修正（条件类 ×2、复合类 ×0.6）。

→ 已按优先级合并，主方案 §五 与附件 1 §三 作废。

### 2. 主属性数值两版差约 6 倍

主方案 §4.3 是 8 / 20 / 50 / 120 / 300，附件 1 是 8 / 13 / 21 / 33 / 53。
按前者 T5 飞剑 = 25 + 300 = 325，是旧版 50 的 **6.5 倍**，秘境直接打穿。→ 以附件 1 为准。

### 3. 子嗣装备「乘还是加」自相矛盾

主方案 §7.2 文字说「加算后再乘境界/灵根/本命」，但它自己的公式和附件 1 §5.2 都写「最后加算、不乘」。
→ 定为**不乘**（公式方胜出）。

### 4. 「其余 25 个词条效果 = 0」被附件 3 推翻，但不能简单照搬

附件 3 要求全量映射。但若「效果=0」的词条还能被 roll 出来，极品 3 条全占位会比下品更差，直接破坏「一键装备按总分排序」。
→ 定为：**无战斗映射的词（驯宠/通灵/蓄灵/纳物/祥瑞/镇宅/通神/锁灵）不进装备 roll 池**，只留在标签表里供打标与课题 B 算契合。

### 5. 词表其实是两套，必须合并

《标签清单》「功能特效」31 词 与 附件 3 的 40+ 词只有部分重叠：
清单有 镇魂/养魂/摄魂/凝神/回气/疗伤/驯宠/通灵/蓄灵/纳物/护体/月华/日光/雷火/祥瑞/吞灵/再生/锁灵/镇宅/蓄火/通神；附件 3 有 绝影/破甲/三花/五方揭谛/黑炎凤 等。
→ 方案 §7.2 出了**合并版字典**，每个词同挂「打标用」和「装备 roll 用」两个用途。
**这是课题 A 与课题 B 唯一共用的数据结构，也是 B 的打标工程阻塞项。**

### 6. 平衡结论要改

- 主方案说「最终面板 ≈ 原面板 ×1.2~1.5」，按附件 1 实际算出来是 **×1.4~2.0**（下品 ×1.4~1.7，极品上限 ×2.0）。旧目标作废。
- 「极品最多 +19%」不成立：T1 +18%（巧合接近），T5 上限 **+42%**，期望 **+23.1%**。
- 极品*期望值* ≈ 上品*上限*，这是附件 2「无保底」的刻意结果，已在方案里写明「不是 bug」。

### 10.2 实现时定死的细则（方案里没写死到代码级的）

- **主属性确定性**：`FNV-1a(series + "," + tier)` → `0.85 + 0.30 × seed`；「攻击或防御 / 速度或生命」
  的二选一吃**同一个 seed**，所以同 series 同 tier 永远同一套。
- **词条 roll 顺序**：先按成色 roll 品质（含降级：两条稀有降一条、两条传说降稀有、三条稀有降普通）→
  传说位只从 A/C 类别抽 → 类别之间等概率 → 该组**目标属性全部未被占用**才可选 →
  属性池耗尽就少一条（不降级、不补位）。结构上消灭碰撞，不需要「重抽 10 次」兜底。
- **词条是单件乘区**：生成时直接乘进这件装备的 `stats`，**不产出 `attackPct` 键**；

  复合类「鎏金」三条属性各取 1/3；`randomResist` 在六种抗性里定一条、不中途重掷。
- **老档迁移不能直接重算面板**：`baseAttributes` 里同时混着灵宠加成，只能「先扣旧面板 → 重生成 →
  再穿上」。映射不到新槽 / 同槽已占的，留在背包**不自动卖**。

  练气二层就是 攻 60.2 / 防 51.5 / 血 248 —— 比同境界子嗣还强。

按 P25 的裸装口径（3 子嗣、桂冈不统计）跑实机队伍，**练气九层能一路通到难度 7**，
难度曲线对成型玩家形同虚设。

### 14.3 顺手修掉一个探针 bug（这条比系数重要）

`sim:realm -- --scale=` 只改了 `stats.health`，**没改战斗实际读的 `currentHealth`**。
所以之前所有带 `--scale` 的试算里，敌人都是「伤害/防御按倍率放大、血量没放大」的玻璃大炮。
第一次扫描因此把系数算成 10（偏紧），修好后是 7。

> 教训：试算开关也要走生产字段。`currentHealth` 是战斗真值，`stats.health` 只是展示。
