# 📜 《多子多福：开创仙朝》UI视觉规范蓝皮书 V1.2 (定稿版)

> **V1.2 更新日志**：基于实机验证，彻底解决“大白纸”问题。引入旧宣纸暖色底；重构顶部导航为“两行式+书签页签”；确立“数值平权”的版面秩序；放全局字号并拉开行距；增加核心 Token 与代码示例。

## 序言：项目设计基调

本规范旨在为这款重度放置、包含极多数值与文本的仙侠游戏，建立一套**“低负担、高陪伴、东方极简”**的视觉体系。我们要像展开一幅生宣画卷，克制、冷静地呈现主角势力的扩张与繁衍。

---

## 第一部分：设计哲学与体验内核 (Why)

所有设计与前端人员必须理解以下底层逻辑：

1. **情绪锚点**：**静谧、隐忍与法度**。面对繁杂系统，玩家的核心愉悦感来自于“掌局者”的秩序感。
2. **设计铁律一：无高光与去拟物原则**。严禁玻璃拟态、发光渐变、3D 图标。所有材质必须是哑光（老旧宣纸与风化金属）。
3. **设计铁律二：模块解耦与认知隔离**。拒绝单页无限堆砌。主页面只留“修行与资源”，其余系统进入独立页签。
4. **设计铁律三：反馈如涟漪**。系统反馈应像一滴墨落在宣纸上缓缓晕染，绝不用强闪烁或大弹窗。
5. **设计铁律四：极简不等于无引导**。必须通过“排版权重（字号/粗细）”、“微质感锚点（菱形/渐变线）”和“交互状态（底色/边框）”来引导视线。

---

## 第二部分：美术意象与材质提取 (Imagery)

提取现实的东方材质，**绝对禁止具象化**：

* **主基调**：**宣纸残卷**（旧宣纸暖底，哑光纸纹）。
* **修行模块**：**晨雾远山**（孤寂感，极细流动的青玉色）。
* **内廷模块**：**朱砂印谱/线装玉牒**（秩序感，名册列表，有孕时的一抹朱砂红）。
* **领地模块**：**风化界碑与青铜**（法度感，微带土色/暗金属）。
* **核心材质**：**暗金**。仅作 UI 的极细边框、按钮描边、悬停微光，代表权柄。

---

## 第三部分：空间骨架与排版节奏 (Structure)

### 1. 顶部导航：两行式分离结构

* **第一行（全局信息）**：左侧游戏大标题，右侧核心资源常驻（灵石、贡献、时间）。无底线，靠留白隔离。
* **第二行（模块导航）**：将导航剥离为独立的“书签/卷标”式区域。
  * **未选中**：淡墨文字，透明边框。
  * **选中态**：文字变青玉色/深墨色，附加极淡米白底色（`#FCFBF7`）与 `1px` 极细暗金边框，明确提示“可点击/当前所在”。

### 2. 分区 1：总览状态（数值平权）

* **布局**：左侧为“封地/地名 + Level”，右侧为 `flex` 横排的各项数值（民心、人口等）。
* **原则**：**数值平权**。不再刻意放大某一个数值，统一字号为 `18px`，字重 `700`，展现军帐账本的严谨秩序感。

### 3. 分区 2 & 3：功能建设与流水

* **合并卡片**：功能按钮（如巡视、征收）挂靠在卡片右上角（`.acts` 使用 `margin-left: auto`）。
* **流水排版**：字号 `14px`，行高 `32px`。时间用 40% 透明度的墨色弱化，事件主体用青玉色加粗，数值正常展示。

## 第四部分：色彩、排版与组件 Token (Tokens & 代码示例)

### 1. 核心 CSS Token 变量

前端必须在全局 `:root` 或主题配置中定义以下变量，严禁在业务代码中写死颜色：

```css
:root {
  /* 背景与面板 */
  --bg-paper: #F3EFE6;          /* 全局底色：旧宣纸色 */
  --bg-surface: #FCFBF7;        /* 卡片底色：素帛米白 */

  /* 字体颜色 */
  --text-main: #3D3D3D;         /* 主文字：柔和松烟墨 */
  --text-sub: #8A857B;          /* 辅助文字：淡灰墨 */
  --text-fade: rgba(61,61,61,.4);/* 极淡文字：流水时间戳 */

  /* 核心强调色 */
  --accent-jade: #2E8B7A;       /* 青玉：进度条、正向状态 */
  --accent-gold: #C9A227;       /* 暗金：边框、菱形锚点、主按钮 */
  --accent-red: #C0392B;        /* 朱砂：有孕小印 */

  /* 基础排版 */
  --font-base: 15px;
  --font-title: 18px;
  --radius-card: 12px;
}
```

### 2. 核心组件代码片段示例

#### 示例 A：卡片容器 (悬浮感与极细金边)

```css
.zone {
  background: var(--bg-surface);
  border: 1px solid rgba(201, 162, 39, 0.3); /* 30% 透明度的暗金 */
  border-radius: var(--radius-card);
  padding: 28px;
  margin-bottom: 24px;
  /* 让卡片浮在旧宣纸背景上的关键微阴影 */
  box-shadow: 0 6px 24px rgba(0, 0, 0, 0.04); 
}
```

#### 示例 B：导航项 (书签态)

```css
.nav-item.on {
  color: var(--accent-jade);
  font-weight: 700;
  background: var(--bg-surface);
  border: 1px solid rgba(201, 162, 39, 0.4);
  border-radius: 6px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.02);
  transition: all 0.2s ease;
}
```

#### 示例 C：视觉锚点 (标题左侧的暗金菱形)

```css
.zone-head h3::before {
  content: '';
  display: inline-block;
  width: 5px;
  height: 5px;
  background: var(--accent-gold);
  transform: rotate(45deg); /* 旋转成菱形 */
  margin-right: 10px;
  vertical-align: middle;
}
```

#### 示例 D：极细进度条

```css
.row .bar {
  height: 6px;
  background: #E6E2D6; /* 轨道底色 */
  border-radius: 3px;
  flex: 1;
}
.row .bar i {
  display: block;
  height: 100%;
  background: var(--accent-jade);
  border-radius: 3px;
}
```

## 第五部分：前端落地验收标准 (Acceptance)

前端在交付页面时，必须通过以下验收：

1. **“视距”测试**：请将屏幕缩放至 100%，阅读正文和流水。最小的辅助字号（如时间戳）**不得低于 13px**，流水行距不得低于 `28px`。保证挂机长时间观看不费眼。
2. **“质感悬浮”测试**：卡片是否凭借微阴影和极细金边，清晰地“浮”在宣纸底色之上，而不是与背景融为一体？
3. **“多端”测试**：窄屏下，两行式导航和右下角的按钮是否发生了挤压变形？流水列表是否出现丑陋的系统默认滚动条？
