# 📜 《多子多福：开创仙朝》UI视觉规范蓝皮书

## 序言：项目设计基调

本规范旨在为这款重度放置、包含极多数值与文本的仙侠游戏，建立一套**“低负担、高陪伴、东方极简”**的视觉体系。我们要避免用传统的“重度页游”或“现代SaaS后台”去包装繁杂的修仙数据，而是要像展开一幅生宣画卷一样，克制、冷静地呈现主角势力的扩张与繁衍。

---

## 第一部分：设计哲学与体验内核 (Why)

在动手画一根线、填一个色之前，所有设计与前端人员必须理解本项目的三大底层逻辑：

1. **情绪锚点：废墟上的新生与掌局感**
* 主角是在黄土沟壑中蛰伏发家的。UI 的底层情绪是“静谧、隐忍与法度”，而非喧闹的视觉刺激。

* 面对复杂的家族与领地系统，玩家的核心愉悦感来自于**“掌局者”的秩序感**。
2. **设计铁律一：无高光与去拟物原则**
* 严禁使用现代 UI 的玻璃拟态、发光渐变、厚重的 3D 图标。所有的材质必须是哑光的（像老旧的宣纸与风化的金属），长视距挂机绝不刺眼。
3. **设计铁律二：模块解耦与认知隔离**
* 原著信息量极其巨大。我们必须砍掉“把所有信息塞进主页”的冲动。主界面只留最核心的“修行与资源”，内廷、领地、百艺等系统必须进入独立的模块页签，各享独立呼吸空间。
4. **设计铁律三：反馈如涟漪，拒绝闪电战**
* 放置类游戏不需要“闪烁、弹窗、跑马灯”。所有的系统反馈（如子嗣加一、资源变化）应该像一滴墨落在宣纸上，缓缓晕染开来。

---

## 第二部分：美术意象与材质提取 (Imagery)

本项目的视觉灵感来源于现实的东方材质，但**绝对禁止具象化（绝不把进度条画成一炷香）**，只提取其纯粹的视觉符号：

* **主基调（全局骨架）**：**宣纸残卷**。极淡的暖白色底，细腻的哑光纸纹感。

* **修行模块（静谧）**：**晨雾远山**。体现长生长视的孤寂感，用极细的、缓慢流动的青玉色代表灵力。

* **内廷模块（秩序）**：**朱砂印谱/线装玉牒**。弱化侍妾的 P1-P4 等级标签，用古籍的竖排或规整排版展现名册感，唯一的视觉高光是“有孕”状态下的那一抹朱砂小印。

* **领地模块（法度）**：**风化界碑与青铜**。仅限内政模块使用这种粗粝的、微带土色或暗金属质感的意象，代表封地的厚重与权力。

* **核心材质（暗金）**：提取自本命“饕餮纹暗金”。不作为大面积色块，仅作为 UI 的**极细边框、悬浮光晕、核心按钮的文字描边**，代表着修仙界的权柄与高级感。

---

## 第三部分：信息架构与空间骨架 (Structure)

针对游戏庞大的系统（修炼、多子多福、建设、百艺、商业），我们采用**“大统一、小差异、渐进式披露”**的空间逻辑：

### 1. 一级导航（极简容器）

* 放弃底栏大图标，采用**文字标签 + 极小线框符号**。

* 当前激活状态不搞高光背景，仅用一道极细的暗金下划线表示。

### 2. 二级页面布局（四分区标准架构）

针对高频实时产出的页面，采用经典四分区布局，但必须配合留白进行降噪：

* **分区 1：总览与状态（裸排大留白）**：页面之眼。用最大的字号（如24px）展示最高频数据，下方留出巨大空白。

* **分区 2：功能设置区（功能案几）**：按钮采用极简线框风（白底+金边），如同案几上的玉简。

* **分区 3：实时流水播报（信息瀑布）**：重灾区。用极淡的灰墨色（40%透明度）和极小的字号，取消所有边框，仅用极细虚线或行距分隔，让它像《起居注》一样静静流淌。

* **分区 4：该页资源（对齐阵列）**：单色线框图标与数字必须严格等宽对齐。

### 3. 宽窄屏适配法则

* **宽屏**：分区 2 和 3 左右并排，中间用大间距（Gap）或极细虚线分隔，绝不用实心粗线框死。

* **窄屏**：分区 2 和 3 垂直分布，分区 3（流水）必须设定内部滚动 `max-height`，滚动条需定制成极细且半透明的样式。

## 第四部分：色彩、排版与组件 Token (Tokens)

这是前端开发直接调用的字典，必须严格遵守使用比例。

### 1. 色彩规范 (Color Tokens)

* **底色（背景）**：`#FAFAF8`（生宣暖白，80%面积）。

* **面（面板底色）**：`#FFFFFF`（素帛白，纯净无渐变，浮于底色之上）。

* **主文字与核心数据**：`#2C2C2C`（松烟墨，15%面积）。

* **次文字与说明**：`#999999`（淡墨，4%面积）。

* **青玉点缀（生机/正向）**：`#2E8B7A`（仅限 1% 面积，仅用于进度填充与核心动态）。

* **暗金点缀（权柄/交互）**：`#C9A227`（用于 1px 边框、按钮线框、Hover 状态）。

* **朱砂（特殊状态）**：`#C0392B`（极小面积，仅用于“有孕”小印、危险警告）。

* **线条法则**：卡片外框统一为 `1px solid rgba(201, 162, 39, 0.25)`。内部分割线统一为 `1px dashed rgba(44, 44, 44, 0.1)`。

### 2. 基础组件规范 (UI Atoms)

* **容器 (Panel)**：白底 + 1px 暗金边框 + 12px 圆角。内 Padding 极大（24px 及以上）。Hover 时边框加深至 0.5，并泛起极微弱的金色阴影。

* **按钮 (Button)**：严禁大面积填充。主操作为“白底 + 1px 暗金边 + 暗金文字”，Hover 时背景泛起极淡的金色（5%透明度）。次操作为纯文字无边框。

* **进度条 (Progress)**：高度极细（4px 或 6px）。底色为极浅灰，填充色为青玉。动效必须是缓慢的“水波呼吸”，严禁快速跑马灯。

* **名册列表 (List)**：无竖线表格感。行高至少 48px 保持透气感。行与行用极淡虚线分割。侍妾有孕时，名字右侧跟一枚 12px x 12px 的朱砂小方印。

* **字体规范 (Typography)**：全局应用 **霞鹜文楷**。大标题/核心数据加粗，正文字重常规，流水播报使用极细字重。

## 第五部分：前端落地验收标准 (Acceptance)

前端在交付前端页面时，必须通过以下验收：

1. **“退远看”测试**：网页缩放至 80%，整体是否仍然如同一张干净的白纸，有没有出现视觉上“糊成一团”的黑块或杂色块？

2. **动效测试**：页面静止时，除了必要的缓慢呼吸动效，是否绝对安静？

3. **多端适配**：在 1440px 宽屏和 700px 窄屏下，四分区布局是否丝滑切换，流水列表是否出现丑陋的系统默认滚动条？
