## 五、C1 · 在线陨落提示（本日新定稿）

### 形态：沿用「有喜叮」同款全局提示，不弹窗

参照物：《当前实现》P18 #8 —— 「有喜当晚触发全局提示：叮！/ 子嗣加一 / 孕育中子嗣名单；诞生弹窗不再重复，也不暂停时间」。陨落用同一套组件、同一档通知。

### 聚合规则（回答「一小时陨落十个怎么办」）

| 场景 | 处理 |

|---|---|

| 单次结算内 1 个陨落 | 一条提示 |

| 单次结算内 N 个陨落 | **合并成一条**：「陨落 N 人：桂某某、桂某某……」 |

| 不同结算周期 | 各出一条，不跨周期合并 |

| 弹窗未关又来新陨落 | **不堆叠**——提示层允许同时存在多条，但同一条内只追加名字，不新开第二条 |

**核心原则**：同一次结算 = 一条；跨结算 = 可多条但不弹窗、不阻塞。

### 内容模板

```
陨落 · N 人

桂某某（练气三层）、桂某某（凡人）

返还：修为 +X · 词条 Y 条
```

名字 + 境界让玩家知道是谁；返还（修为数值 + 词条条数）必须展示。

### 不暂停时钟

与「有喜叮」一致，`PAUSE_ROUTES` 不加，不调 `pauseClockForEvent`。

### 离线

进离线报告，**不弹**。报告格式：

```
本期子嗣陨落 N 人：桂某某（练气三层）、……

返还修为合计 +X · 词条 Y 条
```

**与 B2「唯一暂停点 = 子嗣陨落」不冲突**：离线结算时暂停等确认；在线陨落不暂停，与突破弹窗同理。

### 与通知四档的关系

陨落**不进第 3 档弹窗**（五类：解锁、寿终、离线报告、二选一叙事、突破），走**第 2 档横幅/toast**。

### 待核

1. 「有喜叮」用的组件（`notice.js` 哪条路径）—— 复用同一套

2. 返还字段（修为 / 词条）是否已在 `secretRealm` 陨落结算里产出 —— **待核**

3. 聚合窗口判定点：同一次 `runSegment` 结算还是同一次 tick

### 文档同步

《开发手册》§二 · 《模块解锁方针》§四 · 《模块二》§15.5 · 《当前实现》P53 #12 · 《下一步》B10 前置。
