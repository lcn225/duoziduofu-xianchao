## 一、这张表是干什么的

同参契合 = `Σ(交集标签权重) / Σ(本命标签权重)`。

只按字面撞词，语义相通但用词不同的两件物品会被算低。最典型是原作诡代法：玲珑心对赤尻马猴，字面一个词都撞不上，但“七窍通明、趋吉避凶”和“晓阴阳、避死延生”在更高一层是同一件事。

这张表补这层语义：**让同参的顶层词能通过直接关系边，命中本命的顶层词**。只影响分子，永远不改分母。

---

## 二、方向约定（本版重点）

一条边 `A → B` 的含义固定为：

> **同参打了 A，本命打了 B，则本命的 B 被命中**，按 B 的全权重 1.0 计入交集。

| 字段        | 语义         | 例子                  |
| --------- | ---------- | ------------------- |
| `derives` | 向下衍生：同源不同词 | `玲珑 derives 七窍`     |
| `implies` | 上位/同义：异词同义 | `趋吉避凶 implies 避死延生` |

两者**匹配方向相同**，都是“同参词 → 本命词”。区别只在语义。

写表时问一句：“同参带 A，本命带 B，该不该算命中？”该，就把 A 写进 B 所在键的 `derives` 或 `implies`。

**注意：表的键是同参词，值里的词是本命词。** 不是反过来。

## 三、匹配算法（修正后）

### 3.1 伪代码

```text
function harmony(item, master):
    masterW = sum(weight(t) for t in master.tags.all)
    hit = 0

    // 顶层：同参词作键，查它是否指向本命词
    for m in master.tags.top:
        if m in item.tags.top:
            hit += 1.0
            continue
        for t in item.tags.top:
            if t in rel and (m in rel[t].derives or m in rel[t].implies):
                hit += 1.0
                break   // 同一本命词只计一次

    // 中层/底层：字面交集
    hit += 0.4 * |master.tags.mid ∩ item.tags.mid|
    hit += 0.25 * |master.tags.base ∩ item.tags.base|

    raw = hit / masterW
    return item.id == master.id ? 1.0 : min(raw, 0.95)
```

### 3.2 旧伪代码错在哪

旧版写的是：

```text
for m in master.tags.top:
    if any(t in rel[m].derives or rel[m].implies for t in item.tags.top):
        hit += 1.0
```

这等于**用本命词 m 作键去表里找同参词**，方向是 `m → t`，与“同参 → 本命”相反。

表里 `"趋吉避凶": {"implies": ["避死延生"]}` 这个键，旧写法会用本命词 `避死延生` 去查 `rel["避死延生"]`，表里没这个键，**查不到**；反而本命词 `趋吉避凶` 能查到同参词 `避死延生`，**方向反了**。

修正后：用同参词 `趋吉避凶` 作键查 `rel["趋吉避凶"]`，值里有 `避死延生`，本命词 `避死延生` 命中。方向正确。

## 四、非对称算例（方向定死）

用原作这个例子，正反各跑一次，必须拉开。

| 角色  | 物品   | 顶层标签 |
| --- | ---- | ---- |
| 同参  | 玲珑心  | 趋吉避凶 |
| 本命  | 赤尻马猴 | 避死延生 |

关系表：`"趋吉避凶": {"implies": ["避死延生"]}`

### 正向（修正后，正确）

```text
同参词 t = 趋吉避凶
rel[趋吉避凶].implies = ["避死延生"]
本命词 m = 避死延生，在值里 → 命中
hit += 1.0
raw = 1.0 / 本命总权重 > 0
```

### 反向（旧写法，错误）

```text
本命词 m = 避死延生
rel[避死延生] 不存在 → 查不到
同参词 趋吉避凶 不被检查
hit += 0
raw = 0
```

**结论：正向有分，反向为 0。方向定死：同参词作键，本命词作值。**

## 五、边界规则（实现时不要扩）

1. **只走一跳**：不做传递闭包。A→B、B→C 不推出 A→C。
2. **同参词作键**：只查 `rel[t]`，t 来自同参顶层标签；不反向展开同参词自己的关系。
3. **同一本命词只计一次**：同参多个词命中本命同一个词，不叠加。
4. **关系只影响分子**：分母永远是本命标签权重和。
5. **不设关系强度**：命中即按本命词全权重 1.0，不做 0.5、0.8 衰减。
6. **只对顶层生效**：中层、底层只走字面交集，不查关系表。

## 六、`_meta` 字段说明

`top_relations.json` 顶层新增：

```json
"_meta": {
  "version": "2026-10-28",
  "promoted": ["七星", "反伤", "六甲"],
  "candidate": ["御风"],
  "example_only": ["玲珑", "趋吉避凶"]
}
```

| 字段             | 含义                   | 引擎/脚本处理      |
| -------------- | -------------------- | ------------ |
| `version`      | 表版本                  | 只读           |
| `promoted`     | 已转正的顶层词              | 计入正式词表       |
| `candidate`    | 候选词，参与关系匹配，不计入正式词表统计 | 打标时可用，统计时排除  |
| `example_only` | 示例词，池内暂无打标物          | 只作关系键，不要求有物品 |

**脚本读表时要跳过 `_meta`**，不要把它当成关系键。统计脚本里 `表键 78` 包含了 `_meta`，实际关系键是 77（76 个词 + 1 个 `_meta` 元数据）。修正后应报 `表键 77`、`实打标 71`、`表中有未用` 里去掉 `_meta`。
