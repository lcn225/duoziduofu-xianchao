## 二、落库格式建议

`items.data.js` 新增 `tags` 字段，按层存：

```json
{
  "id": "taotie_jade",
  "tags": {
    "top": ["饕餮纹", "暗金"],
    "mid": ["饰品", "青金石"],
    "base": ["灵器"]
  }
}
```

理由：

- 按层存，引擎算权重时不用再查词表判层；
- 顶层可空数组，中层/底层至少 1 个；
- 关系表单独存 `top_relations.json`，引擎加载一次，不塞进每件物品。

## 三、引擎计算伪代码

```text
function harmony(item, master):
    masterW = sum(weight(t) for t in master.tags.all)
    hit = 0
    for m in master.tags.top:
        if m in item.tags.top:
            hit += 1.0
        else if any(t in rel[m].derives or rel[m].implies for t in item.tags.top):
            hit += 1.0
    hit += 0.4 * |master.tags.mid ∩ item.tags.mid|
    hit += 0.25 * |master.tags.base ∩ item.tags.base|
    raw = hit / masterW
    return item.id == master.id ? 1.0 : min(raw, 0.95)
```

注意：

- 顶层关系命中按本命词全权重 1.0，不按同参词权重；
- 中层/底层按字面交集，不走关系表；
- 封顶 0.95 只对非原物。

## 四、打标规则汇总（`tag_rules.md` 要点）

| 项    | 规则                                                              |
| ---- | --------------------------------------------------------------- |
| 底层   | `category` + `fateElement`；`vessel/beast` 与灵器/灵兽同义时只保留 category |
| 灵器中层 | 功能大类（飞剑/长柄/短柄/防御/饰品/辅助/软兵器/远射）+ 具体材质                            |
| 灵兽中层 | 生态类群（猛禽/鸣禽/游禽/陆禽）+ 具体物种；低频归并                                    |
| 灵植中层 | `type` 植型，名称含参/芝/竹/莲/兰时允许多植型                                    |
| 灵材中层 | 具体材质优先，否则 type 大类；花/叶/果映射植型；器胚/骨材按系列                            |
| 顶层   | 名称/描述明确支持才打；1~2 阶可空，3 阶以上必须 ≥1                                  |
| 跨层   | 暗金/厚土/离火 = 顶层 1.0；青金石/风磨铜/精金 = 中层 0.4                           |
| 同系列  | 批量打标后逐件修例外；低阶不继承高阶本命专属词                                         |
| 封顶   | 同 id = 1.0，非原物 = min(raw, 0.95)                                 |

## 五、关系表使用说明（`tag_rules.md` 附节）

已单独写过交接说明，落库时把那段作为 `top_relations.json` 的 README 即可。核心四条：

1. 边 `A → B` = 同参 A 命中本命 B；
2. 只走一跳，不传递；
3. 同一本命词只计一次；
4. 关系只影响分子。
