## 0. 一分钟背景

放置修仙游戏。主角练「功法」，突破看综合契合度：

```
综合契合度 = 功法契合 × 同参契合 × 灵地契合      （连乘，任何一项短板都拖累整体）
```

- **本命之物**：与主角命格绑定的物品。开局两件：**刃背乌鬣猪**、**饕餮纹暗金镶青金石玉牌**。
- **同参**：玩家挂在某个本命旁边的一件物品。**任何已拥有的物品都能当同参**。
- **同参契合** = 两件物品**标签集合的重合度**，0~1 连续：

```
同参契合 = Σ(交集标签权重) / Σ(本命标签权重)
```

- 标签三层权重：**顶层 1.0（核心意象）/ 中层 0.4（形态、材质）/ 底层 0.25（大类归属）**。
- 分母永远固定为本命自己的权重和 ⇒ **同参标签少不挨罚**（原作「诡代法」的机制基础）。

## 1. 现在卡在哪

1. **顶层标签不能按字面撞词。** 同源要能衍生（玲珑 → 七窍 / 通透 / 机巧），
   异词要能上位（趋吉避凶 ⊃ 避死延生）。必须先有一张 `derives / implies` 关系表，
   否则「玲珑心 → 赤尻马猴」这种正经诡代会被算低。
2. **575 件物品一件都还没打标。** 三阶及以上 **280 件**必须有 ≥1 个顶层标签；
   一二阶 **295 件**不强制。
3. 代码还在跑旧的**六档**（1.0 / 0.8 / 0.6 / 0.4 / 0.25 / 0.1），只等打标完成就一次性切连续值。

## 2. 请你产出（四样）

### 产物 1 · 顶层关系表（最重要）

JSON，形如：

```json
{
  "玲珑":   { "derives": ["七窍", "通透", "机巧"], "implies": [] },
  "趋吉避凶": { "derives": [], "implies": ["避死延生"] }
}
```

- 覆盖《02-标签清单》三、顶层清单的全部词 +《03》§7.1 的特殊字眼/系列。
- `derives` = **向下衍生**（同源不同词）；`implies` = **上位 / 同义**（异词同义）。
- 关系是**单向**的；对称关系写成双向两条。
- 先不要引入「关系强度」——引擎按全权重算交集（关系命中 = 该词权重全额计入）。

### 产物 2 · 打标规则

说明每个数据字段怎么变成标签，要求**能直接写成脚本**：

| 层 | 来源 | 规则 |
|---|---|---|
| 底层 | `category` / `fateElement` | 直接映射，规则固定（见 §3） |
| 中层 | `type` / `name` / `series` | 器型 / 兽型 / 植型 / 材质四张映射表 |
| 顶层 | `name` + `description` | 规则优先，**必须人工的例外逐条列**（id + 理由） |

## 5. 数据里的已知坑（打标前必看）

1. **器型字段 `type` 用「飞剑」，标签表里是「剑」** —— 要做映射（`飞剑 → 剑`）。
2. **灵兽的 `type` 是「妖兽 / 灵兽 / 凶兽 / 异种」，不是物种**。
   物种标签（猪 / 狐 / 鸦 / 猴 …）要从 `name` 或 `series` 里抽。
3. **灵材的 `type` 是「金属 / 宝晶 / 灵土 / 灵木 / 骨材」**，比材质标签粗；
   具体材质词（青金石 / 玄铁 / 寒玉 …）在 `name` 里。
4. **283 个 series，很多是 10 件同系列**（如 `metal_qipei` 10 件、`gem_hanshui` 10 件）。
   同系列通常同材质、同意象 —— 先按 series 批量打，再逐件修例外，省一大半工作量。
5. **灵植 `type`** = 花 / 草 / 叶 / 树 / 果 / 藤 / 竹 / 苔 / 参 / 芝 / 莲 / 兰，
   正好对应中层「植型」，可直接映射。
6. 一二阶 295 件里多数是灵材 / 灵植，顶层标签可以空；**别为了凑标签硬编**。
