# 一、修行主循环（升级速度 · 核心）

## 1.1 三个基本公式

`src/plugins/cultivationMath.js`

```
打坐一次消耗灵力 = floor(10 × 1.5^(境界-1))      # 10 → 9852（18 级），增长 985 倍
打坐一次获得修为 = floor(1  × 1.2^(境界-1))      # 1  → 22   （18 级），增长 22 倍
30%×福缘 概率该次翻倍                             # rollCultivationGain
```

**灵力收入**：`src/App.vue:216` + `src/workers/spirit.js:2` —— 每 **1000ms** tick 一次，基础值 **1**

```
灵力/秒 = 1 × spiritRate × (0.5 + 综合契合度×1.5) × (1 + 0.1×散功次数)
```

`spiritRate` 初值 1，**每次内功突破 ×1.2**（`core.js:106`）。外功突破不给 spiritRate，只给 `灵力 += 50×bodyLevel`。

## 🔴🔴 实测：门槛目前够不到，游戏会卡在练气十层

我直接在 node 里跑了 `harmony.js` 的纯函数（无浏览器依赖）：

| 场景 | 功法 | 同参 | 灵地 | 本命 | 综合 |
|---|---:|---:|---:|---:|---:|
| 开局实测 | 42.0% | 53.0% | 65.0% | 75.0% | **58.75%** |
| 本阶段上限 @练气 | 62.0% | 73.0% | 100.0% | 75.0% | **77.50%** |
| 本阶段上限 @筑基/结丹 | 62.0% | 73.0% | 100.0% | 100.0% | **83.75%** |
| 假设等级能升满（含本命共鸣） | 100% | 100% | 100% | 100% | **100.00%** |

**根因**：`practice.qiArts.known[id].level` 与 `practice.fateItems.known[id].level` 初始化为 1，而**全仓库没有任何代码把它们 +1**（我 grep 过所有写入点，只有 `pets.js:195` 给灵宠升级）。等级是死的，所以：

- 功法契合上限 = 0.40 + **1**×0.02 + 0.20 = **0.62**（设计意图是 20 级 → 1.00）
- 同参契合上限 = 0.50 + **1**×0.03 + 0.20 = **0.73**（设计意图是 10 级 → 1.00）

**后果**：
1. **练气九层门槛（75%）勉强可过** —— 综合上限 77.5%，要求熟练度、祭炼双双顶满 + 灵地 1.0 + 金丹级功法相生，容错极小
2. **筑基门槛（80%）过不去** —— 练气 tier 上限只有 77.5%，**永久卡在练气十层**
3. **结丹门槛（100%）过不去** —— 上限 83.75%

设计文档 `design/开发进度与方案.md` §七-② 专门讨论过「结丹门槛按原文永远达不到」并声称靠「功法分品阶」修好了——**这个修正依赖功法等级能涨到 20 级，但升级路径没实现**，所以实际仍然锁死。

> 要讨论的第一件事：**功法/同参的升级路径是这轮就该做，还是把门槛值先降下来？**

## 熟练度 / 祭炼节奏（`harmony.js:25`）

`secondsPerGameHour = 2`（现实 2 秒 = 1 游戏小时），**这是唯一节奏旋钮**。

| 项 | 速度 | 上限 | 满值耗时 |

# 六、战斗数值

`src/plugins/combat.js`

## 6.1 默认属性（`combat.js:22-48`）

health 100 / maxHealth 100 / damage 10 / defense 5 / speed 10 / critRate **0.05** / dodgeRate **0.05** / **critDamageBoost 0.5** / 其余全 0

## 6.2 伤害公式（`calculateDamage`, `:51-93`）

```
damage = attack × (1 + combatBoost)
暴击  : finalCritRate = max(0, critRate×(1+combatBoost) − 抗暴×(1+对方resistanceBoost))
        命中 → damage ×= (1.5 + critDamageBoost)          ← 基础暴击倍率 1.5
连击  : finalComboRate = max(0, comboRate×(1+combatBoost) − 抗连)
        命中 → damage ×= 1.3
吸血  : 只置标记，回血在回合流程里 = 造成伤害 × 0.3
眩晕  : 只置标记，效果 = 让对方本回合不出手
最终  : damage ×= (1 + finalDamageBoost)
```

## 6.3 防御/减伤（`:95-107`）

```
effectiveDefense = defense × (1 + combatBoost)
damage ×= 100 / (100 + effectiveDefense)      ← 递减减伤，趋近但不达 100%
damage ×= (1 − finalDamageReduce)
```

## 6.4 回合（`executeTurn`, `:190-283`）

- **最多 10 回合**，超过直接判负
- 速度决定先手（`玩家速度×(1+combatBoost)` vs 敌方同式），**平手玩家先手**
- 眩晕只能靠**先手方**命中来实现「跳过对方回合」，一次眩晕跳过一回合

## 6.5 敌人数值生成（`generateEnemy`, `:291-363`）

`L = 层数`，`D = 难度`：

```
health = 100 + D×L×200      damage = 8 + D×L×2
defense = 3 + D×L×2         speed  = 5 + D×L×2
critRate = 0.05 + D×L×0.02  combo/counter = 0.03 + D×L×0.02
stun/vampire = 0.02 + D×L×0.01   各 Resist = 0.02 + D×L×0.01
dodgeRate = 0.05 + D×L×0.02
critDamageBoost = 0.2 + D×L×0.1   critDamageReduce = 0.1 + D×L×0.05
finalDamageBoost/Reduce = 0.05 + D×L×0.02
combatBoost/resistanceBoost = 0.03 + D×L×0.02
```

- **精英**（层%5==0）：百分比属性 ×1.3（封顶 0.8）、绝对值 ×1.5
- **Boss**（层%10==0）：百分比属性 ×1.5（封顶 0.9）、绝对值 ×2
- health/damage/defense/speed **无上限**，随层数线性无界增长

## 6.6 战斗里的死代码 / 未实装

- `critDamageReduce`（弱化爆伤）：`takeDamage` 调用时**没传 attackerStats**（`:134`），暴击减免分支**永不触发**
- `healBoost`（强化治疗）：声明了但**任何地方都没用过**
- crit/combo/stun/vampire 率**只有下钳 `max(0,…)`，没有上钳**，理论上可超 1 变成必触发（只有 `dodgeRate` 被钳到 [0,1]）

| 品阶 | 成功率 | 残页需求 |
|---|---:|---:|
| 一品 | 0.9 | 10 |
| 二品 | 0.8 | 15 |
| 三品 | 0.7 | 20 |
| 四品 | 0.6 | 25 |
| 五品 | 0.5 | 30 |

| 七品 | 0.3 | 40 |
| 八品 | 0.2 | 45 |
| 九品 | 0.1 | 50 |

- 实际成功率：`Math.random() > 成功率 × luck`，其中 `luck = this.luck × this.alchemyRate`
- 残页公式：`5 × 品阶数 + 5`
- 类型倍率：灵力类 1 / 修炼类 1.2 / 属性类 1.5 / 特殊类 2
- 效果随境界：`value × 类型倍率 × (1 + (level×7 − 1) × 0.1)`

## 7.5 装备（`equipment.js`）

强化：maxLevel 100，cost = 10 × (当前级+1)，成功率 = 1 − 当前级×0.05

## 7.6 灵宠（`pets.js`）

- 升级消耗 `(灵宠等级) × 10` 精华；升星返还 `(材料等级−1) × 10` 精华
- 升级成长：非百分比属性 `×(1 + 0.01×qualityMultiplier)`，百分比属性 `+0.01×qualityMultiplier`
- `qualityMultiplier`：神 2.0 / 仙 1.8 / 玄 1.6 / 灵 1.4 / 凡 1.2
- **实际生效的加成**（`pets.js:44-90`）：品质基础加成 神15% / 仙12% / 玄9% / 灵6% / 凡3%；每星 神+2% 其余+1%；每级 `+(等级−1)×基础×0.1`；`phase = floor(star/5)` 额外 `phase×基础×0.5`；战斗属性 = 最终值 × 0.5

# 八、成就系统

`src/plugins/achievements.js` —— **9 类共 93 条，其中 5 条 `deprecated`（`breakthrough_6..10`），生效 88 条**。无铜/银/金分级。

**全部生效成就的灵力累加总量 = 1,159,300**（含废弃则 2,309,300）。

## 🔴 乘数类奖励是连乘的，会指数膨胀

`checkAchievements`（`:782-798`）用 `*=` 叠加：

| 属性 | 全成就连乘上限 | 参与条目 |
|---|---:|---|
| **spiritRate** | **×216.11** | 修为 4 条 + 突破 4 条 + 资源 5 条 |
| herbRate | ×7.02 | 收集 7 条 |
| alchemyRate | ×17.55 | 炼丹 6 条 |
| luck | ×1.65 | 探索 2 条 |

再叠上内功突破本身的 `1.2^17 = ×22.2` 和「顿悟」事件的 ×1.05，**灵力收入的乘数总量级可达数千倍**。

> 这是全项目**最大的数值杠杆**，也是 §1.3 那个「100 天 vs 几小时」区间的来源。

## 🔴 `damage` / `defense` 奖励是死字段

`equipment`（damage ×32.4 / defense ×6）、`dungeon_explore`（damage ×35.29）、`dungeon_combat`（defense ×64.35）这些奖励字段**在发放代码里根本没被读取**，声明了但不生效。

## 🔴 三条成就永远无法达成（已知）

`achievements.js` 引用了三个 store 上不存在的字段，有可选链兜底所以不报错、静默失效：
- `player.equipment` → 应为 `Object.values(equippedArtifacts)`
- `player.dungeonStreakKills` → 无此字段
- `player.highQualityPillsCrafted` → 无此字段

影响「装备 / 秘境连杀 / 高阶炼丹」三类成就。未修，因为成就要被新模块替换。

## 奖励非单调的地方

- `cultivation_5`（48 小时，3000 灵力）排在 `cultivation_6`（24 小时，2000）之前
- `exploration_6`（500 次，15000）> `exploration_7`（1000 次，5000）
- `resources_6`（10 万灵石，20000）> `resources_7`（50 万灵石，10000）

# 九、存档 / 离线

- **自动存档**：无独立定时器，靠每秒 `gainSpirit` 末尾的 `saveData()`。即**每 1 秒把整个 state 加密写一次 IndexedDB**（已知性能隐患）
- IndexedDB `idle-xiuxian`，AES 密钥 `vue-idle-xiuxian`，`SAVE_VERSION = 2`（版本不符直接判废重开）
- **离线收益未实现** —— 关掉页面进度就停。只有 `maxSecondsPerTick: 86400` 占位（`harmony.js:26`），注释写明是留给离线结算模块的
- 改名：首次免费，第 n 次 `2^n × 100` 灵石（`Settings.vue:134`）；道号上限 6 字
- 新手礼包 **20000 灵石**（`Home.vue:25`）
- 全仓库只有 3 个 `setInterval`：灵力 tick 1000ms、自动修炼 1000ms、自动探索 3000ms
