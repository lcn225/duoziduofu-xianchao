# 一、#1 · 药圃供给

## 1.1 现状核对

| 项 | 原前提（2026-11-01） | 现状（2026-11-09 核对） |
|---|---|---|
| 药圃 | 未上线 | **已上线**（B14，`estate.js` 的 `herbGarden`，产**灵植 3/天/级**） |
| 药圃产出用途 | — | 喂丹炉（B11-b 乡间自动百艺，**3 灵植 → 1 件**，每天每级） |
| 药浴能不能吃灵植 | 未确认 | **能吃**（`bath.js:29` `BATH_CATEGORIES = ['灵材', '灵植']`） |
| 结论 | 供给只到 30 件/天，洗髓圆满只能跑 67% 速度 | **67% 数字作废**（见 §1.5） |

## 1.2 药圃进药浴

**结论：进药浴。** 药圃产灵植，灵植既可喂丹炉，也可泡药浴。**不再锁死一个用途。**

**判定层不用改** —— 药浴的料源本来就包含灵植。

## 1.3 ⚠ 真正缺的不是判定，是通路

**代码事实：**

| 环节 | 实际行为 |
|---|---|
| 药圃产出 | 进 `estate.storage.herb`，**一个数字**，不占背包 |
| 封地仓出口 | **只有丹炉/工坊自动消耗，没有「取出到背包」入口** |
| 药浴一键投入 `fillBathPool` | **只读背包 `items`** |
| ⇒ 结果 | **今天玩家的灵植永远进不了药浴池**，"投入=优先级" 这个动作在 UI 上不存在 |

**需要补一条通路。两个方案：**

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）封地仓 → 背包** | 加「取出」按钮，取出时生成**标准件**（阶 = 当前境界段、成色「中」、五系按需均分），进 `items`，之后交给现有 `fillBathPool` | 改动小；复用现有漏斗 + **1 件/小时**节流；丹炉抢料问题一起解决 |
| B 封地仓 → 直接灌药力 | 跳过物品实例，1 件直接折成药力加进 `bath.medicine` | 绕过 1 件/小时 节流，且丢掉五系配平（药浴是"五系同时 ≥ floor"） |

**推荐 A，标准件规则已定（2026-11-09 拍板）：**

| 项 | 规则 |
|---|---|
| 阶 | **= 当前境界段**，取段内低阶（练气一阶 / 筑基二阶 / 金丹三阶）—— 与"掉落阶按境界段"同一口径 |
| 成色 | **固定「中」**，不 roll |
| 五系 | **按药浴当前缺口均分**（哪一系离 `floor` 最远就补哪一系） |
| 数量 | 按封地仓存量取，扣 `storage.herb`，进 `items` 后再走现有 `fillBathPool` |

> 这样生成物是**确定性**的（同输入同输出），不会因 roll 出极品把药浴变成刷材料的口子。

## 1.4 零富余 = 预期行为（不是 bug）

| 产 | 耗 |
|---|---|
| 药圃 **3 灵植/级/天** | 丹炉 **3 灵植/级/天** |

**刚好对平，零富余。** 玩家只要把灵植分给药浴，丹炉就停 —— 这是设计给的优先级手段。**必须在 UI 提示与文档里标明"预期行为"，不要当故障修。**

## 1.5 「67% 速度」作废

**结论：67% 这个数字作废，不重算。**

理由：药力按品阶差 **40 倍**（一阶 10，五阶 400）。「30 件/天」没说几阶料，那个 67% 是按某个假定的品阶构成算出来的。O06 裁剪 + R49 配平后五系构成变了，假定不成立。

**系统按实际投入的料算药力，不预设速度。**

# 二、#2 · 命中/抗闪避词条

## 2.1 代码真值：战斗是**对抗式（减法）**

```
actualDodgeRate = clamp(dodgeRate − dodgeResist, 0, 1)      // combat.js:128
命中率           = 1 − actualDodgeRate                       // 没有下限
玩家 dodgeRate   = 0.05（基础，combat.js:32）+ 词条「无形」
玩家 dodgeResist = 0（combat.js:39；词条「五方揭谛/金刚/罗汉」可随机抽到）
敌方 dodgeRate   = 0.05 + difficulty × level × 0.02          // combat.js:303
敌方 dodgeResist = 0.02 + difficulty × level × 0.01          // combat.js:310
```

**没有 `hit` / 「基础命中」这个属性。** v1 的乘法式假设不成立。

## 2.2 词条结论

| 词条 | stat key | 结论 |
|---|---|---|
| **破妄** | `dodgeResist` | ✅ **采纳**。`dodgeResist` 是**现成属性**，词条只需加一行数据 |
| ~~鹰眼~~ | ~~`hit`~~ | ❌ **砍掉**。减法模型下"抬高基础命中"≡"降低对方闪避"，与破妄完全重复 |

> 将来真出现"高闪避 BOSS、需要命中下限"的需求，再单开**命中率下限**机制 —— 那动的是战斗核心，现在没数据支撑，不提前开。

## 2.3 数值

**走《数值真值表》§5.9「词条」的纯增益区间**（v1 误引成《装备词条表》§三 —— §3 是词表，没有数值段）：

| 品质 | T1 | T2 | T3 | T4 | T5 |
|---|---:|---:|---:|---:|---:|
| 普通 | 1~3% | 2~4% | 3~5% | 4~6% | 5~8% |
| 稀有 | 3~5% | 4~7% | 5~9% | 6~11% | 8~13% |
| 传说 | 5~8% | 7~10% | 9~12% | 11~14% | 13~16% |

**收益定位**：玩家自己的闪避只有 5%，所以破妄的价值全在**打高闪避敌人**（敌方闪避随 `difficulty × level` 涨到 20%+ 时，T5 传说 16% 才有意义）。这是 A 类纯增益，符合现有区间。

# 三、#4 · 药浴的两个模块七依赖

## 3.1 原文

> 药浴的两个模块七依赖：丹方锁、炼器与药浴抢灵材 —— 都等模块七。

## 3.2 丹方锁 —— ✅ 结案

`stores/modules/bath.js:141-150` 的 `bathExcludeOptions()` 已经把 **`lockedSpecies ∪ recipeLockedSpecies`** 合并后同时喂给：

- 浴桶（`bathPlanOptions`，`bath.js` store）
- 药浴池一键投入（`fillBathPool` → `planPoolFill`）

优先级 = **配方锁 > 药浴**（《模块七》§一）。**不用补代码。**

## 3.3 炼器与药浴抢灵材 —— ✅ 结案

| 环节 | 实际行为 |
|---|---|
| 投入药浴池 | `fillBathPool` 用 `takeUnits` 把料**从 `items` 真扣走**，塞进 `bath.pool.stock`，`location: 'estate'` |
| 炼器 / 制符 | `planMaterialsOf(recipe, items)` **只读背包**；乡间自动百艺也用 `bagItems` |

⇒ **进了药浴池的料，炼器拿不到。** 正是 §1 想要的隔离。**不用补代码。**

## 3.4 结论

**#4 两条都结案。** 真正要写的代码只有 §1.3 那条「封地仓 → 药浴」通路。
