# 货币系统修订方案 v2（完整版）

> 2026-10-20 定。核心：**同层自动进位，跨层手动兑换，四阶独立**。

> 替代 P17 的四字段 `{ daZi, jinYeZi, stone1, stone2 }`。

---

## 一、设计原则

1. **货币单位，不是货币种类。** 大子和金页子是同一货币的两种面额，像元/角/分，自动进位。一阶/二阶/三阶灵石同理。

2. **同层自动，跨层手动。** 凡俗层内、修仙层内不需要手动兑换；只有凡俗 ↔ 修仙跨层才需要手动，因为 3.5:1 不是整数，且仙凡物价分离。

3. **四阶灵石是战略资源。** 不进位、不兑换、不参与商品流通，单独字段。

4. **数值逻辑不变，只改数据结构与显示。** 经济 v2 的“二阶/月”基准表不受影响。

---

## 二、兑换链

| 层级 | 比例 | 是否自动 | 出处 |

|---|---:|---|---|

| 大子 → 金页子 | **100:1** | ✅ 自动进位 | 原作物价表 5242 行 |

| 金页子 → 一阶灵石 | **3.5:1** | ❌ 手动跨层 | 原作物价表 5462 行 |

| 一阶 → 二阶 | **100:1** | ✅ 自动进位 | 用户 2026-10-20 确认 |

| 二阶 → 三阶 | **800:1** | ✅ 自动进位 | 用户 2026-10-20 确认 |

| 三阶 → 四阶 | **不设** | — | 四阶独立，战略资源 |

**推论**：1 三阶 = 800 二阶 = **80,000 一阶**。

---

## 三、数据结构

```js
currency = {

secular: 0, // 总大子数（整数）

spiritual: 0, // 总一阶灵石数（整数，含二阶、三阶进位）

strategic: 0 // 四阶灵石数（整数，不进位）

}
```

| 字段 | 最小单位 | 进位链 | 用途 |

|---|---|---|---|

| `secular` | 大子 | 100 大子 = 1 金页子 | 凡俗层一切消费 |

| `spiritual` | 一阶灵石 | 100 一阶 = 1 二阶；800 二阶 = 1 三阶 | 修仙层一切消费 |

| `strategic` | 四阶灵石 | 不进位 | 战略级支出 |

**四阶灵石不参与兑换，不参与商品流通。** 只出现在战略级 UI（仙朝建设、跨域贸易）。

## 四、显示规则

### 4.1 凡俗层（`secular`）

```js
function formatSecular(n) {

const jin = Math.floor(n / 100)

const da = n % 100

if (jin >= 10000) {

return `${(jin / 10000).toFixed(1)} 万金页子`

}

return `${jin.toLocaleString()} 金页子 ${da} 大子`

}
```

| 条件 | 显示 | 示例 |

|---|---|---|

| 金页子 < 10,000 | `X 金页子 Y 大子` | `3,582 金页子 67 大子` |

| 金页子 < 10,000，大子 = 0 | `X 金页子 0 大子` | `3,582 金页子 0 大子` |

| 金页子 ≥ 10,000 | `X.X 万金页子` | `37,582 金页子` → `3.8 万金页子` |

**规则**：

- < 10,000 时，大子**始终写上**（含 0），与修仙层一致。

- ≥ 10,000 时，用「万」显示，**省略大子零头**（零头仍在账上）。

### 4.2 修仙层（`spiritual`，一阶总数）

```js
function formatSpiritual(n) {

if (n < 100) return `${n} 一阶`

if (n < 80000) {

const t2 = Math.floor(n / 100)

const t1 = n % 100

return `${t2.toLocaleString()} 二阶 ${t1} 一阶`

}

const t3 = Math.floor(n / 80000)

const rem = n % 80000

const t2 = Math.floor(rem / 100)

const t1 = rem % 100

return `${t3.toLocaleString()} 三阶 ${t2} 二阶 ${t1} 一阶`

}
```

| 条件 | 显示 | 示例 |

|---|---|---|

| 一阶 < 100 | `X 一阶` | `34 一阶` |

| 100 ≤ 一阶 < 80,000 | `X 二阶 Y 一阶` | `12 二阶 34 一阶` |

| 100 ≤ 一阶 < 80,000，Y = 0 | `X 二阶 0 一阶` | `12 二阶 0 一阶` |

| ≥ 80,000 | `X 三阶 Y 二阶 Z 一阶` | `1 三阶 0 二阶 34 一阶` |

**规则**：

- **中间位为 0 也要写上**（用户 2026-10-20 确认）。

- 三阶、二阶、一阶**始终全部显示**，不省略。

### 4.3 战略层（`strategic`）

`X 四阶`，如 `5 四阶`。不进位。

## 五、消费与找零

### 5.1 同层消费：直接扣最小单位

```js
// 买 20 金页子的侍妾

currency.secular -= 20 * 100

// 买 10 一阶的丹药

currency.spiritual -= 10
```

**自动找零**：`secular = 1234567`（12,345 金页子 67 大子），扣 2000 后 `= 1232567`，显示 `12,325 金页子 67 大子`。零钱保留。

**余额不足**：拒绝购买，不扣款。

### 5.2 跨层兑换：手动，3.5:1，双向

```js
// 凡俗 → 修仙

function secularToSpiritual(secularAmount) {

const maxN = Math.floor(secularAmount / 350) // 3.5 金页子 = 350 大子

if (maxN === 0) return { error: '不足 3.5 金页子' }

const fee = Math.ceil(maxN * 0.05) // 5% 手续费，向上取整

const net = maxN - fee

currency.secular -= maxN * 350

currency.spiritual += net

return { converted: maxN, fee, net }

}

// 修仙 → 凡俗

function spiritualToSecular(n) {

if (n > currency.spiritual) return { error: '余额不足' }

const fee = Math.ceil(n * 0.05)

const net = n - fee

currency.spiritual -= n

currency.secular += net * 350 // 3.5 金页子 = 350 大子

return { converted: n, fee, net }

}
```

**规则**：

- 双向兑换（用户确认）。

- 按 3.5 的整数倍扣，余数留 `secular`。

- 手续费 5%，**向上取整到整数一阶/大子**。

- 不够 3.5 金页子不能兑。

**手续费待验证**：P17 拍的 5–10%，当前按 5% 落地，实机后调。

## 六、四阶灵石

- 单独字段 `strategic`，不参与自动进位。

- 不参与跨层兑换。

- 不参与商品流通。

- 获取途径：**待定**（宝箱/秘境/事件，等模块五/八）。

- 用途：战略级支出（仙朝建设、跨域开拓、联姻彩礼等）。

## 七、老档迁移

### 7.1 迁移算法

```js
function migrateToV2(oldCurrency) {

const { daZi = 0, jinYeZi = 0, stone1 = 0, stone2 = 0 } = oldCurrency

return {

secular: daZi + jinYeZi * 100,

spiritual: stone1 + stone2 * 100,

strategic: 0,

currencyVersion: 2

}

}
```

### 7.2 规则

- **只合并字段，不改数值**（用户确认）。

- P18 已按 90/10 拆分的存档，数值不变，只合并。

- 迁移后删旧字段，加 `currencyVersion: 2`。

- 幂等：已有 `currencyVersion: 2` 的存档跳过。

### 7.3 P18 自动补差额

P18 的 `fixLegacyCurrencyRate()` 逻辑保留，在迁移前执行（把 `daZi` 补到正确值），再合并字段。
