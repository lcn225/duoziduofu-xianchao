## 设计 vs 代码（2026-10-16）

`10-现行设计/` 现在有**两代**设计并存，读的时候别搞混：现行**代码**实现的是旧的一代，
2026-10-16 新写的那批是**还没落地**的一代。

| | 现行**代码**实现的 | 现行**设计**（还没落地） |
|---|---|---|
| 契合度 | 三维**加权** 0.15 / 0.50 / 0.35 | 三维**连乘**（功法 × 同参 × 灵地） |
| 同参亲和度 | 4 档（1.0 / 0.7 / 0.4 / 0.15） | **6 档**（1.0 / 0.8 / 0.6 / 0.4 / 0.25 / 0.1） |
| 门槛 | 0.55 / 0.60 / 0.68 / 0.71 / 0.85 | 0.15 / 0.25 / 0.40 / 0.55 / 0.80 |
| 灵地基础产出 | 1.0 ~ 15.0 | 20 ~ 100（×20） |
| 品阶 | 10 档（三阶以上不分下中上） | 16 档 |
| 境界 | 18 级（止于结丹圆满） | 22 级（补元婴） |
| 在哪 | `90-历史归档/灵气系统 — 三维加权版.md` | `10-现行设计/灵气系统` + `同参系统` |

⚠ `npm run verify` 的断言是照**左边那一列**写的 —— 返工落地前它仍然全绿，
**别以为它验证了新设计**。（当前共 399 条：契合度+模块二 234 条、桂冈的一天 77 条、三大挂机 88 条。）

**两条已定的实现口径**（2026-10-16）：

- **同参契合度先「硬编」** —— 桂冈那几件（猪王 1.0 / 猪妖·成年 0.8 / 猪系列 0.6 / 盾 0.4 /
  三件灵器 0.25）直接写死，**不实现判定规则**。理想解「给所有物品打标签、算标签接近度」
  工作量太大，记在待办里。见《同参系统》§3.4。
- **门槛以《同参系统》为准** —— 《灵气系统》§4.3 / §6.1 / §7.2 那三节已标废弃、不再维护。
